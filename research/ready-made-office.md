# LLM-компания: берите каркас готовым, ядро пишите сами

Готовой «LLM-компании», которую можно запустить из РФ целиком, нет. Платформы «бизнес под ключ» — Polsia и аналоги — стоят на Stripe и Meta Ads, а российского аналога не найдено. Готовым стоит брать каркас и инфраструктуру: Paperclip как оболочку совета директоров (пилотом), RubyLLM 2.1 и официальный MCP Ruby SDK как рантайм агентов на Rails, GPT Researcher для скаута, официальные API Яндекса, открытую базу RFSD и Checko для данных, ЮKassa с её MCP-сервером и шаблон AstroWind для smoke-теста. Писать самому — всё, что делает цикл уникальным, и всё, что трогает деньги: стоп-фильтр, калькулятор экономики, турнир, тонкие клиенты к Директу (прогноз — только через устаревший Live 4), Wordstat и Метрике, рублёвый реестр и шлюз трат, генератор лендингов и платёжный сервис. Рублей не считает ни один оркестратор: бюджеты Paperclip и Claude — это только LLM-токены ([SPEC Paperclip](https://github.com/paperclipai/paperclip/blob/master/doc/SPEC.md)). Главный внешний риск — доступ к моделям: России нет среди поддерживаемых стран Anthropic ([Anthropic](https://www.anthropic.com/supported-countries)), поэтому Claude Agent SDK — только референс, а агенты-сотрудники должны работать на YandexGPT, GigaChat или open-weight моделях, чьё качество в агентных циклах ещё не проверено. Формула max CPC = цена × срок жизни × конверсия ÷ 3 не учитывает маржу и завышает ставку в 1/маржа раз — ниже предложена исправленная версия. Экосистема MCP для Яндекса молода и держится на одиночках, а взрывная популярность Paperclip (99.1k★ за ~7,5 месяца) не доказана и не опровергнута — звёзды не аргумент.

> **Как читать.** «Не проверено» — нет подтверждения первичным источником. «По сниппету поиска» — факт подтверждён только сводкой поисковой выдачи, сама страница не открывалась (российские домены были недоступны из среды исследования). «Предложение» — собственный синтез или рекомендация отчёта. Прогнозы, оценки и допущения помечены словами «оценка», «допущение» или «гипотеза». Все метрики активности — на 2026-10-09. Подробные заметки по слоям и полные списки источников лежат в [research/notes/ready-made-office/](notes/ready-made-office/): [слой 1](notes/ready-made-office/l1-orchestrators.md), [слой 2](notes/ready-made-office/l2-ai-business-platforms.md), [слой 3](notes/ready-made-office/l3-idea-validation.md), [слой 4a](notes/ready-made-office/l4a-yandex-apis.md), [слой 4b](notes/ready-made-office/l4b-ru-data-marketplaces.md), [слой 5](notes/ready-made-office/l5-landing-yookassa.md), [слой 6](notes/ready-made-office/l6-ruby-ecosystem.md), [сквозные риски](notes/ready-made-office/x-risks-ru.md).

## Слой 1. Оркестраторы: совет директоров есть только у Paperclip, рублёвых бюджетов нет ни у кого

Проверено шесть кандидатов. Все пять нужных сущностей — оргструктура, бюджет на агента, гейты одобрения, расписание, аудит — как продуктовые объекты с UI для совета есть только у **Paperclip** ([README](https://github.com/paperclipai/paperclip/blob/master/README.md)). Ни один кандидат не даёт коннекторов к Wordstat, Директу, ГИР БО и ЮKassa. Ни у одного нет рублёвого реестра: бюджеты везде означают стоимость LLM-токенов в долларах или отсутствуют вовсе. Решающий фильтр для РФ — можно ли направить агентов на OpenAI-совместимый `base_url` (Yandex AI Studio, GigaChat через gpt2giga, свой vLLM). Его проходят Paperclip (через OpenCode), CrewAI, библиотека LangGraph, n8n и Temporal, который вызывает любую модель как обычную activity. Claude Agent SDK не проходит.

### Paperclip: пилот на 1–2 цикла как оболочка «компании и совета»

**Что это.** Self-hosted control plane «компании из агентов» под MIT: сервер на Node.js 24, React UI, PostgreSQL через Drizzle ([README](https://github.com/paperclipai/paperclip/blob/master/README.md), [SPEC](https://github.com/paperclipai/paperclip/blob/master/doc/SPEC.md)). Оргструктура — строгое дерево: у агента ровно один менеджер, CEO подчиняется совету ([org-structure](https://github.com/paperclipai/paperclip/blob/master/docs/guides/board-operator/org-structure.md)). Гейты — approvals типов `hire_agent`, `approve_ceo_strategy`, `budget_override_required` и `request_board_approval` с циклом pending → approved / rejected / revision_requested ([SPEC-implementation](https://github.com/paperclipai/paperclip/blob/master/doc/SPEC-implementation.md), [approvals API](https://github.com/paperclipai/paperclip/blob/master/docs/api/approvals.md)). Расписание — routines по cron, webhook или API; каждый запуск создаёт отслеживаемую задачу. Аудит — append-only журнал мутаций с полями actor / action / entity ([activity API](https://github.com/paperclipai/paperclip/blob/master/docs/api/activity.md)). Бюджет — `budgetMonthlyCents` на компанию и на агента: на 80% предупреждение, на 100% **hard stop с автопаузой**, окно — календарный месяц по UTC ([costs API](https://github.com/paperclipai/paperclip/blob/master/docs/api/costs.md)). У MCP-шлюза есть режимы Allowed / Ask first / Off — готовый гейт на инструменты, которые тратят деньги ([README](https://github.com/paperclipai/paperclip/blob/master/README.md)).

**Почему пилот.** Это единственное прямое совпадение с метафорой «LLM-компания + совет директоров»: CEO-агент, стратегия на одобрение, найм под гейтом, бюджеты, журнал. API сделан под клиентов не на TypeScript — в спецификации так и записано: «REST API, not tRPC — need non-TS clients» ([SPEC](https://github.com/paperclipai/paperclip/blob/master/doc/SPEC.md)).

**Ограничения.** Проекту ~7,5 месяцев: первые коммиты — 2026-02-20, первая публикация в npm — 2026-03-03, с тех пор **1 764 версии** в npm, летом по 300+ в месяц ([npm](https://registry.npmjs.org/paperclipai), [ранние коммиты](https://github.com/paperclipai/paperclip/commits/master/?until=2026-02-20)). Коммиты делают 1–2 core-разработчика в соавторстве с агентами; идут крупные рефакторинги ядра heartbeat ([коммиты](https://github.com/paperclipai/paperclip/commits/master)). Бюджеты считают **только LLM**: «External revenue/expense tracking — future plugin» ([SPEC](https://github.com/paperclipai/paperclip/blob/master/doc/SPEC.md)). Стоимость берётся из разбора вывода адаптера. Для OpenCode с российским провайдером цены может не оказаться, и тогда hard stop не сработает — не проверено. Телеметрия включена по умолчанию ([README](https://github.com/paperclipai/paperclip/blob/master/README.md)). На странице репозитория висят «12 alerts» в разделе Security and quality; что за ними — не проверено ([repo](https://github.com/paperclipai/paperclip)).

**Как подключить.** Rails или Go ходят в REST `/api` по Bearer-ключу: создают задачи и approvals, читают costs и activity ([API overview](https://github.com/paperclipai/paperclip/blob/master/docs/api/overview.md)). Детерминированные стадии (Wordstat, Директ, ГИР БО, формула экономики) отдаются своему сервису-«сотруднику» через адаптер `http`: Paperclip шлёт POST с `runId`, `agentId` и контекстом, сервис отвечает через API ([http adapter](https://github.com/paperclipai/paperclip/blob/master/docs/adapters/http.md)). Вариант попроще — адаптер `process` запускает ruby- или go-команду с переменными `PAPERCLIP_*` ([process adapter](https://github.com/paperclipai/paperclip/blob/master/docs/adapters/process.md)). LLM-роли идут через `opencode_local` на OpenAI-совместимый `baseURL` ([adapters](https://github.com/paperclipai/paperclip/blob/master/docs/adapters/overview.md), [OpenCode providers](https://github.com/sst/opencode/blob/dev/packages/web/src/content/docs/providers.mdx)). Стоимость российских моделей придётся отправлять самим через `POST /api/companies/{companyId}/cost-events` с пересчётом рублей в центы ([cost reporting](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/cost-reporting.md)). Телеметрию выключить (`PAPERCLIP_TELEMETRY_DISABLED=1`), версию зафиксировать.

**Плюсы.** Готовый UI совета: approvals, расходы против бюджета, журнал, оргчарт, мобильный режим. MIT, self-hosted, аккаунт Paperclip не нужен. Секреты шифруются локальным мастер-ключом, ключи агентов хранятся хэшами ([secrets](https://github.com/paperclipai/paperclip/blob/master/docs/deploy/secrets.md), [auth](https://github.com/paperclipai/paperclip/blob/master/docs/api/authentication.md)).

**Минусы.** Второй рантайм (Node 24) рядом с Rails или Go. Молодой код с бешеным темпом изменений. Аномальная популярность (разбор — в разделе «Риски»). Бюджеты не про рубли. Насколько хорошо YandexGPT и GigaChat вызывают инструменты внутри OpenCode — не проверено; если плохо, автономия ролей сжимается до узких вызовов, и ценность Paperclip падает.

### Temporal: движок своего конвейера, если нужны долгие ожидания

**Что это.** Платформа durable execution под MIT, форк Uber Cadence. Сервер v1.0.0 вышел 2020-09-30, v1.32.1 — 2026-10-07 ([README](https://github.com/temporalio/temporal), [Go proxy](https://proxy.golang.org/github.com/temporalio/temporal/@latest)). Нативные SDK для Go и Ruby; гем `temporalio` в GA с версии 1.0.0 от 2025-09-29, сейчас 1.9.0 ([RubyGems](https://rubygems.org/api/v1/versions/temporalio.json)).

**Почему брать.** Три из пяти требований закрыты на уровне продукта. Schedules — с часовым поясом, overlap policy, catch-up и backfill ([schedule](https://github.com/temporalio/documentation/blob/main/docs/encyclopedia/workflow/schedule.mdx)). Signals и Updates с `wait_condition` дают ожидание решения совета, которое переживает сбои ([message passing](https://github.com/temporalio/documentation/blob/main/docs/encyclopedia/workflow-message-passing/workflow-message-passing.mdx)). Event History — «a complete and durable log of everything that has happened» ([event history](https://github.com/temporalio/documentation/blob/main/docs/encyclopedia/event-history/event-history.mdx)). Лестница бюджета ложится на таймеры: каждая ступень ждёт Update «повысить» от совета, а вебхук ЮKassa приходит в Rails и пересылается в workflow как Signal (предложение).

**Ограничения.** Нет агентов, ролей, бюджетов и UI совета; Web UI — технический. Нужны отдельный сервер, PostgreSQL (SQLite — только для разработки), воркеры и дисциплина детерминизма ([persistence](https://github.com/temporalio/documentation/blob/main/docs/encyclopedia/temporal-service/persistence.mdx)). Ruby SDK работает только на Linux и macOS; модели ActiveRecord нельзя переиспользовать как модели Temporal; код workflow нужно грузить заранее, иначе Zeitwerk даёт ошибку ([sdk-ruby](https://github.com/temporalio/sdk-ruby)). Продакшен-опыт Ruby SDK в Rails после GA — не проверен.

**Как подключить.** Rails — гем `temporalio`, раздел Rails и сэмпл `rails_app` в README SDK ([sdk-ruby](https://github.com/temporalio/sdk-ruby)). Go — `go.temporal.io/sdk` v1.49.0 ([Go proxy](https://proxy.golang.org/go.temporal.io/sdk/@latest)).

**Плюсы.** Надёжные долгие ожидания, ретраи и аудит. Нативно для обоих кандидатов в стек. Без SaaS и вендорских ключей.

**Минусы.** Для одного прогона в неделю это тяжёлая артиллерия. Лёгкая альтернатива — Solid Queue или GoodJob с конечным автоматом цикла в БД (раздел слоя 6).

### Claude Agent SDK и Managed Agents: референс дизайна, не рантайм агентов в РФ

**Что это.** Agent SDK — «Claude Code как библиотека» для Python (MIT) и TypeScript (Commercial Terms). Из Ruby и Go его вызывают подпроцессом: «run the CLI as a subprocess with the `-p` flag and `--output-format json`» ([overview](https://code.claude.com/docs/en/agent-sdk/overview)). Есть permissions, хук `PreToolUse` с deny, субагенты, MCP и лимит `max_budget_usd` на вызов ([Python SDK](https://github.com/anthropics/claude-agent-sdk-python), [cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)). Managed Agents — хостинг агентов у Anthropic в beta (заголовок `managed-agents-2026-04-01`): cron-деплойменты с часовым поясом IANA, жёсткий бюджет в центах USD на сессию с паузой `budget_reached`, статус `requires_action` для подтверждения инструментов, серверная история событий и webhooks ([MA overview](https://platform.claude.com/docs/en/managed-agents/overview), [MA deployments](https://platform.claude.com/docs/en/managed-agents/scheduled-deployments), [MA budgets](https://platform.claude.com/docs/en/managed-agents/budgets)).

**Почему референс.** России нет в списке поддерживаемых стран Anthropic ([supported countries](https://www.anthropic.com/supported-countries)). Подмену модели через шлюз Anthropic не поддерживает: «doesn't support routing Claude Code to non-Claude models through any gateway» ([LLM gateway](https://code.claude.com/docs/en/llm-gateway)). Технический обход есть — gpt2giga отдаёт Anthropic-совместимый `/messages` поверх GigaChat, — но авторы прокси сами предупреждают, что это не drop-in replacement ([gpt2giga](https://github.com/ai-forever/gpt2giga)). Коммерческие условия позволяют приостановить доступ при нарушении региональной политики, а СМИ в 2026 году сообщали о волнах блокировок российских аккаунтов (подробности — в разделе «Риски»). Поэтому строить на SDK продакшен-агентов компании нельзя: рантайм может остановиться в любой момент. Разработка через Claude Code — текущая рабочая настройка основателя; этот вердикт касается только рантайма агентов-сотрудников.

**Что забрать как дизайн.** Бюджет на каждый прогон, а не только месячный. Пауза при исчерпании вместо завершения. Cron с часовым поясом. Подтверждение вызова инструмента. Серверная история событий. И ещё один урок: `total_cost_usd` в SDK — клиентская оценка, и документация прямо пишет «Do not bill end users or trigger financial decisions from these fields» ([cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)). Это прямой аргумент за собственный реестр денег.

**Плюсы** (как референс). Лучший готовый дизайн бюджетов и подтверждений; в документации MA есть примеры SDK на Go и Ruby. **Минусы.** Страна не поддерживается; данные MA лежат на серверах Anthropic, Zero Data Retention на них не распространяется ([MA overview](https://platform.claude.com/docs/en/managed-agents/overview)).

### CrewAI и LangGraph: брать идеи, а не платформу

**CrewAI** (MIT, 59.5k★, PyPI 1.15.26 от 2026-10-08) даёт самую «человеческую» модель ролей — role, goal, backstory — и иерархического менеджера-делегатора ([hierarchical](https://github.com/crewAIInc/crewAI/blob/main/docs/edge/en/learn/hierarchical-process.mdx)). В Flows есть `@human_feedback`: свободный ответ совета сводится к одному из исходов `emit` — approved, rejected, needs_revision ([HF in Flows](https://github.com/crewAIInc/crewAI/blob/main/docs/edge/en/learn/human-feedback-in-flows.mdx)). Но денежных бюджетов нет, только `max_iter`, `max_rpm` и `max_execution_time` ([agents](https://github.com/crewAIInc/crewAI/blob/main/docs/edge/en/concepts/agents.mdx)). Расписания в OSS нет. Продакшен-HITL через вебхуки — только в Enterprise ([HITL](https://github.com/crewAIInc/crewAI/blob/main/docs/edge/en/learn/human-in-the-loop.mdx)). Телеметрия включена по умолчанию ([telemetry](https://github.com/crewAIInc/crewAI/blob/main/docs/edge/en/telemetry.mdx)). Из Rails — только через свою Python-обёртку. **Вердикт: референс** промптов ролей и маршрутизации решений совета.

**LangGraph** (библиотека MIT, 43.0k★, 1.2.14 от 2026-10-06) даёт самый чистый механизм гейтов: `interrupt()` в любой ноде, продолжение через `Command(resume=...)`, состояние в checkpointer ([interrupts](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/interrupts.mdx)). Расписание есть только в Agent Server. А он распространяется под **Elastic-2.0**, требует `LANGGRAPH_CLOUD_LICENSE_KEY` и исходящий доступ к `beacon.langchain.com` для проверки лицензии и отчёта об использовании ([standalone](https://github.com/langchain-ai/docs/blob/main/src/langsmith/deploy-standalone-server.mdx), [PyPI langgraph-api](https://pypi.org/pypi/langgraph-api/json)). Для РФ это лишняя зависимость от вендора в США. **Вердикт: референс** семантики interrupt/checkpoint.

Остальное — одной строкой. n8n (206.8k★) живёт под fair-code Sustainable Use License («only for your own internal business purposes») и не знает оргструктур и бюджетов; годится максимум как временный «клей» с одобрением через Telegram ([LICENSE.md](https://github.com/n8n-io/n8n/blob/master/LICENSE.md), [HITL](https://github.com/n8n-io/n8n-docs/blob/main/docs/build/integrate-ai/ai-examples/human-in-the-loop-for-tools.md)). Mastra (Apache-2.0), Microsoft Agent Framework (MIT) и Agency Swarm (MIT) в шорт-лист не вошли и не оценивались ([npm](https://registry.npmjs.org/@mastra/core), [PyPI](https://pypi.org/pypi/agent-framework/json), [PyPI](https://pypi.org/pypi/agency-swarm/json)).

**Вердикт слоя.** Готовым брать оболочку совета (Paperclip, пилотом) и при желании движок конвейера (Temporal). Референсом — дизайн бюджетов и подтверждений из Managed Agents, interrupt/checkpoint из LangGraph, ролевые шаблоны из CrewAI. Самому писать доменный конвейер, рублёвый реестр с жёсткими лимитами и мост «решение совета → действие с деньгами».

## Слой 2. «Бизнес под ключ»: из РФ не работает ни одна платформа, ценны только уроки

Готовой платформы «ИИ запускает и ведёт бизнес», которую можно взять целиком, нет. Глобальные (Polsia, NanoCorp, Cofounder) стоят на Stripe и Meta Ads, закрыты и не дают API или MCP. Деньги и рекламный аккаунт у них держит платформа, а не владелец. Российского аналога Polsia не найдено ([Sostav](https://www.sostav.ru/blogs/288561/92124), [vc.ru](https://vc.ru/services/2873629-top-kompaniy-po-ii-avtomatizatsii-v-rossii), по сниппету поиска). Ни один продукт — ни глобальный, ни российский — не покрывает отсев по стоп-факторам, сбор данных, экономику и турнир. Ценность слоя — в уроках и в одном российском инструменте для ручного smoke-теста.

### Polsia: карта продукта и предупреждение «строить до проверки спроса»

**Что это.** Закрытый SaaS «AI that runs your company while you sleep». Под каждую идею он поднимает веб-сервер, базу, почту, аккаунт Stripe и рекламный аккаунт Meta; агенты ведут код, маркетинг, поддержку и холодные рассылки (по сниппету поиска) ([Product Hunt](https://www.producthunt.com/products/polsia), [Tim Frin](https://timfrin.substack.com/p/how-polsia-builds-and-runs-companies)). Публичного API или MCP не найдено (не проверено первоисточником). Series A — $30M при оценке $250M, объявлен 22.05.2026; основатель заявил run-rate ≈$10M (по сниппету поиска) ([Pulse 2](https://pulse2.com/polsia-30-million-at-250-million-valuation-raised-for-ai-operations-platform/)).

**Почему референс.** Из РФ не работает ни одно звено. Stripe «currently does not support users located in Russia, Ukraine and Belarus» (по сниппету поиска) ([Stripe Support](https://support.stripe.com/questions/impact-of-sanctions-on-russia-and-belarus)). Реклама идёт только в Meta, а с 01.09.2025 реклама на ресурсах организаций, запрещённых в РФ за экстремизм, запрещена законом (по сниппету поиска) ([Радио Свобода](https://www.svoboda.org/a/reklama-instagram-feysbuk-zakon/33358648.html)). Экономика противоположна модели основателя: по ToS от 17.09.2026 — 3% с платежей клиентов, 20% с рекламного бюджета и выплаты с задержкой 31 день (по сниппету поиска, обзоры конкурентов) ([UseCarly](https://www.usecarly.com/blog/polsia-pricing/), [Crevio](https://crevio.co/blog/is-polsia-legit)).

**Главный урок.** Со слов основателя в пересказе конкурента, около **10% компаний на Polsia заработали хотя бы $1**, отток в первый месяц — около 50% (не проверено: запись интервью не прослушана) ([Crevio](https://crevio.co/blog/is-polsia-legit)). Если цифра верна, платформа массово строит до проверки спроса. Отсев и турнир до трат — ровно то, чего нет ни у одной платформы «под ключ», и главный довод за цикл основателя.

**Ограничения сведений.** Первичные страницы polsia.com не открылись; условия взяты из вторичных обзоров, часть — от конкурентов, версии ToS противоречат друг другу. Имя основателя в источниках расходится: Ben Cera или Ben Broca. Неофициальный репозиторий [PolsiaAI/Polsia](https://github.com/PolsiaAI/Polsia) (142★, 2 коммита, лицензия не указана, связь с polsia.com не заявлена) полезен только расписанием агентов: план в 06:00, сводка в 20:00, реклама и финансы — каждые 6 часов.

**Плюсы** (как референс). Механика «компания на идею» с изолированными ресурсами; ритм агентов. **Минусы.** Ничего нельзя подключить; трекшн — неаудированные заявления.

### Project Vend: лучший по доказательствам референс ограждений

**Что это.** Эксперимент Anthropic и Andon Labs: Claude вёл реальный офисный магазин. Фаза 1 (27.06.2025) — «did not succeed at making money»: продажи ниже себестоимости, выдуманный Venmo-аккаунт, скидки сотрудникам ([Project Vend 1](https://www.anthropic.com/research/project-vend-1)). Фаза 2 (18.12.2025) добавила CEO-агента с правилами «All financial decisions require CEO approval» и «No pricing under 50% margin», CRM и обязательную проверку цен и сроков поставки. Недели с отрицательной маржой «largely eliminated», но за Q3 магазин собрал **$2 649.20 — 17.7% цели** в $15 000 ([Project Vend 2](https://www.anthropic.com/research/project-vend-2)).

**Почему референс.** Он показывает, какие ограждения работают: численные пороги, процедуры («bureaucracy matters»), разделение ролей. И какие провалы ждать. CEO-агент на той же модели разделял слабости исполнителя: отклонил больше 100 просьб о поблажках, но одобрил примерно в 8 раз больше. Он был готов подписать контракт, запрещённый Onion Futures Act 1958 года. Сотрудники убедили агента, что новым CEO «избран» человек ([Project Vend 2](https://www.anthropic.com/research/project-vend-2)).

**Что перенести в цикл** (предложение). Деньги одобряет только совет; агент-директор готовит пакет с цифрами. Пороги — max CPC, стоп-пороги ступеней, потолок риска — живут инвариантами в коде, а не в промпте. Турнир и критику финалистов делает другая модель или независимый промпт-оппонент. Юридические вопросы — только человеку. Andon Market — контрпример лестницы: агент получил лимит $100 000 сразу и, по сообщениям СМИ, потерял $62 тыс. за 4 месяца (по сниппету поиска) ([ABC30](https://abc30.com/post/artificial-intelligence-boss-named-luna-running-san-francisco-store-andon-market-cow-hollow-neighborhood/18943220/), [The Hustle](https://thehustle.co/news/what-happens-when-your-ai-boss-is-kinda-dumb)).

**Плюсы.** Первичные данные, два задокументированных этапа. **Минусы.** США и офлайн-торговля, а не онлайн-ниши РФ; ряды фазы 1 даны только графиком.

### ИИ-помощник Директа: российский исполнитель smoke-теста, но без API

**Что это.** В «Простом старте» Директа помощник в диалоге выясняет специфику бизнеса, предлагает стратегию и бюджет, генерирует тексты, изображения и при необходимости лендинг, затем согласует ключевые параметры с рекламодателем (по сниппету поиска) ([Директ](https://direct.yandex.ru/base/articles/ii-pomoshchnik-prostoy-start-yandex-direct)). Тест шёл 20.02–27.03.2026 на 50 тыс. компаний; Яндекс заявляет «конверсия выше на треть» (по сниппету поиска) ([Яндекс](https://yandex.ru/company/news/15-04-2026-02)). Генератор лендингов — в бете. API или MCP у помощника не найдено.

**Почему референс плюс ручная опция.** Оркестратор вызвать помощника не может. Но для первых smoke-тестов, пока свой генератор лендингов не готов, им можно пользоваться вручную. Цепочка «бриф → стратегия и бюджет → креативы и лендинг → согласование → запуск» — готовый шаблон для агента-маркетолога. Яндекс сам строит агентный запуск рекламы, так что «настроить и вести кампанию» коммодитизируется внутри Директа. Оркестратору выгодно держать то, чего у Яндекса нет: отсев, экономику, турнир, лестницу бюджета, ЮKassa и гейты совета (предложение).

**Плюсы.** Нативно в РФ, без отдельной платы (не проверено). **Минусы.** Нет API. Агентство пишет, что помощник ускоряет первый запуск, но не заменяет настройку целей в Метрике и работу с семантикой (по сниппету поиска) ([M-Context](https://m-context.ru/blog-monster-context/ii-pomoshchnik-yandeks-direkt-2026/)).

## Слой 3. Валидация идей: готов только движок поиска, турнир и формулу писать самому

Готовым стоит брать одно — **GPT Researcher** как движок desk research для скаута. Специализированные «валидаторы стартап-идей» на GitHub — это молодые наборы промптов или хакатонные проекты, и ни один не работает с данными Яндекса. SaaS-валидаторы (ValidatorAI, DimeADozen, IdeaProof) не дают API. Турнир финалистов, стоп-фильтр и калькулятор экономики дешевле написать самому по проверенным референсам: по оценке заметок, это сотни строк на Ruby или Go, а не отдельная Python-зависимость (оценка). Нативных Ruby-реализаций в этом слое не найдено вовсе.

### GPT Researcher + gptr-mcp: движок скаута и разведки конкурентов

**Что это.** Self-hosted агент исследования: 30.0k★, 3 211 коммитов, последний коммит и релиз PyPI 0.16.1 — 2026-09-26, 111 релизов с 2024-04-12 ([repo](https://github.com/assafelovic/gpt-researcher), [PyPI](https://pypi.org/pypi/gpt-researcher/json)). Режим Deep Research строит рекурсивное дерево поиска; по README прогон занимает около 5 минут и около $0.4 на o3-mini. Из 27 LLM-провайдеров есть **`gigachat`**, остальные OpenAI-совместимые подключаются через `OPENAI_BASE_URL`; провайдера «yandex» нет ([base.py](https://github.com/assafelovic/gpt-researcher/blob/main/gpt_researcher/llm_provider/generic/base.py)). Из 21 ретривера ни один не ходит в Яндекс, зато есть custom: GET с `query` → JSON-список `{url, raw_content}` ([custom.py](https://github.com/assafelovic/gpt-researcher/blob/main/gpt_researcher/retrievers/custom/custom.py)). MCP-обёртка gptr-mcp (MIT, 372★) отдаёт `deep_research`, `quick_search`, `write_report` и другие инструменты через stdio, SSE или streamable HTTP ([gptr-mcp](https://github.com/assafelovic/gptr-mcp)).

**Почему брать.** Активен, пермиссивная лицензия, работает в своём Docker, говорит по MCP и HTTP, принимает свой поисковик и знает GigaChat. Для скаута этого достаточно: `quick_search` на каждую из ~50 идей, `deep_research` для финалистов с вопросами «кто лидер ниши, есть ли монополист, какие цены у конкурентов» (предложение).

**Ограничения.** Лицензия в метаданных расходится: файл LICENSE — Apache-2.0, PyPI — MIT ([LICENSE](https://github.com/assafelovic/gpt-researcher/blob/main/LICENSE)); обе пермиссивные. Ретривер по умолчанию Tavily — иностранный SaaS, оплата из РФ не проверена. Качество на русских запросах не проверено. Количественных данных (Wordstat, прогноз Директа, ГИР БО) он не даёт — это слой 4. Темп релизов высокий, версию пиновать.

**Как подключить.** Поднять gpt-researcher и gptr-mcp sidecar-сервисами в Docker. Rails или Go ходят к ним по MCP или HTTP к FastAPI (формальный контракт FastAPI не проверен). Свой эндпоинт `GET /search?query=` на Rails или Go поверх выбранного российского поиска заменяет Tavily (предложение).

**Плюсы.** Не нужно писать собственного агента поиска; поисковик и модель заменяемы. **Минусы.** Третий рантайм (Python) в контуре; качество на русском — главный неизвестный.

### AI-Researcher: Swiss-турнир как образец, но с исправлениями

**Что это.** Код к статье Si, Yang, Hashimoto «Can LLMs Generate Novel Research Ideas?» (ICLR 2025). Попарные сравнения идут по швейцарской системе: пары из соседей по счёту, победитель получает очко ([arXiv](https://arxiv.org/pdf/2409.04109), по сниппету поиска). По статье, разрыв оценок между топ-10 и низ-10 рос с 0.56 при одном раунде до 1.73 при пяти и падал до 1.30 при шести (по сниппету поиска). Демо стоило $0.74 за ранжирование 10 предложений в 5 раундов ([README](https://github.com/NoviScl/AI-Researcher)).

**Почему референс.** Алгоритм маленький — около 100 строк (оценка) — и не зависит от домена. Но в коде есть дыры ([tournament_ranking.py](https://github.com/NoviScl/AI-Researcher/blob/main/ai_researcher/src/tournament_ranking.py)). Пара судится один раз, без перестановки, хотя идея с большим счётом чаще стоит первой. Любой ответ, кроме «1», включая мусор, засчитывается второй идее. Счёт хранится по первым 200 символам текста. Последний коммит — 2025-08-07, больше года тишины.

**Почему перестановка обязательна.** LLM-судьи систематически смещены. В MT-Bench «all of them exhibit strong position bias»: GPT-4 согласован с собой после перестановки ответов в 65.0% случаев, Claude-v1 — в 23.8% и в 75.0% выбирает первый ответ (по сниппету поиска) ([arXiv 2306.05685](https://arxiv.org/pdf/2306.05685)). У Wang et al. одна перестановка позволяет Vicuna-13B «обыграть» ChatGPT в 66 из 80 запросов (по сниппету поиска) ([arXiv 2305.17926](https://arxiv.org/pdf/2305.17926)).

**Схема турнира** (предложение). 8–12 финалистов, 4–5 раундов Swiss. Каждый матч — два вызова судьи с перестановкой; при расхождении ничья 0.5. Судья — модель другого семейства, чем генератор (урок и Project Vend, и MT-Bench о self-enhancement). Карточки идей одинаковой длины по шаблону с числами: частотность, прогнозный CPC, max CPC, маржа — защита от смещения к многословию, по аналогии со style control в [arena-hard-auto](https://github.com/lmarena/arena-hard-auto). Для топ-2/3 — многоходовые дебаты, как у Google co-scientist ([arXiv 2502.18864](https://arxiv.org/pdf/2502.18864), по сниппету поиска). Elo нужен только для истории между неделями; при малом числе финалистов надёжнее разовая оценка Bradley-Terry с bootstrap-интервалом.

**Плюсы.** Дёшево: удвоение вызовов из-за перестановок — копейки на фоне бюджета smoke-теста. **Минусы.** Перенос выводов с научных гипотез на бизнес-идеи — допущение; исследований турниров бизнес-идей с проверкой на реальных продажах не найдено.

### idea-validation-agents: рубрики для стоп-фильтра

**Что это.** Набор Markdown-промптов и скиллов для Claude Code, Codex и Cursor под MIT: 478★, 57 форков, всего 9 коммитов с 2026-04-13 по 2026-06-16 ([repo](https://github.com/MaxKmet/idea-validation-agents), [commits](https://github.com/MaxKmet/idea-validation-agents/commits)). Итоговый скор 0–100 считается «multiplicative-floor algorithm»: «one catastrophic weakness kills the overall score». Насыщенность рынка оценивается по пяти факторам, среди них **incumbent dominance** — прямой аналог стоп-фактора «монополист». Riskiest Assumption Test ограничен «≤2-week, ≤$100 behavioral experiment». Вердикты — pursue / test / pivot / drop.

**Почему референс.** Рантайма нет, kill-критерии без числовых порогов, источники данных — TikTok, Reddit, X, App Store, Google Trends, без Яндекса. Популярность аномальна для 9 коммитов, агрегаторы показывали другие числа звёзд (427 и 260, по сниппету поиска) ([sourcepulse](https://www.sourcepulse.org/projects/30847528), [gittrend](https://gittrend.io/repo/MaxKmet/idea-validation-agents)). Это набор промптов, а не проверенная система.

**Что взять** (предложение). Мультипликативный «пол» как логику стоп-фильтра. Фактор incumbent dominance с собственной метрикой доли по выручке из ГИР БО (слой 4). Формат решения pursue/test/pivot/drop для совета. RAT как шаблон первой ступени лестницы.

### Формула основателя завышает max CPC в 1/маржа раз

Конфликт заметок разрешается арифметикой. «÷ 3» в формуле основателя — это правило **LTV:CAC ≥ 3** Дэвида Скока: LTV должен превышать CAC «at least three times» (по сниппету поиска) ([транскрипт интервью](https://videohighlight.com/v/bCBccKfG9U0)). Но LTV у Скока считается **по валовой марже**: простая версия — ARPA × Gross Margin / Churn (по сниппету поиска) ([ChartMogul](https://chartmogul.com/resources/ltv-cheat-sheet.pdf), [Skok](https://www.forentrepreneurs.com/metricas-saas-2/)). Break-even CPC = прибыль на клиента × конверсия клик → покупка (по сниппету поиска) ([ppc.io](https://ppc.io/tools/ppc-calculator)). Формула «цена × срок жизни × конверсия ÷ 3» — частный случай при марже 100%. При марже меньше 100% она завышает допустимый CPC в 1/маржа раз.

| Пример: цена 3 000 ₽/мес, срок жизни 6 мес, CR клик→оплата 2%, маржа 40% | max CPC |
|---|---|
| Формула основателя: 3 000 × 6 × 0.02 ÷ 3 | **120 ₽** |
| С маржой (цель LTV:CAC = 3): 3 000 × 0.4 × 6 × 0.02 ÷ 3 | **48 ₽** |
| Break-even по марже (LTV:CAC = 1): 3 000 × 0.4 × 6 × 0.02 | **144 ₽** |
| Фактический LTV:CAC при ставке 120 ₽: 7 200 ₽ маржи ÷ (120 ₽ ÷ 0.02) | **1.2, а не 3** |

**Предложение: исправленная формула.** max CPC (цель) = цена × валовая маржа × срок жизни × CR(клик → оплата) ÷ 3; жёсткий стоп ступени — та же величина без деления на 3 (break-even). Маржа считается после себестоимости и комиссии эквайринга. CR — именно клик → оплата; если тест меряет заявки, умножать на конверсию заявка → оплата. Срок жизни до появления данных брать консервативно: первый платёж или 3 месяца, раз сам Скок считает LTV:CAC преждевременным до product/market fit (по сниппету поиска) ([транскрипт интервью](https://videohighlight.com/v/bCBccKfG9U0)).

**Плюсы.** Согласовано с источником правила «÷ 3». Не даёт переплачивать в 2.5 раза при марже 40%. Два порога — цель и break-even — дают лестнице ясные правила остановки. **Минусы.** До продаж маржа и срок жизни — допущения, а каждый новый параметр — место, где LLM-аналитик может «подогнать» цифры; поэтому параметры фиксирует совет до запуска. Формула строже: часть ниш, прошедших бы по исходной версии, отсеется.

### Стоп-факторы и лестница: готовых порогов нет ни у кого

Формализованного российского списка стоп-факторов с порогами не найдено. Единственный официальный стоп-сигнал — статус Директа «Мало показов»: такие группы «приостанавливаются и не участвуют в аукционе» (по сниппету поиска) ([Яндекс](https://yandex.ru/adv/news/malo-pokazov-novyy-status-dlya-grupp-obyavleniy)). Числовой порог Яндекс не публикует. Ориентир «меньше 30 запросов в месяц» — ответ ассистента Яндекса со ссылкой на ppc.world, а не официальное правило ([alice.yandex.ru](https://alice.yandex.ru/neurum/c/drugoe/q/esli_menshe_30_poiskovyh_zaprosov_v_mesyac_02eaf880), по сниппету поиска). По исследованию eLama, при 1–5 показах в месяц отключается 38% фраз (по сниппету поиска) ([eLama](https://elama.ru/blog/kak-rabotat-so-statusom-malo-pokazov/)). «Монополист» у практиков описан только словами, без количественного критерия ([reg.ru](https://www.reg.ru/blog/monopoliya/), по сниппету поиска). Прогноз бюджета Директа практики называют «жутко косым» и советуют закладывать 20–40% запаса (по сниппету поиска) ([qna.habr](https://qna.habr.com/q/256633)).

**Лестница smoke-теста** (предложение, по Савойе и справке Директа). Ступень 0 — XYZ-гипотеза «не меньше X% из Y сделают Z» с порогами, записанная до запуска ([Shortform](https://www.shortform.com/pdf/the-right-it-pdf-alberto-savoia), по сниппету поиска). Ступень 1 — fake door: объявление → лендинг → кнопка, замер CTR и конверсии. Ступень 2 — предзаказ с предоплатой через ЮKassa (технически — холд, см. слой 5): деньги весомее слов. Объём ступени — около 10 целевых конверсий в неделю или по калькулятору выборки. Следующая ступень — только если фактический CPC не выше max CPC по марже. Меняется не больше одного элемента объявления за раз ([справка Директа](https://yandex.ru/support/direct/efficiency/ad-groups.html), по сниппету поиска).

## Слой 4. MCP и API для РФ: читать готовым, писать и тратить — только своим кодом

Все функции, которые нужны циклу, есть в официальных API. Готовых нативных клиентов для Ruby и Go нет, официальных MCP-серверов Яндекса для Директа, Метрики и Wordstat тоже нет ([www1.ru](https://www1.ru/news/2026/10/08/iandeks-360-otkryl-servisy-dlia-vnesnix-ii-agentov-cerez-mcp.html), по сниппету поиска: 8 октября 2026 года «Яндекс 360» открыл MCP только для офисных сервисов). Сообщество за 2025–2026 годы написало больше десятка MCP-серверов, но у каждого один-два автора и единицы или десятки звёзд. Отсюда раздел труда: агенту — готовые MCP в режиме только чтения, бэкенду — свой тонкий клиент, а всё, что тратит деньги, — через собственный шлюз трат (раздел «Деньги и токены»).

### 4a. Яндекс: три поколения API под одну задачу

**Директ.** Кампании, ставки и отчёты живут в API v5 и v501; боевой адрес `https://api.direct.yandex.com/json/v5`, есть песочница ([yamcp client.py](https://github.com/Lermont/yamcp/blob/main/src/yadirect_mcp/client.py)). Доступ получают через своё OAuth-приложение и заявку в «Настройки API → Мои заявки». Тестовый доступ открывает только песочницу; для полного нужна новая заявка. Страница настроек откроется, только если в кабинете есть хотя бы одна кампания, хватит черновика. Рассмотрение — от часа до трёх рабочих дней, в пик до семи (по сниппету поиска) ([Заявка на доступ](https://yandex.ru/dev/direct/doc/ru/troubleshooting/register)). Лимит — суточные баллы на рекламодателя, остаток виден в заголовке `Units` (по сниппету поиска) ([Ограничения](https://yandex.ru/dev/direct/doc/ru/troubleshooting/limits)). Во всех просмотренных проектах у Директа один OAuth-scope `direct:api`, отдельного read-only scope не встретилось ([stufently README](https://github.com/stufently/yandex-mcp), официальный список не проверен). Значит, запрет записи для агента придётся обеспечивать кодом, а не правами токена.

**Прогноз бюджета есть только в устаревшем Live 4.** По официальной таблице соответствий методов прогноз и подбор фраз в v5 не реализованы, рекомендуется v4 или Live 4 (по сниппету поиска) ([Method equivalents](https://yandex.ru/dev/direct/doc/en/concepts/methods)). Рабочая цепочка (код от сентября 2026): `CreateNewForecast` → опрос `GetForecastList` → `GetForecast` → `DeleteForecastReport`, без автоповтора `create` ([yamcp forecast.py](https://github.com/Lermont/yamcp/blob/main/src/yadirect_mcp/forecast.py)). Объявлений о закрытии не найдено, официальный changelog 2026 года не проверен. Частичная замена в v5 — `KeywordBids.get` с `AuctionBids`, но только для фраз, уже добавленных в кампанию; для групп со статусом RARELY_SERVED приходит null (по сниппету поиска) ([KeywordBids.get](https://yandex.ru/dev/direct/doc/ru/keywordbids/get)). Это главный технологический риск слоя: нужен изолированный адаптер и запасной путь — ручной прогноз в интерфейсе.

**Метрика** стабильна. Квоты — 5 000 запросов в сутки на пользователя и 200 запросов за 5 минут к `/stat/v1/data` (по сниппету поиска) ([квоты](https://yandex.ru/dev/metrika/doc/api2/intro/quotas.html)). Для предоплат важна загрузка офлайн-конверсий: CSV `ClientId,Target,DateTime,Price,Currency`, обработка до 24 часов (по сниппету поиска) ([upload](https://yandex.com/dev/metrika/doc/api2/management/yclid_conversion/upload.html)). Схема (предложение): сохранять ClientId при заявке, по вебхуку оплаты ЮKassa грузить офлайн-конверсию, читать её в отчётах Директа через параметр `Goals` ([report format](https://yandex.ru/dev/direct/doc/en/report-format), по сниппету поиска).

### Wordstat: основной путь — Yandex Cloud, остальное спорно

Заметки слоёв расходятся, и до конца это противоречие не снимается. Сводим так.

**Путь C — Wordstat в Yandex Cloud AI Studio Search API v2 — основной в 2026 году.** Эндпоинт `https://searchapi.api.cloud.yandex.net/v2/wordstat/` (topRequests, dynamics, regions, getRegionsTree), авторизация `Api-Key` сервисного аккаунта и `folderId` в теле запроса ([977ADAM client.go](https://github.com/977ADAM/yandex-wordstat-mcp-golang/blob/main/internal/wordstat/client.go)). Статус — Preview, работа только синхронная (по сниппету поиска) ([Yandex Cloud](https://yandex.cloud/en/docs/search-api/concepts/wordstat)). С 1 июня 2026 года Yandex Cloud не принимает новые OAuth-токены Яндекс ID, нужен сервисный аккаунт (по сниппету поиска) ([OAuth-токен](https://yandex.cloud/ru/docs/iam/concepts/authorization/oauth-token)). **Цена спорная.** Официальная страница тарифов: GetTop и GetDynamics — 20 ₽ за 1 000 запросов с НДС, GetRegionsDistribution — 50 ₽, дерево регионов бесплатно (по сниппету поиска) ([pricing](https://aistudio.yandex.ru/ru/docs/search-api/pricing)). Статья на Хабре 2026 года пишет, что Wordstat пока бесплатен ([Хабр](https://habr.com/ru/articles/1030276/), по сниппету поиска). README Yurich-ru — что нужен платёжный аккаунт, «карта не списывается, есть бесплатная квота» ([README](https://github.com/Yurich-ru/yandex-ads-mcp)). Размер бесплатной квоты не найден — не проверено. Для решения это неважно: 50 идей × 2 запроса — около 100 запросов в неделю, примерно 2 ₽ по официальной цене (предложение).

**Путь B — отдельный `api.wordstat.yandex.net`** — это та «бесплатная бета по заявке», которую нашли заметки слоя 2: запущена в июне 2025 года, доступ через поддержку Директа по логину и ClientId (по сниппету поиска) ([ppc.world](https://ppc.world/news/yandeks-zapustil-besplatnyy-api-dlya-vordstata/), [справка](https://yandex.ru/support2/wordstat/en/content/api-wordstat)). В 2026 году статус спорный. В PR от 2026-09-04 адрес назван неработающим ([PR #141](https://github.com/artwist-polyakov/polyakov-claude-skills/pull/141)). Yurich-ru, altrr2 и stufently в мае–июле 2026 года ушли на Cloud v2 ([Yurich-ru](https://github.com/Yurich-ru/yandex-ads-mcp/commits/master), [altrr2](https://github.com/altrr2/yandex-tools-mcp/commits/main), [stufently](https://github.com/stufently/yandex-mcp/commits/main)). Ask Ads пишет прямо: «Старый отдельный Wordstat API с OAuth не используется» ([README](https://github.com/askads/mcp-yandex-wordstat)). При этом yamcp в октябре 2026 года оставляет этот путь опцией ([README](https://github.com/Lermont/yamcp)). Официального объявления об отключении нет. Вывод: работает ли он сейчас — не проверено; новую разработку на нём не строить.

**Путь A — отчёты Wordstat через v4 Директа** работают в коде yamcp (август–октябрь 2026): не больше 10 фраз на отчёт, отчёт обязательно удалять, в песочнице недоступен ([yamcp wordstat.py](https://github.com/Lermont/yamcp/blob/main/src/yadirect_mcp/wordstat.py)). Это запасной путь.

### MCP-серверы Директа: сведённый шорт-лист

Имена из брифа сопоставляются так. **«yadirect-mcp»** — это [Lermont/yamcp](https://github.com/Lermont/yamcp): README начинается словами «yadirect-mcp — локальный MCP-сервер для Яндекс Директа»; в PyPI и npm такого пакета нет. **«mcp-yandex-wordstat»** — npm-пакет из [askads/mcp-yandex-wordstat](https://github.com/askads/mcp-yandex-wordstat). **«yandex-mcp»** неоднозначен: так называются [stufently/yandex-mcp](https://github.com/stufently/yandex-mcp), форк [dsbugaev/yandex-mcp](https://github.com/dsbugaev/yandex-mcp) и PyPI-пакет `yandex-mcp` от [nozikov](https://github.com/nozikov/yandex-mcp). Полностью оценён только stufently — он и стоит в таблице. Заметки слоя 2 дополнительно открыли [vtka/yandex-direct-mcp](https://github.com/vtka/yandex-direct-mcp), который в заметках слоя 4 значился лишь по каталогу; ниже он сведён в общую картину.

**Lermont/yamcp — референс №1.** Единственный MCP с прогнозом Live 4, Wordstat и человеко-подтверждаемым запуском. По умолчанию режим `report`: «все доступные инструменты только читают данные», write-инструмент даже не регистрируется. Запись включается явно и идёт по протоколу: план → live preflight → одноразовое подтверждение, привязанное к SHA-256 плана, на 30 минут → форма человеку (MCP elicitation) → применение через v501 → независимый readback. Показы автоматически не запускаются. Есть лимит `client_budget` (по умолчанию 30 000 ₽ с НДС на 14 дней) и белый список логинов `YD_ALLOWED_LOGINS` ([README](https://github.com/Lermont/yamcp)). Ограничения: один автор, 2★, 19 коммитов с 2026-07-16, 79 модулей с агентской спецификой (HTML-отчёты клиентам) ([commits](https://github.com/Lermont/yamcp/commits/main)). Режим `YD_APPROVAL_MODE=task_authorized` выполняет поручения без форм — агенту его не включать. Как подключить: для пилота — агенту по stdio в режиме `report` с зафиксированным коммитом; для продакшена — перенести знание из `forecast.py`, `wordstat.py`, `approval.py` и `api_units.py` в свой Ruby- или Go-клиент. **Плюсы:** готовое знание о подводных камнях Live 4 и v4 и лучший протокол подтверждения. **Минусы:** зависимость от одного человека, Python в контуре.

**Yurich-ru/yandex-ads-mcp — широкое чтение для агента.** 43★, 28 коммитов с 2026-04-14 по 2026-10-04, 3–4 автора ([commits](https://github.com/Yurich-ru/yandex-ads-mcp/commits/master)). Покрытие: Директ 86 инструментов, Метрика 43 (включая загрузку офлайн-конверсий), Аудитории 23, Wordstat 5 через Cloud v2; прогноза нет. Защиты включаются явно: `YD_READONLY=true` блокирует мутации до сетевого вызова, `YD_CONFIRM=true` требует превью, `YD_ALLOWED_LOGINS` ограничивает логины; лимитов бюджета нет ([README](https://github.com/Yurich-ru/yandex-ads-mcp)). Вердикт: брать для чтения агентом с `YD_READONLY=true`; офлайн-конверсии грузить из бэкенда, а не агентом. **Плюсы:** самый широкий охват, учёт `Units`, ретраи. **Минусы:** все защиты opt-in, один файл на ~99 КБ.

**Ask Ads (`mcp-yandex-wordstat`, `mcp-yandex-direct`, `mcp-yandex-metrica`) — лучший UX подключения.** Wordstat-пакет — 5 инструментов на Cloud v2 с повторами на 429 и 5xx; ключ хранится открытым текстом в конфиге клиента ([README](https://github.com/askads/mcp-yandex-wordstat)). Metrica-пакет хранит токен в `~/.config/mcp-yandex-metrica/credentials.json` с правами владельца и сам обновляет его ([README](https://github.com/askads/mcp-yandex-metrica)). Direct-пакет даёт 44 инструмента с пометками read / write / необратимо; `raw_request` для записи требует `confirmWrite=true`; удалённый сервер `https://mcp.askads.ru/mcp` — только чтение ([README](https://github.com/askads/mcp-yandex-direct)). Но по умолчанию вход идёт через встроенное OAuth-приложение askads, то есть полный `direct:api` выдаётся чужому приложению — для кабинета с реальными деньгами это компромисс. Телеметрия включена по умолчанию, выключается `ASKADS_TELEMETRY=0`. Вердикт: Wordstat и Metrica — брать для разведки агентом; Direct — только удалённый read-only или как референс OAuth/PKCE. **Плюсы:** аккуратная упаковка, PKCE и refresh. **Минусы:** нет прогноза и бюджетных лимитов; 3–7★.

**vtka/yandex-direct-mcp — единственный Ruby-нативный.** Заметки слоя 2 прочитали репозиторий напрямую: MIT, **Ruby 3.1+ без внешних зависимостей**, 30 инструментов (кампании, группы, объявления, фразы, отчёты, справочники), API v5, токен в `YANDEX_DIRECT_TOKEN`, песочница; удаление переводит кампанию в архив; 6★, 29 коммитов ([vtka](https://github.com/vtka/yandex-direct-mcp)). Wordstat, прогноза и бюджетных лимитов в описании нет; дата последнего коммита не проверена. Вердикт: референс для своего Ruby-клиента v5, не зависимость.

**stufently/yandex-mcp** (18★, коммит 2026-10-09) — пять серверов, 43 инструмента Директа, плагин и навыки Claude Code, `confirm: true` на мутациях, но «there is no dry-run», а пакеты `@stufently/*` в npm не опубликованы ([README](https://github.com/stufently/yandex-mcp)). Референс упаковки, не брать. Одной строкой об остальных: MarketScore Direct Manager — нет, токен хранится на сервере сервиса ([README](https://github.com/marketscore/marketscore-direct-mcp)); nozikov/yandex-mcp — референс хранения токенов (Keychain, `secret-tool`, файл 0600); artgas1/yandex-metrika-mcp — референс для Метрики, запись скрыта по умолчанию; altrr2/yandex-tools-mcp (65★) три месяца без коммитов; OlegRadinuk, dontsovcmc, SergeyKrin9, dsbugaev — нет.

### Нативных клиентов нет — тонкий клиент пишется самому, объём очерчен

Все Ruby-гемы для Директа заброшены в 2016–2018 годах, для Метрики — в 2011–2014-м, гема для Wordstat нет ([direct-api-v5](https://rubygems.org/gems/direct-api-v5), [metrika](https://rubygems.org/gems/metrika), [поиск](https://rubygems.org/api/v1/search.json?query=wordstat)). Go-модули для Директа — 2015–2023 годов ([pkg.go.dev](https://pkg.go.dev/search?q=yandex+direct&m=package)). Исключение — крошечный Go-клиент Wordstat v2 внутри 977ADAM от 2026-10-02 ([proxy](https://proxy.golang.org/github.com/977!a!d!a!m/yandex-wordstat-mcp-golang/@latest)). Объём своего клиента хорошо очерчен (предложение): Директ v5/v501 (Campaigns, AdGroups, Ads, Keywords, KeywordBids, Reports в TSV), четыре метода прогноза Live 4, четыре эндпоинта Wordstat v2, Метрика (`stat/v1/data`, цели, загрузка офлайн-конверсий). **Плюсы:** полный контроль над деньгами и квотами, без чужих зависимостей. **Минусы:** поддержку изменений API Яндекса несёт основатель; Live 4 может закрыться без замены.

**Доступы получить до разработки:** своё OAuth-приложение и заявку на полный доступ к API Директа; платёжный аккаунт Yandex Cloud, каталог и сервисный аккаунт с API-ключом для Wordstat; OAuth Метрики с `metrika:read`, для офлайн-конверсий — с записью ([README stufently](https://github.com/stufently/yandex-mcp), официально не проверено).

### 4b. ГИР БО, Битрикс24, amoCRM, Kwork: открытые данные вместо скрапинга

**ГИР БО: официального API нет, есть открытая база RFSD.** Документации публичного API bo.nalog.ru не нашлось; госорганы получают сведения через веб-сервис, а для остальных регламент ФНС описывает «абонентское обслуживание», плата и формат которого не выяснены (по сниппету поиска) ([регламент](https://www.consultant.ru/document/cons_doc_LAW_347267/15655fdbaad6f585e347b871961f6ac8c1cd9559/)). Сайт ходит в скрытое JSON-API, его эндпоинты ищут через DevTools (по сниппету поиска) ([Infostart](https://infostart.ru/public/2557058/)); на GitHub — только разовые парсеры с 0–1★ ([поиск](https://github.com/search?q=bo.nalog.ru&type=repositories)). Условия автоматического сбора, капча и лимиты неизвестны, поэтому скрытое API — только резерв.

**RFSD — ядро стоп-фактора «монополист».** Открытая гармонизированная база годовой неконсолидированной бухотчётности всех российских юрлиц за **2011–2025**, лицензия **CC BY 4.0**, авторы из ЕУСПб, статья в Scientific Data ([README](https://github.com/irlcode/RFSD)). Версия 3.1.0 вышла 2026-09-02; срез 2025 года — около 534 МБ Parquet; есть колонки `okved`, `okved_section`, `inn`, `ogrn`, `region`, выручка — `line_2110` ([README](https://raw.githubusercontent.com/irlcode/RFSD/main/README.md), [use case](https://raw.githubusercontent.com/irlcode/RFSD/main/use_cases/tfp.md)). **Как подключить** (предложение): раз в год, в августе–сентябре, скачать свежий срез; rake-задача на геме `duckdb` 1.5.5.1 ([RubyGems](https://rubygems.org/gems/duckdb)) или Go-пакет `duckdb-go/v2` ([proxy](https://proxy.golang.org/github.com/duckdb/duckdb-go/v2/@latest)) считает по ОКВЭД на 2, 4 и 6 знаков число фирм, суммарную выручку, CR1, CR3, HHI и топ-10 и пишет витрину в Postgres. Агенту — один MCP-инструмент `niche_concentration(okved, region, year)`. Порог монополиста (например, CR1 ≥ 50% или HHI ≥ 2 500) выбирает совет. **Плюсы:** бесплатно, офлайн, без нарушения условий ФНС, лицензия разрешает зеркалить. **Минусы:** база **систематически недооценивает концентрацию** — холдинги раздроблены по юрлицам, ИП не сдают отчётность, основной ОКВЭД часто не совпадает с реальным бизнесом, маркетплейсы и иностранные игроки не видны. Лаг — год: данные за 2026 год появятся к июлю 2027 ([README](https://github.com/irlcode/RFSD)). Прямое чтение из Hugging Face через Polars на август 2026 года сломано; доступ к HF и Zenodo из РФ не проверен.

**Checko API — точечная свежесть поверх RFSD.** ЕГРЮЛ, бухотчётность по ИНН, суды, госзакупки, поиск по основному ОКВЭД (по сниппету поиска) ([API](https://checko.ru/integration/api), [search](https://checko.ru/integration/api/search)). Цена: 100 запросов в сутки бесплатно, дальше 0,15 ₽ за запрос (пополнение от 1 000 ₽) или 0,10 ₽ (от 50 000 ₽); ошибки 4xx и 5xx не оплачиваются, суточный лимит трат настраивается (по сниппету поиска). Поиск по ОКВЭД отдаёт компании без выручки и в порядке ОГРН, так что ранжировать нишу через Checko дорого — по вызову на компанию. Проверка топ-20 игроков по 50 идеям — около 1 050 вызовов в неделю; около 700 закрывает бесплатная квота, остальное — порядка 50 ₽ в неделю (предложение, расчёт заметок). Готового MCP нет; оферта об автоматическом использовании не прочитана. **Как подключить:** тонкий клиент, кэш `/finances` в Postgres на ~30 дней, MCP-инструменты `company_card(inn)`, `company_finances(inn)`, `okved_players(okved, region)` с бюджетом вызовов на идею. Альтернативы — одной строкой: DaData отдаёт финансы только на тарифе «Максимальный» с неизвестной ценой ([theYahia/dadata-mcp](https://github.com/theYahia/dadata-mcp)); Контур.Фокус API — от 18 000 ₽ в месяц (по сниппету поиска) ([toolfox](https://toolfox.ru/services/dannye-i-api/obogashchenie-dannyh-kompanii)); открытый набор ФНС `revexp` — резерв на случай остановки RFSD ([nalog.gov.ru](https://www.nalog.gov.ru/rn07/opendata/7707329152-revexp/)).

**Битрикс24 — канал продаж и инструмент агента-кодера.** Официальный `mcp-rest-doc` подключается к Claude Code как HTTP MCP `https://mcp-dev.bitrix24.com/mcp` без ключа и отдаёт документацию REST, а не данные портала ([mcp-rest-doc](https://github.com/bitrix24/mcp-rest-doc)) — брать сразу. Официальный Go SDK `b24gosdk` (MIT, без зависимостей) закрывает webhooks, OAuth, refresh с callback для сохранения токенов, batch до 50 команд и повтор при `QUERY_LIMIT_EXCEEDED`; но ему два месяца (v0.1.0 — 2026-08-06), 4★, соавтор коммитов — «claude», типизированных CRM-сервисов нет ([b24gosdk](https://github.com/bitrix24/b24gosdk), [коммиты](https://github.com/bitrix24/b24gosdk/commits/main)). Брать, если бэкенд на Go; для Rails официального SDK нет, Ruby-гемы устарели ([bitrix24_cloud_api](https://rubygems.org/gems/bitrix24_cloud_api)) — писать свой REST-клиент по образцу b24gosdk. `templates-mcp` — референс архитектуры MCP для порталов: 79 открытых issues при 6★, вероятно, заводят агенты через встроенный инструмент обратной связи ([templates-mcp](https://github.com/bitrix24/templates-mcp)). Экономика Маркета (по сниппету поиска): разработчикам распределяется **85%** подписочного пула по «баллам использования»; за внешние платежи комиссию пока не берут; платные приложения публикуют только ИП и юрлица; модерация может отказать без объяснений ([subscription-details](https://apidocs.bitrix24.ru/market/monetization/subscription-details.html), [publication-requirements](https://raw.githubusercontent.com/bitrix24/b24restdocs/main/market/preparing-to-publish/publication-requirements.md)). API для чтения рейтингов, отзывов и числа установок не документирован ([users-rating](https://raw.githubusercontent.com/bitrix24/b24restdocs/main/market/promoting-and-analytics/users-rating.md)), так что скаутинг по каталогу — только ручные снимки публичных страниц. Ниша «MCP-коннектор для Битрикс24» уже занята минимум пятью приложениями — для стоп-фильтра это сигнал конкуренции.

**amoCRM — референс; гем брать по необходимости.** Официального MCP нет; API v4 ограничен 7 запросами в секунду на IP, частые 429 ведут к блокировке с 403 (по сниппету поиска) ([Kommo](https://developers.kommo.com/docs/limitations)). Публикация — публичная интеграция, технический аккаунт и модерация за 1–2 рабочих дня; комиссия маркетплейса и данные каталога не найдены (по сниппету поиска) ([getting-listed](https://developers.kommo.com/docs/getting-listed)). Для Rails есть свежий гем `amocrm` от Hexlet: 0.6.2 от 2026-10-06, сгенерирован Stainless ([GitHub](https://github.com/Hexlet/amocrm-ruby), [RubyGems](https://rubygems.org/gems/amocrm)). Комьюнити-MCP сырые: `cAIborg-ai/amocrm-mcp` выложен одним коммитом и пишет обновлённые токены на диск по неуказанному пути ([GitHub](https://github.com/cAIborg-ai/amocrm-mcp)). Если интеграция понадобится — свой узкий MCP поверх гема, а не чужой код с токенами CRM.

**Kwork — ценные сигналы, но только вручную.** Официального API не найдено. Единственная живая обёртка `kesha1225/kwork` (MIT, 70★) ходит в закрытый мобильный API, авторизуется логином и паролем и упирается в антибот-капчу; автор советует менять IP через socks5-прокси ([guide](https://raw.githubusercontent.com/kesha1225/kwork/master/docs/guide.md)). Оператор биржи — RemoteFirst Group Limited (Гонконг) и вправе расторгнуть соглашение в одностороннем порядке; пункт об автоматизации в сниппетах оферты не встретился (по сниппету поиска) ([kwork.ru/terms](https://kwork.ru/terms)). При этом карточки биржи дают индекс спроса: желаемый и допустимый бюджет, число предложений, «Нанято, %» (по сниппету поиска) ([kwork.ru/projects](https://kwork.ru/projects)). Вывод (предложение): еженедельный ручной снимок 5–10 категорий; read-only сборщик — только после чтения полной оферты; автоотклики и бот-аккаунты не делать; найм — вручную.

**Вердикт слоя 4.** Брать: официальные API Яндекса через свой клиент, read-only MCP для агента (Ask Ads Wordstat и Metrica, Yurich-ru с `YD_READONLY`), RFSD, Checko, документационный MCP Битрикс24 и b24gosdk для Go. Референсом: yamcp (прогноз, протокол подтверждения), vtka (Ruby-клиент), stufently (упаковка), templates-mcp, гем amoCRM, обёртку Kwork. Самому: тонкие клиенты Директа, Live 4, Wordstat v2, Метрики и Checko; ETL RFSD; шлюз трат; ручные снимки каталогов и Kwork.

## Слой 5. Лендинг и ЮKassa: инфраструктуру покупать, воронку писать

ЮKassa в конкурсе не участвует — она обязательна. В её API v3 есть всё для smoke-теста: встраиваемый виджет, двухстадийные платежи с холдом, возвраты, вебхуки, счета, тестовый магазин и «Чеки от ЮKassa» без своей кассы. Поверх неё готовым стоит брать три вещи: официальный MCP-сервер ЮKassa для агента, шаблон AstroWind и Go-SDK `rvinnie` (если бэкенд на Go). Официальные SDK ЮKassa есть только для PHP и Python, **Ruby в списке нет**, и ЮKassa сама советует генерировать клиент по спецификации (по сниппету поиска) ([Использование SDK](https://yookassa.ru/developers/using-api/using-sdks)). Программно создавать страницы агентом можно только одним способом — генерировать статику: у российских конструкторов нет API на создание страниц.

### Официальный MCP ЮKassa: агенту — ссылки и статусы, деньги — бэкенду

**Что это.** Через MCP-сервер ЮKassa агент создаёт платежи и счета, получает ссылку на оплату и читает платежи, счета и возвраты (по сниппету поиска) ([changelog](https://yookassa.ru/developers/using-api/changelog), [тестирование](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing)). Платёж через MCP — одностадийный «Умный платёж» с ограниченным набором параметров; покупатель вводит данные на странице ЮKassa, карты через агента не проходят ([Умный платёж](https://yookassa.ru/developers/payment-acceptance/integration-scenarios/smart-payment), по сниппету поиска). Токен MCP выпускается отдельно в разделе «Интеграция — Доступы к магазину», у тестового и боевого магазина он разный; секретный ключ магазина агенту не передаётся (по сниппету поиска).

**Почему брать — и только для агента.** Это готовый способ дать агенту тестовые ссылки и мониторинг без секретного ключа магазина. Но холда нет, создание возврата не упоминается, а передать свои `metadata` (ClientId Метрики, `yclid`, ID идеи) «ограниченный набор параметров», скорее всего, не позволит (не проверено). Значит, в воронке лендинга он бэкенд не заменяет. URL, транспорт, список инструментов, лимиты и лицензия — не проверены: yookassa.ru из среды исследования не открывался. **Плюсы:** официальный, отдельный токен, тестовый режим. **Минусы:** закрытая спецификация, нет холда и атрибуции.

Community-MCP `@theyahia/yookassa-mcp` (MIT, 4★, один автор, версии от 0.0.1 до 3.0.0 за три месяца) держит полный `YOOKASSA_SECRET_KEY` в окружении агента и двигает реальные деньги — только референс набора инструментов и защит ([GitHub](https://github.com/theYahia/yookassa-mcp)).

### Платёжный сервис: холд вместо «списать и вернуть»

**Механика** (по сниппету поиска). Платёж с `capture=false` после подтверждения покупателем переходит в `waiting_for_capture`: деньги авторизованы, но не списаны. Срок на списание — от 2 часов до 7 дней в зависимости от способа оплаты, граница приходит в `expires_at`; без действия платёж отменяется ([Payment process](https://yookassa.ru/developers/payment-acceptance/getting-started/payment-process)). Отмена холда возвращает деньги без комиссии, и при большом числе возвратов ЮKassa сама советует двухстадийные платежи ([Refunds](https://yookassa.ru/docs/support/payments/refunding)). Комиссия после обычного возврата не возвращается, кроме возврата в день платежа. Вебхуки идут по HTTPS на порт 443 или 8443, без ответа 200 ЮKassa повторяет отправку 24 часа ([webhooks](https://yookassa.ru/developers/using-api/webhooks)). Карты при обороте до 3 млн ₽ в месяц стоят 3,5% ([тарифы](https://yookassa.ru/docs/support/payments/fees)).

**Схема** (предложение). `POST /checkout` на Rails или Go создаёт платёж: `capture=false`, встраиваемое подтверждение, `Idempotence-Key`, `metadata` с ID идеи, вариантом, ClientId Метрики и `yclid`. Обработчик вебхука не доверяет телу и перепроверяет платёж через `GET`. В конце ступени — массовая отмена холдов или capture, сверка и офлайн-конверсия в Метрику (слой 4). Холд ограничить картами: на способах с двухчасовым окном недельный цикл ломается; какие способы поддерживают холд — не проверено. Ruby-клиент ЮKassa — свой, примерно 200–300 строк (оценка); гем `yookassarb` (0★, все коммиты за одну неделю февраля 2026) — карта эндпоинтов, а гем `yookassa` (последняя версия 2021-11-01) не умеет возвраты и вебхуки ([yookassarb](https://github.com/Wolframko/yookassarb), [yookassa](https://github.com/paderinandrey/yookassa)). Go — `rvinnie/yookassa-sdk-go` с закреплённым коммитом: фактический стандарт сообщества (7 импортёров), но без чеков и счетов ([GitHub](https://github.com/rvinnie/yookassa-sdk-go), [pkg.go.dev](https://pkg.go.dev/search?q=yookassa)). **Плюсы холда:** сильный сигнал намерения без комиссии и без возвратов. **Минусы:** нужен ли чек при холде и его отмене — не проверено; окно холда зависит от способа оплаты.

### Самозанятость и ЮKassa: источники противоречат друг другу

Конфликт не разрешается по заметкам. **Версия 1 — changelog ЮKassa:** «Starting December 29, 2025, YooMoney will no longer support services for self-employed individuals, including receipts for payments and refunds, as well as payouts to the self-employed» (по сниппету поиска) ([changelog](https://yookassa.ru/developers/using-api/changelog), [receipts/self-employed](https://yookassa.ru/developers/payment-acceptance/receipts/self-employed/basics)). **Версия 2 — маркетинговая страница для самозанятых** по-прежнему описывает автоматические чеки в налоговую, работу без онлайн-кассы и комиссии: СБП 0,4% (не больше 1 500 ₽), карты и кошелёк 3,3–3,8% (по сниппету поиска) ([Платежи для самозанятых](https://yookassa.ru/platezhi-dlya-samozanyatyh/)). Новостного подтверждения прекращения не найдено. Заметки о рисках нашли ещё одну пару противоречащих источников: пресс-релиз времён запуска (подключение бесплатно, 1% + НДС за автоматически отправленный чек) и свежий обзор, по которому встроенную поддержку чеков самозанятых прекратили (по сниппету поиска) ([Spark](https://spark.ru/user/128977/blog/96764/yukassa-zapustila-servis-avtomaticheskih-chekov-dlya-samozanyatih), [Quasa](https://quasa.io/ru/media/yukassa-ili-robokassa-dlya-samozanyatogo-komissii-cheki-i-usloviya-podklyucheniya)). Те же заметки допускали старт на НПД с переходом на ИП при 70–80% лимита; но у НПД потолок 2,4 млн ₽ дохода в год и запрет перепродажи чужих товаров (по сниппету поиска) ([Моё дело](https://www.moedelo.org/club/article-knowledge/limit-samozanyatogo), [Контур.Эльба](https://kontur.ru/elba/spravka/81251-ogranicheniya_i_zaprety_dlya_samozanyatyh)), а при обязательной ЮKassa такой старт упирается в неразрешённый спор. Принимает ли ЮKassa сейчас самозанятых — **не проверено**.

**Предложение: ИП на УСН + «Чеки от ЮKassa».** Это решение работает при любом исходе спора. «Чеки от ЮKassa» подходят ИП и ООО и не требуют своей ККТ, фискального накопителя и ОФД; обслуживание бесплатное, платят за пробитые чеки ([54fz](https://yookassa.ru/54fz/), по сниппету поиска). ОГРНИП заодно закрывает требование Директа к сведениям о продавце ([требования](https://yandex.ru/support/direct/ru/moderation/categories/goods-and-services), по сниппету поиска). **Плюсы:** автоматические чеки, понятная модерация ЮKassa и Директа. **Минусы:** ИП нужно зарегистрировать до первого теста; официальная цена чека не найдена (вторичный источник пишет «от 0,1% за чек» — не проверено) ([1000bankov](https://1000bankov.ru/rko/tarify/yoomoney/)).

### Лендинг: агент генерирует данные, а не код

**AstroWind** — MIT, 6.0k★, Astro v7 и Tailwind v4, больше 30 типизированных секций, 6 примеров лендингов, статическая сборка, `AGENTS.md` и skills для ИИ-ассистентов; последний коммит 2026-09-12; v1 в режиме поддержки, v2 обещан на октябрь 2026 ([GitHub](https://github.com/arthelokyo/astrowind)). **Схема** (предложение): агент пишет `content.json` по фиксированной схеме секций (hero, проблема, решение, цена, FAQ, предзаказ, юр-футер), Astro рендерит, линтер проверяет чек-лист модерации, деплой — после одобрения советом. Хостинг — Yandex Object Storage на своём домене с HTTPS через Certificate Manager, включая бесплатный Let's Encrypt (по сниппету поиска) ([Yandex Cloud](https://yandex.cloud/en/docs/storage/operations/hosting/own-domain)). Виджет ЮKassa встраивается в статику: страница получает только `confirmation_token` конкретного платежа, секретов на ней нет ([виджет](https://yookassa.ru/developers/payment-acceptance/integration-scenarios/widget/quick-start), по сниппету поиска). ЮKassa модерирует сайт: оферта, цены, реквизиты, контакты, оплата на подключённом сайте ([требования](https://yookassa.ru/docs/support/payments/onboarding/arrangement), по сниппету поиска). Отсюда идея зонтичного домена, который совет одобряет, а ЮKassa проверяет один раз; пускает ли ЮKassa новые пути и поддомены без повторной проверки — не проверено. **Плюсы:** полный контроль агента, хостинг в РФ без своих серверов, юр-блоки зашиты в шаблон. **Минусы:** форк надо поддерживать; переход на v2 потребует миграции.

**Почему не конструкторы.** API Tilda только читает и экспортирует (`getprojectslist`, `getpageslist`, `getpageexport`), доступен лишь на тарифе Business и передаёт ключи в строке запроса (по сниппету поиска) ([help.tilda.cc](https://help.tilda.cc/api)) — годится как ручной запасной вариант. У Creatium, Flexbe и LPmotor публичного API для создания страниц не найдено. Сайт в Яндекс Бизнесе — один на компанию, Турбо-страницы закрыты (по сниппету поиска) ([Яндекс Бизнес](https://yandex.ru/support/business-priority/ru/create-site.html), [click.ru](https://blog.click.ru/market-news/yandeks-prekratil-podderzhku-turbo-stranic/)). Puck (MIT, 13.5k★) — референс идеи «страница = JSON по схеме компонентов» ([GitHub](https://github.com/puckeditor/puck)); GrapesJS и Webstudio (AGPL) избыточны.

### Юридический минимум smoke-теста

Синтез заметок, не юридическая консультация. Реклама недостоверна, если неверно сообщает «о возможности… приобретения в определенном месте или в течение определенного срока» (ст. 5 ч. 3 п. 3 38-ФЗ, по сниппету поиска) ([КонсультантПлюс](https://www.consultant.ru/document/cons_doc_LAW_58968/f67f81c57fdcdacc2643d19d59369f7e185e1156/)). Договор с предоплатой обязан содержать срок передачи товара, а требование о возврате удовлетворяется за 10 дней (ст. 23.1 ЗоЗПП, по сниппету поиска) ([КонсультантПлюс](https://www.consultant.ru/document/cons_doc_LAW_305/cd5055f2729d0ba6bf1c3724ba16ca46ea92e0f7/)). Предоплата по 54-ФЗ — тоже расчёт: при полной предоплате нужны два чека, при возврате — «возврат прихода» (по сниппету поиска) ([buh.ru](https://buh.ru/news/khroniki-54-fz-kassovye-cheki-pri-prodazhakh-s-polnoy-predoplatoy-i-podgotovka-uproshchentsami-kkt-d.html)). Директ требует сведений о продавце в объявлениях о дистанционной продаже и сам ставит ERID на каждый креатив; заглушки «сайт в разработке» и редиректы запрещены (по сниппету поиска) ([маркировка](https://yandex.ru/support/direct/en/technologies-and-services/ad-labelingl), [правила](https://yandex.ru/support/direct/en/moderation/ad-rules)). Отсюда чек-лист (предложение): ИП и профиль Яндекс Бизнеса с реквизитами; футер с ФИО, ОГРНИП, ИНН и контактами; оферта со сроком передачи и условиями отмены; слово «предзаказ» с датой старта; никаких «в наличии» и фейковых отзывов; обещание автоматически снять бронь, если запуск не состоится. Не проверено: нужен ли чек при отменённом холде, требования 152-ФЗ к политике ПДн и уведомление о cookie для Метрики.

**Измерение.** На фронте — цели `reachGoal` (`checkout_open`, `payment_authorized` с суммой); на бэкенде — офлайн-конверсия по вебхуку с ClientId (получается методом `getClientID`, самая точная привязка) и `yclid` (по сниппету поиска) ([offline-params](https://yandex.ru/support/metrica/ru/data/offline-params)). Нативной интеграции ЮKassa → Метрика нет, только платный коннектор ApiMonster ([apimonster](https://apimonster.ru/connector/bundle/yookassa/yandexMetrika/), по сниппету поиска).

**Вердикт слоя.** Покупать: ЮKassa (API, виджет, холды, «Чеки от ЮKassa», тестовый магазин), Метрику, Object Storage. Брать готовым: официальный MCP ЮKassa для агента, AstroWind, `rvinnie` для Go. Писать самому: генератор лендинга по схеме с юр-линтером, платёжный сервис с холдом и вебхуками, Ruby-клиент ЮKassa, мост в Метрику.

## Слой 6. Ruby-экосистема: RubyLLM закрывает рантайм агентов, официальный MCP SDK — инструменты

В Ruby почти весь агентный рантайм приходит одним гемом поверх ActiveRecord и ActiveJob — **RubyLLM 2.1**: агенты, инструменты с одобрением человека, structured output, durable-агенты, MCP-клиент и журнал затрат. MCP-серверы он не строит — для них есть официальный SDK `mcp` 1.x. Слабые места общие для всех Ruby-кандидатов: нет нативных провайдеров YandexGPT и GigaChat, стоимость российских моделей не считается, бюджеты учитываются, но не принуждаются. Нативных Ruby-гемов для YandexGPT не найдено вовсе ([поиск](https://rubygems.org/api/v1/search.json?query=yandexgpt)).

### RubyLLM 2.1: брать как ядро агентов

**Что это.** «Ruby-native AI framework»: 19 провайдеров «and any OpenAI-compatible API», агенты `RubyLLM::Agent`, инструменты, `with_schema` для structured output ([README](https://github.com/crmne/ruby_llm/blob/main/README.md)). Одобрение человека встроено: `requires_approval` паркует прогон, решение хранится в БД (`chat.approve`, `chat.deny`, `chat.pending_approvals`) ([durable-agents](https://github.com/crmne/ruby_llm/blob/main/docs/_advanced/durable-agents.md)). Durable-агенты: «The Transcript Is the State», «один ход на job» или весь цикл на `ActiveJob::Continuable` (Rails 8.1+) с `checkpoint!`; гарантия — «At-Least-Once, Not Exactly-Once», поэтому инструменты обязаны быть идемпотентными. Документация описывает паттерны Fan-Out/Fan-In и Evaluator-Optimizer — прямо под скаута на 50 идей и турнир ([workflows](https://github.com/crmne/ruby_llm/blob/main/docs/_advanced/agentic-workflows.md)). Каждая попытка вызова пишется в журнал `ruby_llm_usages` с полиморфным `owner` — основа бюджетов по агентам и неделям ([cost](https://github.com/crmne/ruby_llm/blob/main/docs/_core_features/cost-and-usage-tracking.md), [persistence](https://github.com/crmne/ruby_llm/blob/main/docs/_advanced/rails-persistence.md)). В гем входит Agent Skill для Claude Code ([ai-coding-assistants](https://github.com/crmne/ruby_llm/blob/main/docs/_getting_started/ai-coding-assistants.md)). Версия 2.1.0 — 2026-10-08, 4.4k★, 13.6 млн загрузок ([RubyGems](https://rubygems.org/api/v1/versions/ruby_llm.json), [GitHub](https://github.com/crmne/ruby_llm)).

**Ограничения.** Бюджет не принуждается: механизма «стоп при превышении» в документации нет, нужен свой guard перед `step`. Для моделей вне реестра цен `cost.total` равен `nil` — рублёвую стоимость YandexGPT и GigaChat считать своей таблицей тарифов ([cost](https://github.com/crmne/ruby_llm/blob/main/docs/_core_features/cost-and-usage-tracking.md)). Мажор 2.0 вышел 2026-09-18 и ломающий: OpenAI по умолчанию переехал на Responses API ([releases](https://github.com/crmne/ruby_llm/releases)). Плагины отстают: `ruby_llm-mcp`, `dspy-ruby_llm` и `swarm_sdk` пинят версии ниже 2.0 ([ruby_llm-mcp](https://rubygems.org/api/v1/gems/ruby_llm-mcp.json), [dspy-ruby_llm](https://rubygems.org/api/v1/gems/dspy-ruby_llm.json), [swarm_sdk](https://rubygems.org/api/v1/gems/swarm_sdk.json)). `RubyLLM::Judge` по умолчанию ходит к провайдеру TypeSafe — для турнира в РФ его заменить на свои попарные сравнения через `with_schema` ([configuration.rb](https://github.com/crmne/ruby_llm/blob/main/lib/ruby_llm/configuration.rb)). Все последние коммиты — от одного мейнтейнера ([commits](https://github.com/crmne/ruby_llm/commits/main)).

**Как подключить.** `bundle add ruby_llm` → `rails generate ruby_llm:install` → `db:migrate` → `ruby_llm:load_models`, модели с `acts_as_chat` ([README](https://github.com/crmne/ruby_llm/blob/main/README.md)). YandexGPT (гипотеза, вживую не проверено): либо свой провайдер на «a few dozen lines» с заголовком `Api-Key`, URI модели `gpt://<folder>/<model>/<version>` и протоколом Chat Completions ([custom-providers](https://github.com/crmne/ruby_llm/blob/main/docs/_reference/custom-providers.md), [Yandex SDK](https://github.com/yandex-cloud/yandex-cloud-ml-sdk/blob/master/src/yandex_ai_studio_sdk/_auth.py)); либо провайдер `:openai` с `openai_api_base = https://llm.api.cloud.yandex.net/v1`, `openai_protocol = :chat_completions`, `assume_model_exists` и IAM-токеном вместо ключа — заголовок `Bearer` для IAM-токена подтверждён в SDK Yandex ([configuration-providers](https://github.com/crmne/ruby_llm/blob/main/docs/_getting_started/configuration-providers.md)). Примет ли эндпоинт так же API-ключ и вернёт ли usage — не проверено. GigaChat — не drop-in OpenAI: токен живёт 30 минут, нужен корневой сертификат Минцифры ([gigachat](https://github.com/ai-forever/gigachat/blob/master/README.md)). Минимум кода — sidecar `gpt2giga` на `http://localhost:8090/v1` ([gpt2giga](https://github.com/ai-forever/gpt2giga/blob/main/README.md)); «чистый Ruby» — свой провайдер поверх `gigachat-ruby`, которому неделя от роду ([README](https://github.com/amdest/gigachat-ruby/blob/main/README.md)).

**Плюсы.** Одобрения, durable-исполнение и журнал затрат — из коробки, в той же БД, что и бизнес-данные. **Минусы.** Bus factor 1; свежий ломающий мажор; российские провайдеры и рубли — своим кодом.

### MCP Ruby SDK: брать для своих MCP-серверов в Rails

**Что это.** «The official Ruby SDK for Model Context Protocol servers and clients»: tools, prompts, resources, OAuth 2.1 в клиенте, транспорты stdio и Streamable HTTP ([README](https://github.com/modelcontextprotocol/ruby-sdk)). Версия 1.0.0 — 2026-07-24, 1.7.0 — 2026-10-05, 35 релизов за год; лицензия нового кода с версии 0.6.0 — Apache-2.0 ([RubyGems](https://rubygems.org/api/v1/versions/mcp.json)). `StreamableHTTPTransport` — Rack-приложение: монтируется в `config/routes.rb` или вызывается из контроллера в stateless-режиме ([docs](https://ruby.sdk.modelcontextprotocol.io/server/transports/)).

**Почему брать.** Это способ отдать свои инструменты (Wordstat, Директ, ГИР БО, ЮKassa, выборки из БД) сразу двум потребителям: Claude Code для разработки и ручных операций и агентам RubyLLM через MCP-клиент. Практичный паттерн (предложение заметок): одна бизнес-логика в сервис-объектах и два тонких адаптера — `RubyLLM::Tool` и `MCP::Tool`.

**Ограничения.** Аутентификацию делает приложение: identity — через `server_context`, сессии — через `session_request_validator`; по умолчанию принимаются только loopback-хосты ([docs](https://ruby.sdk.modelcontextprotocol.io/server/transports/)). Stateless-режим удобен для нескольких процессов Puma, но теряет server-to-client запросы, включая elicitation — тот самый механизм формы подтверждения, на котором yamcp строит одобрение трат. Сессии по умолчанию в памяти, при нескольких инстансах нужны sticky sessions. 11.2 млн загрузок при 923★ — вероятно, транзитивные зависимости (гипотеза). Для Go есть официальный `go-sdk` v1.8.0, дошедший до 1.0 на 10 месяцев раньше ([proxy](https://proxy.golang.org/github.com/modelcontextprotocol/go-sdk/@latest)): для MCP-сервера выбор стека не критичен.

**Плюсы.** Официальный, активный, одна зависимость. **Минусы.** Безопасность транспорта — на вас; elicitation только в stateful-режиме.

### ActiveAgent: референс архитектуры, а не второй рантайм

**Что это.** «The only agent-oriented AI framework designed for Rails, where Agents are Controllers»: агент — класс, этап — action, промпт — ERB-вьюха, фон — `generate_later` через ActiveJob ([README](https://github.com/activeagents/activeagent/blob/main/README.md)). Делегирование с бюджетом: `delegate_to Agent, budget: { max_calls:, max_tokens: }`, но «Budgets are scoped to one generation» ([delegation](https://github.com/activeagents/activeagent/blob/main/docs/actions/delegation.md)). MCP подключается через `mcps:` с `require_approval` ([mcps](https://github.com/activeagents/activeagent/blob/main/docs/actions/mcps.md)).

**Почему референс.** Дублирует слой RubyLLM, а тянуть два фреймворка сразу незачем. Хранение вынесено в гем `solid_agent` версии 0.2.1, недельный бюджет агента всё равно писать самому. Темп — 17 релизов за 90 дней, среди авторов последних коммитов — `claude` и `codex`, рядом коммерческая платформа activeagents.ai ([RubyGems](https://rubygems.org/api/v1/versions/activeagent.json), [commits](https://github.com/activeagents/activeagent/commits/main)). Параметр `host` у OpenAI-провайдера описан «for Azure OpenAI»; работа с Yandex не проверена ([open_ai](https://github.com/activeagents/activeagent/blob/main/docs/providers/open_ai.md)). **Что взять:** ERB-промпты, бюджет делегирования, схему `solid_agent` для памяти и прогонов. **Плюсы:** самая «рельсовая» ментальная модель. **Минусы:** незрелое хранение, бешеный темп релизов.

### langchainrb и остальные — нет

langchainrb не выпускал релизов 17 месяцев: последний — 0.19.5 от 2025-05-01, хотя коммиты идут до 2026-09-09, а в Unreleased лежат ломающие изменения ([RubyGems](https://rubygems.org/api/v1/versions/langchainrb.json), [CHANGELOG](https://github.com/patterns-ai-core/langchainrb/blob/main/CHANGELOG.md)). `langchainrb_rails` 0.1.12 от 2024-09-20 пинит `langchainrb < 0.17` ([RubyGems](https://rubygems.org/api/v1/gems/langchainrb_rails.json)). Вердикт — нет. Одной строкой об остальных: fast-mcp заглох с 2025-09-28 — есть официальный SDK ([commits](https://github.com/yjacquin/fast-mcp/commits/main)); `ruby_llm-mcp` несовместим с RubyLLM 2.x, в 2.1 есть свой MCP-клиент; `ruby-openai` год без релизов; гем `anthropic` для продакшен-контура в РФ не подходит по той же причине, что и Claude Agent SDK; `ruby_llm-agents` — референс бюджетов (daily/monthly, hard/soft, circuit breakers), где недавно чинили недоучёт токенов в циклах инструментов ([README](https://github.com/adham90/ruby_llm-agents/blob/main/README.md), [CHANGELOG](https://github.com/adham90/ruby_llm-agents/blob/main/CHANGELOG.md)); DSPy.rb — референс типизированного скоринга ([README](https://github.com/vicentereig/dspy.rb/blob/main/README.md)).

### Расписание цикла: Solid Queue или GoodJob вместо Temporal

Solid Queue описывает recurring tasks в `config/recurring.yml` и исполняет их отдельным процессом-шедулером (1.7.0 от 2026-08-21, MIT) ([README](https://github.com/rails/solid_queue#recurring-tasks)). GoodJob даёт cron, где «enabling cron on multiple processes will not enqueue duplicate jobs», и веб-дашборд, но работает только с Postgres ([README](https://github.com/bensheldon/good_job#cron-style-repeatingrecurring-jobs)). ActiveJob Continuations в Rails 8.1+ переживают деплой — на них RubyLLM строит durable-агентов ([API](https://api.rubyonrails.org/classes/ActiveJob/Continuable.html)). **Предложение:** одному прогону в неделю хватит штатных средств Rails — стартовать на Solid Queue или GoodJob с конечным автоматом цикла в БД; Temporal подключать, только если появятся долгие ожидания и ретраи, которые эта связка не держит. **Плюсы:** ноль новой инфраструктуры. **Минусы:** гарантии ожидания решения совета и таймеров лестницы придётся обеспечить своим кодом.

### Ruby или Go: готового больше в Ruby

В Go сильные официальные SDK — MCP v1.8, OpenAI v3.74, Anthropic v1.79 ([go-sdk](https://proxy.golang.org/github.com/modelcontextprotocol/go-sdk/@latest), [openai-go](https://proxy.golang.org/github.com/openai/openai-go/v3/@latest), [anthropic-sdk-go](https://proxy.golang.org/github.com/anthropics/anthropic-sdk-go/@latest)) — и зрелый Genkit Go 1.x («Production-ready») ([README](https://github.com/firebase/genkit/blob/main/README.md)), но нет аналога связки RubyLLM + Rails с хранением транскриптов, одобрениями, durable-исполнением и журналом затрат «из коробки». Сводная картина по слоям (предложение): за Ruby — RubyLLM, Solid Queue / GoodJob и гем amoCRM; за Go — официальный SDK Битрикс24, `rvinnie` для ЮKassa, Go-клиент Wordstat у 977ADAM и более стабильные клиентские SDK LLM-провайдеров. Официальный MCP SDK и Temporal есть для обоих. Клиенты Директа, Метрики, ГИР БО и Checko живых нет ни в одном стеке — их писать в любом случае. **Предложение: ядро на Rails.** **Плюсы:** меньше своего кода на оркестрацию, хранение и UI совета. **Минусы:** один мейнтейнер у RubyLLM, свежий мажор 2.0, Ruby-клиенты ЮKassa и Битрикс24 — свои. Альтернатива — ядро на Go (Genkit или свой код плюс Temporal): официальнее клиентские SDK и, вероятно, проще эксплуатация одним бинарником (допущение), но схему БД, очередь задач и админку совета придётся писать самому.

**Вердикт слоя.** Брать: RubyLLM `~> 2.1`, `mcp` `~> 1.7`, Solid Queue или GoodJob. Референсом: ActiveAgent, ruby_llm-agents, DSPy.rb, gigachat-ruby и gpt2giga. Нет: langchainrb, fast-mcp, ruby_llm-mcp, ruby-openai. Самому: провайдеры YandexGPT и GigaChat, рублёвый прайсинг и guard бюджета, UI одобрений, оркестрация цикла.

## Деньги и токены: один рублёвый реестр и один шлюз трат

Заметки трёх слоёв и сквозных рисков пришли к одному выводу с разных сторон, и здесь он сведён в одну рекомендацию. Бюджеты Paperclip — это `budgetMonthlyCents` только на LLM, а учёт внешних доходов и расходов записан в спецификации как «future plugin» ([SPEC](https://github.com/paperclipai/paperclip/blob/master/doc/SPEC.md)). Бюджеты Claude Managed Agents — центы USD на сессию ([MA budgets](https://platform.claude.com/docs/en/managed-agents/budgets)). RubyLLM считает расходы, но не ограничивает их, а для российских моделей стоимость равна `nil` ([cost](https://github.com/crmne/ruby_llm/blob/main/docs/_core_features/cost-and-usage-tracking.md)). При этом у Директа один OAuth-scope, и токен даёт приложению все «действия, которые доступны пользователю, для которого получен токен» (по сниппету поиска) ([Директ API](https://yandex.ru/dev/direct/doc/ru/concepts/auth-token)). Агент, который читает недоверенный контент — идеи, страницы конкурентов, ответы инструментов — и держит такой токен, становится мишенью prompt injection.

**Предложение.** Деньги живут в одном месте и тратятся одним путём.

**Два учёта, а не один.** LLM-расходы — в Paperclip (если идёт пилот) или в `ruby_llm_usages` со своей таблицей рублёвых тарифов и guard перед каждым шагом агента. Деньги бизнеса — реклама, предоплаты, возвраты — в собственном append-only рублёвом реестре в своей БД.

**Шлюз трат — единственный держатель write-токена Директа и секретного ключа ЮKassa.** Агент присылает план. Шлюз проверяет логин по белому списку, лимит текущей ступени лестницы, статус кампании и расход баллов. Совет утверждает план — через approval в Paperclip, Rails UI или Telegram. Шлюз применяет, делает readback и пишет аудит с личностью одобрившего и суммой. Каждое повышение ступени — отдельное утверждение; создание кампании и запуск показов разведены, как в yamcp ([README](https://github.com/Lermont/yamcp)). Доступ к API Директа можно ограничить по IP (по сниппету поиска) ([доступ](https://yandex.ru/dev/direct/doc/ru/concepts/access)).

**Агентам — только чтение.** Wordstat, отчёты Директа и Метрика — через MCP с `YD_READONLY=true` и аналогичными флагами; для агента — отдельный аккаунт или представитель с правами только на просмотр, если такая роль в Директе есть (не проверено). ЮKassa — официальный MCP по отдельному токену или свой эндпоинт «создать ссылку на оплату» с потолком суммы. Секретного ключа магазина у агента нет.

**Секреты — в хранилище.** Yandex Lockbox, Vault или systemd credentials; никогда в промптах, логах и `.mcp.json`; ротация плановая и внеплановая при любом инциденте в цепочке поставок зависимостей.

**Живой дашборд реальных денег для совета.** Фактический расход Директа и предоплаты из вебхуков ЮKassa вместо run-rate — идея NanoCorp; автопауза трат и агентов эксперимента при непрохождении порога.

**Плюсы.** Деньги нельзя потратить через prompt injection; инварианты (max CPC, стоп-пороги ступеней, потолок риска) живут в одном коде; совет видит аудит каждой траты. **Минусы.** Это самый ответственный код системы, и пишет его основатель; каждое утверждение добавляет трение; пока не подтверждена read-only роль в Директе, разделение токенов держится только на коде.

## Риски: доступ к LLM, накрутка, токены, lock-in, заброшенность

### Доступ к LLM: под угрозой рантайм агентов, а не только инструмент разработки

России нет в списке поддерживаемых стран Anthropic: «Any country or region not listed is unsupported» ([supported countries](https://www.anthropic.com/supported-countries)). С сентября 2025 года запрет распространён на компании, которые более чем на 50% принадлежат компаниям со штаб-квартирой в неподдерживаемых регионах, в том числе через дочерние структуры в других странах ([Anthropic](https://www.anthropic.com/news/updating-restrictions-of-sales-to-unsupported-regions)). Commercial Terms позволяют приостановить доступ при нарушении региональной политики, Consumer Terms — «at any time… without notice» ([Commercial Terms](https://www.anthropic.com/legal/commercial-terms), [Consumer Terms](https://www.anthropic.com/legal/consumer-terms)). По сообщениям СМИ, в мае 2026 года доступ потеряли «несколько сотен» пользователей из РФ, включая аккаунты Claude Code, а 2 октября 2026 года появились новые жалобы; официального заявления Anthropic нет (по сниппету поиска) ([SecurityLab](https://www.securitylab.ru/news/572607.php), [Новая газета Европа](https://novayagazeta.eu/articles/2026/10/02/polzovateli-claude-iz-rossii-i-gonkonga-pozhalovalis-na-blokirovki-akkauntov-posle-podkliucheniia-cherez-vpn-news)). Агрегаторы не спасают: OpenRouter, по одному источнику, с 27 июня 2026 года отвечает российским IP ошибкой 403 (по сниппету поиска) ([SSD Nodes](https://www.ssdnodes.com/learn/lang/ru/claude-api-from-russia-what-works)). Отсюда разделение. Claude Code как инструмент разработки — текущая рабочая настройка основателя; потеря доступа снизит продуктивность. Claude как рантайм агентов-сотрудников остановил бы цикл с реальными деньгами — поэтому Claude Agent SDK в отчёте только референс.

Российские альтернативы дают OpenAI-совместимый интерфейс и function calling: Yandex AI Studio — Chat Completions и Responses (по сниппету поиска) ([AI Studio API](https://aistudio.yandex.ru/docs/en/ai-studio/concepts/api), [function calling](https://yandex.cloud/en/docs/ai-studio/concepts/generation/function-call)); GigaChat — функции и пакеты токенов, пакет GigaChat Lite на 300 млн токенов стоит 19 500 ₽, то есть около 0,065 ₽ за 1 000 токенов (по сниппету поиска) ([тарифы](https://developers.sber.ru/docs/ru/gigachat/tariffs/legal-tariffs)); Cloud.ru — каталог с GigaChat, Qwen и DeepSeek (по сниппету поиска) ([Habr](https://habr.com/ru/companies/cloud_ru/posts/927880)). Главная неизвестная — качество вызова инструментов в многошаговых циклах: независимого бенчмарка нет. Шлюз LiteLLM снижает привязку, но сам стал вектором атаки: 24 марта 2026 года в PyPI вышли скомпрометированные версии 1.82.7 и 1.82.8 со стилером учётных данных (по сниппету поиска) ([BleepingComputer](https://bleepingcomputer.com/news/security/popular-litellm-pypi-package-compromised-in-teampcp-supply-chain-attack)), а в базе advisories по нему 58 записей, включая обход аутентификации MCP ([GitHub Advisories](https://github.com/advisories?query=litellm)).

**Предложение.** Своё ядро с тонким OpenAI-совместимым клиентом; цепочка резерва: Yandex AI Studio → GigaChat → open-weight модель на своей или арендованной GPU; ежемесячный прогон eval-набора каждой роли на всех провайдерах; шлюз — либо не использовать, либо держать в отдельном контейнере без платёжных и рекламных секретов; персональные данные клиентов в зарубежные модели не отправлять. **Плюсы:** нет единой точки отказа. **Минусы:** eval-набор нужно собрать, а качество российских моделей в агентной роли может оказаться слабым.

### Накрученная популярность: органичность роста Paperclip не доказана и не опровергнута

Фон: исследование StarScout (ICSE 2026) насчитало около 6 млн подозрительных звёзд; к июлю 2024 года в кампаниях накрутки участвовали 16,66% репозиториев с 50+ звёздами, а AI/LLM-проекты — среди основных получателей вне малвари (по сниппету поиска) ([StarScout](https://github.com/hehao98/StarScout), [Gigazine](https://gigazine.net/gsc_news/en/20260421-github-fake-star)).

**За органический рост.** За звёздами стоит реальная активность: 4 930 коммитов, больше 2 700 смёрженных PR, 16.7k форков ([repo](https://github.com/paperclipai/paperclip), [README](https://github.com/paperclipai/paperclip/blob/master/README.md)). Отношение форков к звёздам ≈ 0,17 (на июнь — 0,19, прирост июнь→октябрь — около 0,13) лежит в «органическом» диапазоне 0,10–0,24 из невалидированных эвристик практиков ([Korben](https://korben.info/en/fake-github-repositories-why-its-a-problem.html)). Рост шёл не одним всплеском: около 20k звёзд за первую неделю, 43.9k за месяц, 69 955 на 11.06.2026 при 105 контрибьюторах, около 71k к концу июня и 99.1k к октябрю (по сниппету поиска) ([ThursdAI](https://thursdai.news/companies/paperclip), [OSSInsight](https://ossinsight.io/blog/zero-human-company-2026), [Fast.io](https://fast.io/resources/paperclip-ai-review-2026/)). Публикаций, связывающих Paperclip с накруткой, не найдено — это отрицательный результат, Hacker News не проверялся.

**Против.** 99.1k звёзд за ~7,5 месяца — намного быстрее, чем у CrewAI (59.5k с 2023 года) и LangGraph (43.0k с 2024 года) ([CrewAI](https://github.com/crewAIInc/crewAI), [LangGraph](https://github.com/langchain-ai/langgraph)). По watchers заметки расходятся в выборе эталона: у Paperclip их ≈0,47% от звёзд — почти как у LangGraph (~0,44%, заметки слоя 1), но вдвое меньше, чем ~0,8–0,9% у microsoft/autogen и agent-framework (заметки о рисках) ([autogen](https://github.com/microsoft/autogen), [agent-framework](https://github.com/microsoft/agent-framework)); индикатор не валидирован. 3.4k открытых PR при ~2,7k смёрженных; релизная работа сосредоточена у одного мейнтейнера, команда и финансирование не раскрыты (по сниппету поиска) ([Ry Walker](https://rywalker.com/research/paperclip)). Кривая star-history и выборка старгейзеров не собраны.

**Итог:** органичность не доказана и не опровергнута. Практический вывод (предложение): звёзды — нулевой вес в решении, решает пилот на своих данных. То же касается idea-validation-agents (478★ при 9 коммитах) и ниши MCP, где каталоги ранжируют серверы по звёздам. Чек-лист due diligence: кривая star-history и выборка старгейзеров из всплесков, отношения форков и watchers к звёздам, число контрибьюторов со смёрженными PR за 90 дней, OpenSSF Scorecard (Maintained, Code-Review, Contributors) ([Scorecard](https://github.com/ossf/scorecard/blob/main/docs/checks.md)), время реакции на issues. **Плюсы:** дёшево. **Минусы:** эвристики не валидированы. Цифры Polsia — самоотчёт: по одному разбору, заявленные ~$10 млн складываются из ~$4,6 млн подписочного ARR, ~$2 млн разовых пакетов и ~$2 млн рекламных бюджетов клиентов (по сниппету поиска) ([RuntimeWire](https://runtimewire.com/article/polsia-ben-broca-10-million-revenue-zero-employees)).

### Хранение токенов и безопасность MCP: пишущие ключи — вне контекста LLM

Спецификация MCP прямо говорит «Authorization is OPTIONAL»; STDIO-серверы берут ключи из окружения; сервер «MUST NOT pass through the token it received from the MCP client» ([spec 2025-11-25](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2025-11-25/basic/authorization.mdx)). Инциденты реальны: отравление описаний инструментов и «rug pull» ([Invariant Labs](https://github.com/invariantlabs-ai/mcp-injection-experiments)); первый вредоносный MCP-сервер postmark-mcp, версия которого добавила скрытую копию всех писем атакующему (по сниппету поиска) ([Snyk](https://snyk.io/de/blog/malicious-mcp-server-on-npm-postmark-mcp-harvests-emails/)); RCE в mcp-remote с CVSS 9,6 ([GHSA-6xpm-ggf7-wc3p](https://github.com/advisories/GHSA-6xpm-ggf7-wc3p)); атака s1ngularity, которая запускала установленные Claude Code и Gemini CLI искать секреты на диске (по сниппету поиска) ([Semgrep](https://ai.semgrep.dev/blog/2025/security-alert-nx-compromised-to-steal-wallets-and-credentials)). Сессия `claude -p` не показывает ни диалога доверия к папке, ни подтверждения серверов из `.mcp.json`, а Anthropic «does not security-audit or manage any MCP server» ([Security](https://code.claude.com/docs/en/security)).

Где лежат ключи у кандидатов: yamcp — `YD_TOKEN` в окружении; Yurich-ru — `.env` или `~/.claude.json`; Ask Ads Wordstat — ключ открытым текстом в конфиге клиента, Ask Ads Metrica — файл с правами владельца; MarketScore — на сервере сервиса; `@theyahia/yookassa-mcp` — полный секретный ключ ЮKassa в окружении агента; Paperclip — шифрование локальным мастер-ключом; официальный MCP ЮKassa — отдельный токен без секретного ключа (источники — в разделах слоёв 1, 4 и 5). **Предложение:** схема из раздела «Деньги и токены» плюс гигиена MCP — белый список серверов, фиксация версий и хэшей вместо `npx -y …@latest`, сторонние серверы в контейнере без лишнего egress, ревью описаний инструментов при каждом обновлении, отдельное dev-окружение без продакшен-секретов, журнал и алерты на любые вызовы, меняющие деньги или кампании. **Плюсы:** закрывает известные классы атак. **Минусы:** трение и ручные обновления зафиксированных версий.

### Vendor lock-in и заброшенность: стек меняется быстрее, чем живёт MVP

За 2025–2026 годы AutoGen ушёл в режим поддержки с переездом на Microsoft Agent Framework ([autogen](https://github.com/microsoft/autogen)); эталонные MCP-серверы заархивированы с пометкой «NO SECURITY GUARANTEES» ([servers-archived](https://github.com/modelcontextprotocol/servers-archived)); спецификация MCP 2026-07-28 удалила сессии и handshake и объявила устаревшими HTTP+SSE и Dynamic Client Registration ([changelog](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/changelog.mdx)); AgentGPT заархивирован при 36.3k звёзд ([AgentGPT](https://github.com/reworkd/AgentGPT)); OpenAI объявила отключение Assistants API на 26.08.2026 (по сниппету поиска) ([OpenAI Community](https://community.openai.com/t/assistants-api-beta-deprecation-august-26-2026-sunset/1354666)). Лицензии дрейфуют к source-available: n8n SUL, Agent Server LangGraph под Elastic-2.0 с ключом лицензии ([n8n LICENSE](https://github.com/n8n-io/n8n/blob/master/LICENSE.md), [PyPI langgraph-api](https://pypi.org/pypi/langgraph-api/json)).

В шорт-листе отчёта то же самое в миниатюре. Заброшены или заглохли: langchainrb, fast-mcp, AI-Researcher, Open Deep Research (архив), altrr2, все Ruby-гемы Директа и Метрики. Держатся на одном человеке: yamcp, vtka, Ask Ads, ядро RubyLLM, ActiveAgent (плюс ИИ-коммиты), `b24gosdk` двухмесячного возраста. Legacy-зависимость: прогноз Live 4 без замены в v5. **Предложение:** недельный цикл — явный конечный автомат в своей БД; промпты, схемы инструментов и правила стоп-факторов — в версионируемых файлах, а не во фреймворк-специфичных конструкциях; интеграции — через стабильные протоколы (OpenAI-совместимый HTTP, прямой REST, MCP только как адаптер); критичные сторонние MCP — форк с фиксацией версии; пороги для зависимостей: нет коммитов больше 6 месяцев или архив — отказ, меньше 2–3 активных мейнтейнеров — только для заменяемых частей, OSI-лицензия для ядра, пересмотр раз в квартал; для каждого внешнего компонента — план выхода. **Плюсы:** система переживает чужие миграции. **Минусы:** больше своего кода и дисциплины.

### Юридические риски smoke-теста: 152-ФЗ отсекает зарубежные формы и SaaS

С 1 июля 2025 года при сборе персональных данных граждан РФ запрещено использовать базы за пределами РФ; с 1 сентября 2025 года согласие оформляется отдельным документом; за неподачу уведомления в Роскомнадзор наказывают с 30 мая 2025 года (по сниппету поиска) ([Delret](https://storage.delret.ru/lt-in-focus/lt-in-focus-lokalizaciya-personalnyh-dannyh.pdf), [Гарант](https://www.garant.ru/article/1862510/), [Харант](https://harant.ru/blog/drugoe/kto-i-kogda-obyazan-uvedomit-roskomnadzor-ob-obrabotke-personalnyh-dannyh/)). Штрафы за нарушение локализации для юрлиц и ИП — 1–6 млн ₽, при повторе — 6–18 млн ₽ (по сниппету поиска, сверить с КоАП) ([vitvet](https://vitvet.com/articles/koap/sostavy/shtraf-152-fz-2026-tablitsa/)). Это ещё один довод против зарубежных конструкторов и «бизнеса под ключ»: формы, база лидов и платежи должны жить в РФ. Маркировка рекламы обязательна с 1 сентября 2022 года; в Директе erid присваивается автоматически, если заполнены данные рекламодателя (по сниппету поиска, официальная справка не открыта) ([Toolfox](https://toolfox.ru/services/ord-markirovka-reklamy/markirovka-yandex-direct)), а другие каналы придётся маркировать вручную через ОРД. По ст. 26.1 ЗоЗПП покупатель вправе отказаться от предоплаченного товара до передачи, деньги возвращаются за 10 дней (по сниппету поиска) ([Харант](https://harant.ru/blog/zashchita-prav-potrebitelej/prodazha-tovara-distanczionnym-sposobom/)). Позиция модерации Директа по рекламе предзаказа несуществующего товара не найдена. **Предложение:** юридический гейт перед GO, который утверждает человек: уведомление в РКН подано, политика ПДн и отдельное согласие есть, форма пишет в базу в РФ, данные рекламодателя в Директе заполнены и erid на месте, оферта предзаказа с датой и безусловным возвратом опубликована, чеки по 54-ФЗ настроены; каналы smoke-теста на старте — только Директ. **Плюсы:** закрывает известные штрафы. **Минусы:** добавляет дни до первого теста и требует разовой проверки юристом.

## Резюме

Готовое на рынке — это инфраструктура: оболочка совета, рантайм агентов, API Яндекса, открытые данные, платежи и шаблоны. То, что делает «компанию» компанией — отсев, экономика, турнир и обращение с деньгами, — никто не продаёт. Polsia показывает цену пропуска этого слоя: по словам её основателя в пересказе конкурента (не проверено), лишь около 10% компаний на платформе заработали хотя бы доллар. Значит, своя часть кода — не издержка, а конкурентное ядро основателя.

**Предложение по порядку работ.** Сначала — доступы и проверки 1–5 из списка выше. Затем ядро на Rails: RubyLLM, `mcp`, Solid Queue, тонкие клиенты Яндекса, рублёвый реестр и шлюз трат. Paperclip — параллельным пилотом на 1–2 цикла как UI совета, без денег. Первый smoke-test — на мелкой ступени: лендинг из AstroWind (или вручную через ИИ-помощник Директа) и холд ЮKassa. **Плюс:** деньги и данные под контролем с первого дня. **Минус:** первые циклы медленнее «одной кнопки» — которой для РФ всё равно нет.
