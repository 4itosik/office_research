# MVP «LLM-компании» на одном Claude Code — ТЗ для разработки

Дата: 2026-10-12. Статус: ТЗ для запуска разработки. Основа — [первый отчёт](ready-made-office.md) (готовые решения по слоям) и [второй отчёт](claude-code-harness.md) (компания на примитивах Claude Code). Метрики внешних проектов — на 2026-10-09.

> **Как читать.** «Не проверено» — нет подтверждения первичным источником. «По сниппету поиска» — факт подтверждён только сводкой поисковой выдачи. «Предложение» — проектное решение этого ТЗ. «Оценка» и «допущение» — прогнозы и стартовые значения без замеров. «[совет]» — параметр, который утверждает человек до запуска. Раздел 19 — как отдать это ТЗ в разработку.

## 0. Коротко

- **Принцип: Claude думает, человек платит.** Claude Code ищет идеи, фильтрует, собирает данные, считает экономику, проводит турнир, пишет пакет совета, лендинг и план кампании, следит за метриками. Все денежные действия человек делает руками в кабинетах Директа и ЮKassa.
- **«Только Claude Code»** — нет своего бэкенда, БД, сервера и стороннего оркестратора. Компания — git-репозиторий: роли — субагенты, стадии — скиллы-команды, формулы — скрипты, данные — источники только на чтение, состояние и аудит — файлы в git.
- **Почему без шлюза трат.** У агентов нет ни одного токена с правом записи в Директ или ЮKassa. Тратить нечем, поэтому защищать нечего.
- **Цель:** два сухих цикла до пакета совета и первый smoke-test с реальной рекламой примерно за 3 недели (оценка).
- **LLM:** $13–27 в неделю по API-тарифам Claude (оценка второго отчёта).
- **Главный риск:** доступ к Claude Code. В его системных требованиях указано «Location: Anthropic supported countries» ([setup](https://code.claude.com/docs/en/setup)). Страховка — переносимые скиллы и путь в гибридный вариант (раздел 18).

## 1. Рамка MVP

### 1.1. Что входит

- Недельный цикл: скаут → стоп-фильтр → данные → экономика → турнир → пакет совета → лендинг → план кампании → ежедневный мониторинг → ретро.
- Два гейта совета: решение GO по идее и каждая ступень лестницы бюджета.
- Аудит: каждый вызов инструмента и каждое решение — в git.

### 1.2. Что не входит

- Свой сервер, БД, шлюз трат, Telegram-бот.
- Автоматическое управление кампаниями, ставками и бюджетами.
- Холд ЮKassa (двухстадийный платёж). Для него нужен код с секретным ключом магазина.
- Запуск цикла по расписанию без человека.
- Российские модели, Paperclip, другие harness.
- Загрузка офлайн-конверсий в Метрику агентом (нужен токен с правом записи).

### 1.3. Допустимые зависимости

Расширения Claude Code (скиллы, субагенты, хуки, MCP-серверы), Python-скрипты в репозитории, статический лендинг, облачное хранилище для статики, кабинеты Директа, Метрики и ЮKassa под управлением человека.

## 2. Недельный цикл

| # | Стадия | Команда | Роль (модель) | Вход | Выход |
|---|---|---|---|---|---|
| 1 | Старт недели | `/cycle` | director (Opus 5.5) | реестр идей, уроки | `cycles/<неделя>/manifest.json` |
| 2 | Скаут | `/scout` | scout (Sonnet 5.5) | устав, реестр, уроки, ручные сигналы | `ideas.json`, ~50 карточек |
| 3 | Стоп-фильтр | `/filter` | analyst (Haiku 5.5 + скрипт) | `ideas.json`, RFSD | `filtered.json`, 10–15 идей + отказы с причинами |
| 4 | Данные | `/data` | analyst (Sonnet 5.5) | `filtered.json` | `market.json`: частотность, прогноз CPC |
| 5 | Экономика | `/economics` | analyst + скрипт | `market.json` | `economics.json`, 8–12 финалистов |
| 6 | Турнир | `/tournament` | judge (Opus 5.5) + скрипт | финалисты | `ranking.json` с протоколом матчей |
| 7 | Пакет совета | `/board-pack` | director | артефакты 2–6 | `board-pack.md`, шаблон `decision.md` → **гейт 1** |
| 8 | Лендинг | `/landing` | marketer (Sonnet 5.5) | `decision.md` с GO | собранный лендинг, URL после подтверждения |
| 9 | План кампании | `/smoke-plan` | marketer | `decision.md`, `market.json` | `smoke/plan.md` + таблица для Директа |
| 10 | Мониторинг | `/monitor` | analyst (Haiku 5.5) | план, решение, Метрика, ЮKassa | `smoke/daily/<дата>.md` → **гейт 2** (человек) |
| 11 | Ретро | `/retro` | director | всё за неделю | `retro.md`, реестр, `memory-bank/` |

`/cycle` последовательно запускает стадии 2–7 и останавливается после пакета совета. Каждая стадия работает в своём субагенте, обмен — только через файлы. Стадии 8–11 запускает человек после GO.

**Устав (`CLAUDE.md`) обязан содержать:** миссию и сегменты; роли и их границы; стоп-факторы со ссылкой на `references/stop-factors.md`; правило «агенты не создают, не меняют и не оплачивают ничего в Директе и ЮKassa»; правило «формулы и пороги — только в `scripts/`»; правило «каждая цифра в пакете совета ссылается на артефакт стадии». Текст устава — контекст, а не гарантия: «context, not enforced configuration» ([memory](https://code.claude.com/docs/en/memory)). Гарантии дают права, токены и человек (раздел 9).

## 5. Роли (субагенты)

| Роль | Модель | Инструменты | Нельзя | Выход |
|---|---|---|---|---|
| director | Opus 5.5 | `Agent(scout, analyst, marketer, judge)`, Read, Grep, Write в `cycles/` | MCP ЮKassa, публикация, WebSearch | `board-pack.md`, `retro.md` |
| scout | Sonnet 5.5 | WebSearch, WebFetch, Read, Write в `cycles/<неделя>/`, `scripts/registry.py` | любые MCP | `ideas.json` |
| analyst | Sonnet 5.5; Haiku 5.5 на фильтр и мониторинг | Read, `scripts/*`, скиллы Вордстата и Метрики, yamcp (report), MCP ЮKassa — только чтение | создание и изменение чего-либо во внешних системах | `filtered.json`, `market.json`, `economics.json`, `smoke/daily/*` |
| marketer | Sonnet 5.5 | Read, Write в `landing/` и `cycles/<неделя>/smoke/`, сборка лендинга | публикация и создание ссылки ЮKassa без подтверждения | контент лендинга, `smoke/plan.md` |
| judge | Opus 5.5 | Read (только карточки пары) | всё остальное | вердикт матча в JSON |

- Директор работает как агент главной сессии: `claude --agent director`. Список порождаемых ролей `Agent(...)` действует только у агента главной сессии ([sub-agents](https://code.claude.com/docs/en/sub-agents#restrict-which-subagents-can-be-spawned)).
- Ограничения субагентов: не видят историю диалога, до 20 одновременно, вложенность до 3 уровней ([sub-agents](https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields)).
- Судья в Claude Code может быть только моделью Claude: «the workers are Claude sessions» ([agents](https://code.claude.com/docs/en/agents)). Смещение судьи к текстам своей семьи моделей снимается частично — перестановками и нормализацией карточек (раздел 7). Полностью — только судьёй другой семьи после MVP.

Эскиз frontmatter (поля сверить с [sub-agents](https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields)):

```yaml
---
name: scout
description: Ищет и описывает идеи бизнеса по уставу. Запускается только из /scout.
tools: WebSearch, WebFetch, Read, Write, Bash
model: sonnet
maxTurns: 60
---
```

## 6. Скиллы-команды

Общие правила (предложение):

- У всех стадийных скиллов `disable-model-invocation: true`: стадию запускает человек или `/cycle`, а не совпадение описания ([skills](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill)). Поле специфично для Claude Code; при переезде в другой harness его убирают.
- Скрипты разрешаются точечно: `allowed-tools: Bash(${CLAUDE_SKILL_DIR}/scripts/… *)` ([skills](https://code.claude.com/docs/en/skills#available-string-substitutions)). Таймаут Bash — 2 минуты: скрипты обязаны укладываться.
- Тело скилла — короткое. После компакции контекста от каждого скилла остаются первые 5 000 токенов, от всех вместе — 25 000 ([skills](https://code.claude.com/docs/en/skills#skill-content-lifecycle)). Справочники — в `references/`.
- Каждая стадия: проверяет, нет ли уже валидного артефакта; пишет артефакт по схеме; прогоняет `validate.py`; обновляет `manifest.json`; делает коммит `cycle(<неделя>): <стадия>`.

### `/cycle`
- **Вход:** неделя (по умолчанию текущая ISO-неделя).
- **Шаги:** создать `cycles/<неделя>/` и `manifest.json` → `/scout` → `/filter` → `/data` → `/economics` → `/tournament` → `/board-pack`. При ошибке стадии — остановка с отчётом, без повтора.
- **Приёмка:** повторный запуск не пересоздаёт готовые стадии; в конце — сообщение «ждём decision.md».

### `/scout`
- **Вход:** устав, `registry.csv`, `memory-bank/lessons.md`, `inputs/<неделя>/signals.md` (если есть).
- **Шаги:** 70–80 сырых идей из веб-сигналов (запросы «где заказать…», «как найти…», жалобы и отзывы, ручные сигналы); дедупликация через `registry.py`; 50 карточек по схеме.
- **Выход:** `ideas.json`.
- **Приёмка:** 50 карточек; у каждой не меньше 2 URL-источников; ноль повторов с реестром за 12 недель; все обязательные поля схемы.

### `/filter`
- **Вход:** `ideas.json`, `references/stop-factors.md`, RFSD.
- **Шаги:** жёсткие стоп-факторы по чек-листу; концентрация ниши через `concentration.py`; мультипликативный «пол»: любой фатальный фактор — отказ.
- **Выход:** `filtered.json` — 10–15 прошедших и все отказы с правилом и доказательством.
- **Приёмка:** у каждого отказа есть `rule_id` и ссылка; пороги взяты из `references/stop-factors.md`, а не из ответа модели.

Стартовые стоп-факторы (допущение, утверждает совет):
- лицензируемая или регулируемая деятельность (медицина, финансы, алкоголь, образование с лицензией и т.п.);
- категории, для которых Директ требует документы или ограничивает рекламу;
- нужен склад, производство или запасы до первой продажи;
- монополист: CR1 ≥ 50% или HHI ≥ 2 500 по ОКВЭД ниши [совет];
- спрос ниже порога частотности по главным фразам [совет]. Ориентир: Директ присваивает группам статус «Мало показов» и останавливает их, числового порога Яндекс не публикует ([Яндекс](https://yandex.ru/adv/news/malo-pokazov-novyy-status-dlya-grupp-obyavleniy), по сниппету поиска).

### `/data`
- **Вход:** `filtered.json`.
- **Шаги:** 5–10 фраз на идею → Вордстат (`topRequests`, `dynamics`) через скилл `yandex-wordstat`; прогноз бюджета Live 4 через yamcp (`direct_forecast`, `action="create"`) → CPC, клики, бюджет. Если прогноза нет — явная пометка, ручной прогноз в кабинете делает человек.
- **Выход:** `market.json`.
- **Приёмка:** у каждой идеи частотность по фразам и прогноз CPC либо пометка «нет прогноза»; расход квот записан в `manifest.json`.

### `/economics`
- **Вход:** `market.json`, гипотезы цены, маржи, срока жизни и конверсии из карточек.
- **Шаги:** `max_cpc.py` для каждой идеи: цель и безубыточность; чувствительность к конверсии ×0,5 и ×1,5; вердикт — прогнозный CPC не выше max CPC (цель) при базовой конверсии.
- **Выход:** `economics.json`, 8–12 финалистов.
- **Приёмка:** все числа посчитаны скриптом; в артефакте записаны входы и версия скрипта.

### `/tournament`
- **Вход:** финалисты. Карточки приводятся к одному шаблону и одной длине.
- **Шаги:** `swiss.py` строит пары тура (seed — номер недели); judge судит каждую пару дважды, A–B и B–A, по рубрике; расхождение — 0,5 очка обоим; 4–5 туров.
- **Выход:** `ranking.json`: очки, дополнительный показатель Бухгольца, протокол всех матчей.
- **Приёмка:** каждая пара судилась в обоих порядках; протокол воспроизводим по seed.

Зачем перестановки: в MT-Bench GPT-4 согласован с собой после перестановки ответов в 65,0% случаев, Claude-v1 — в 23,8% ([arXiv 2306.05685](https://arxiv.org/pdf/2306.05685), по сниппету поиска).

### `/board-pack`
- **Вход:** артефакты стадий 2–6.
- **Выход:** `board-pack.md` по шаблону и `decision.md` со статусом `PENDING`. Содержание пакета: топ-3 (суть, частотность, прогноз CPC, max CPC цель и безубыточность, концентрация, риски); предложение ступени 1 (бюджет, дни, порог гипотезы); варианты домена; юридический чек-лист; приложение — отсеянные идеи с причинами; стоимость цикла в токенах и долларах.
- **Приёмка:** каждая цифра ссылается на артефакт; на чтение уходит не больше часа.

### `/landing`
- **Гейт:** `gate_check.py` пропускает только при `status: GO` и заполненных `approved_by`, `approved_at`.
- **Шаги:** `content/<idea_id>.json` по схеме секций (оффер, проблема, решение, цена, «предзаказ» с датой старта, FAQ, условия возврата, футер с ФИО, ОГРНИП, ИНН и контактами) → сборка AstroWind → проверка по `moderation-checklist.md` → публикация только после подтверждения человека.
- **Выход:** URL; цели Метрики `checkout_click` и `pay_click` размечены.
- **Приёмка:** чек-лист пройден; нет «в наличии»; есть дата старта и условия возврата; формы сбора данных нет.

### `/smoke-plan`
- **Гейт:** как у `/landing`.
- **Шаги:** фразы с частотностью, минус-слова, 3–5 объявлений, гео, расписание, дневной бюджет = бюджет ступени ÷ дни, UTM; пороги гипотезы и правила остановки — из `decision.md`.
- **Выход:** `smoke/plan.md` и таблица для ручного заведения кампании.
- **Приёмка:** дневной бюджет × дни ≤ бюджет ступени; пороги совпадают с `decision.md`.

### `/monitor`
- **Вход:** `smoke/plan.md`, `decision.md`.
- **Шаги:** Метрика — визиты, цели, клики и расходы Директа (параметр `direct_client_logins`; расходы без НДС) ([direct-clicks](https://yandex.ru/dev/metrika/ru/stat/direct-clicks), по сниппету поиска); ЮKassa — оплаты через MCP только на чтение; расчёт фактического CPC, конверсий клик → цель и клик → оплата; сравнение с порогами.
- **Выход:** `smoke/daily/<дата>.md` с рекомендацией: продолжать, остановить или просить следующую ступень.
- **Приёмка:** ни одного вызова на запись; рекомендация опирается только на пороги из `decision.md`.

### `/retro`
- **Выход:** `retro.md` (что сработало, что нет, предложения совету по порогам); статусы в `registry.csv`; новые уроки в `memory-bank/lessons.md`.

## 7. Скрипты (детерминированная логика)

Все скрипты — Python, с тестами `pytest`, без сетевых вызовов, кроме чтения локальных файлов.

**`validate.py`** — проверка артефакта по JSON Schema из `schemas/`; ненулевой код выхода при ошибке.

**`gate_check.py`** — читает YAML front-matter `decision.md` и возвращает 0 только при `status: GO` с заполненными `approved_by` и `approved_at`.

**`registry.py`** — добавление идей, поиск повторов (нормализованное название плюс нечёткое сравнение), смена статусов: `new`, `rejected`, `finalist`, `tested`, `go`, `killed`.

**`concentration.py`** — DuckDB по Parquet RFSD. Вход: префикс ОКВЭД (2, 4 или 6 знаков), регион (необязательно), год (последний доступный). Выход: число фирм, суммарная выручка (`line_2110`), CR1, CR3, HHI (сумма квадратов долей × 10 000), топ-10. Колонки `okved`, `okved_section`, `inn`, `ogrn`, `region`, `line_2110` есть в базе ([README](https://raw.githubusercontent.com/irlcode/RFSD/main/README.md), [use case](https://raw.githubusercontent.com/irlcode/RFSD/main/use_cases/tfp.md)). Ограничения учесть в выводе: отчётность неконсолидированная, ИП нет, основной ОКВЭД часто не совпадает с реальным бизнесом — концентрация занижена. Единицы `line_2110` — проверить. Лицензия CC BY 4.0 требует атрибуции.

**`max_cpc.py`** — исправленная формула из [первого отчёта](ready-made-office.md), раздел «Формула основателя завышает max CPC»:
- маржинальный LTV = цена × валовая маржа × срок жизни (для разовой покупки — × число повторных покупок);
- max CPC (цель) = маржинальный LTV × CR(клик → оплата) ÷ 3;
- max CPC (безубыточность) = маржинальный LTV × CR(клик → оплата);
- маржа — после себестоимости и комиссии эквайринга (3,5% по картам при обороте до 3 млн ₽ в месяц, [тарифы](https://yookassa.ru/docs/support/payments/fees), по сниппету поиска);
- если тест меряет заявки, CR(клик → оплата) = CR(клик → заявка) × CR(заявка → оплата).

Обязательный тест: цена 3 000 ₽ в месяц, маржа 40%, срок жизни 6 месяцев, CR 2% → цель 48 ₽, безубыточность 144 ₽; формула без маржи дала бы 120 ₽.

**`swiss.py`** — швейцарская система: пары внутри групп с равными очками, без повторных пар, при нечётном числе — свободный тур; seed из номера недели; сведение вердиктов двух порядков (расхождение — 0,5); дополнительный показатель Бухгольца при равенстве очков; выход — протокол и рейтинг. Тесты: детерминизм по seed, отсутствие повторных пар.

## 9. Доступы, права и аудит

### 9.1. Токены

| Переменная | Что даёт | Кто использует | Чего нет и не будет |
|---|---|---|---|
| `YC_API_KEY`, `YC_FOLDER_ID` | Вордстат (Search API v2) | analyst | — |
| `YD_TOKEN_READONLY` | Директ от представителя «только чтение»: прогноз Live 4 (проверить), статистика | analyst через yamcp | токен основного логина Директа |
| `METRIKA_TOKEN` | Метрика, только `metrika:read` | analyst | право записи, офлайн-конверсии |
| `YOOKASSA_MCP_TOKEN` | MCP ЮKassa: сначала тестовый магазин, потом боевой | analyst (чтение), marketer (создание ссылки — с подтверждением) | секретный ключ магазина |
| `ANTHROPIC_API_KEY` | LLM для запусков без человека | Claude Code | — |

- Секреты — в `.env` вне git. Скиллы polyakov хранят токены в `config/.env` внутри каталога скилла ([polyakov](https://github.com/artwist-polyakov/polyakov-claude-skills)) — добавить в `.gitignore`.
- Представитель «только чтение» и через API может только получать данные (по сниппету поиска): «если агентство предоставило клиенту доступ в веб-интерфейс только на чтение, то и через API представитель клиента сможет только получать данные» ([доступ](https://yandex.ru/dev/direct/doc/ru/concepts/access)). Работает ли под этой ролью прогноз Live 4 — не проверено (раздел 17).
- Скилл `yandex-direct` из polyakov не подключать: он умеет `--apply`, и в нём написано «Если пользователь уже поручил конкретное действие, повторное подтверждение не требуется» ([SKILL.md](https://github.com/artwist-polyakov/polyakov-claude-skills/blob/main/plugins/yandex-direct/skills/yandex-direct/SKILL.md)).

### 9.2. Права Claude Code

Эскиз `.claude/settings.json`. Синтаксис правил и имена MCP-инструментов сверить с [permissions](https://code.claude.com/docs/en/permissions) после подключения серверов.

```json
{
  "permissions": {
    "deny": ["Bash(*--apply*)", "Read(./.env)", "Read(./**/config/.env)"],
    "ask": ["Bash(*publish*)", "mcp__yookassa"]
  },
  "hooks": {
    "PostToolUse": [
      {"matcher": "*", "hooks": [{"type": "command", "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/audit.sh"}]}
    ]
  }
}
```

- `ask` на весь MCP ЮKassa — проще всего. После подключения сузить: чтение разрешить, создание ссылки оставить с подтверждением.
- Опционально — файловые managed settings под root (`/etc/claude-code/managed-settings.json`) с теми же deny и `disableBypassPermissionsMode`: агент их не перепишет ([managed-settings](https://code.claude.com/docs/en/managed-settings)).

### 9.3. Аудит

- `audit.sh` читает JSON события со stdin и дописывает строку с меткой времени в `cycles/<текущая неделя>/audit.jsonl`. Всегда завершается с кодом 0.
- Хук — журнал, а не защита. По умолчанию хуки пропускают действие при exit 1, неверном пути, таймауте и ошибке HTTP; опция `onFailure: "block"` появилась в v2.1.295 и описана только в changelog ([hooks](https://code.claude.com/docs/en/hooks#exit-code-output), [changelog](https://code.claude.com/docs/en/changelog#2-1-295)).
- Транскрипты Claude Code удаляются через 30 дней ([claude-directory](https://code.claude.com/docs/en/claude-directory)). Всё, что важно, — в артефактах стадий и коммитах.
- Git — журнал решений: `decision.md` коммитит только человек.

## 11. Smoke-test: лестница и юридический минимум

### 11.1. Лестница

- **Ступень 0.** До запуска в `decision.md` записана гипотеза: «не меньше X% из Y сделают Z» [совет].
- **Ступень 1, fake door.** Лендинг с ценой и кнопкой «Оформить предзаказ». Клик засчитывается как цель Метрики, дальше экран «скоро запуск» с датой. Формы нет, персональные данные не собираются. Бюджет — малый [совет].
- **Ступень 2, предоплата.** Кнопка ведёт на многоразовый счёт ЮKassa: одна ссылка для многих покупателей по фиксированной цене, создаётся в кабинете без кода (по сниппету поиска) ([счета](https://yookassa.ru/docs/support/merchant/payments/invoicing), [многоразовый счёт](https://vc.ru/yoomoney/2278021-bot-yookassa-dlya-vystavleniya-schetov-v-messendzhere-max)). Если запуск не состоится — возврат вручную из кабинета. Холда в счёте нет (допущение). Комиссия при возврате не возвращается, кроме возврата в день платежа (первый отчёт, слой 5).
- **Переход на следующую ступень** — только если фактический CPC не выше max CPC (цель) и порог гипотезы выполнен. Решение и бюджет — человек.

### 11.2. Юридический чек-лист перед GO

Синтез отчётов, не юридическая консультация.

- ИП, профиль Яндекс Бизнеса с реквизитами — сведения о продавце в объявлениях о дистанционной продаже ([требования](https://yandex.ru/support/direct/ru/moderation/categories/goods-and-services), по сниппету поиска).
- Маркировку (erid) Директ ставит сам, если заполнены данные рекламодателя (по сниппету поиска, первый отчёт). Других каналов в MVP нет.
- Футер: ФИО, ОГРНИП, ИНН, контакты. Оферта предзаказа: срок передачи и условия возврата. Требование о возврате предоплаты удовлетворяется за 10 дней (ст. 23.1 ЗоЗПП, по сниппету поиска).
- Слово «предзаказ» и дата старта — в объявлении и на лендинге. Никаких «в наличии» и выдуманных отзывов. Реклама недостоверна, если неверно сообщает о возможности приобретения в определённый срок (ст. 5 ч. 3 п. 3 38-ФЗ, по сниппету поиска).
- Заглушки «сайт в разработке» и редиректы Директ запрещает ([правила](https://yandex.ru/support/direct/en/moderation/ad-rules), по сниппету поиска).
- Чеки по 54-ФЗ — «Чеки от ЮKassa»; при полной предоплате нужен чек предоплаты, затем чек полного расчёта (по сниппету поиска, первый отчёт).
- 152-ФЗ: без форм персональные данные не собираются. С 1 июля 2025 года сбор данных россиян в зарубежные базы запрещён (по сниппету поиска, первый отчёт). Нужно ли уведомление о cookie для Метрики — не проверено.

## 12. Регламент человека на неделю (оценка времени)

- **Понедельник:** `claude --agent director` → `/cycle`. Чтение пакета совета — 30–60 минут. Заполнить и закоммитить `decision.md`.
- **Вторник:** `/landing` и `/smoke-plan`. Подтвердить публикацию лендинга. Завести кампанию в Директе по таблице — 30–60 минут. Создать многоразовый счёт ЮKassa — 10 минут.
- **Среда–воскресенье:** `/monitor` раз в день. Можно через `/loop` в открытой сессии: задачи истекают через 7 дней ([scheduled-tasks](https://code.claude.com/docs/en/scheduled-tasks)), этого хватает на неделю теста. Решения «стоп» или «следующая ступень» и изменения бюджета — вручную в кабинете.
- **Воскресенье:** `/retro`, утвердить предложения по порогам.

- Каждая цифра пакета совета прослеживается до артефакта и источника.

## 15. Стоимость (оценка)

- **LLM:** $13–27 в неделю, $59–115 в месяц по API-тарифам; в дорогом сценарии с ретраями — до $81 в неделю (второй отчёт, «Стоимость недельного цикла»). Цены за миллион токенов на вход и выход: Haiku 5.5 — $0,10 и $0,50, Sonnet 5.5 — $2 и $10, Opus 5.5 — $4 и $20, Fable 5.1 — $10 и $50 ([pricing](https://platform.claude.com/docs/en/about-claude/pricing)).
- **Вордстат:** около 2 ₽ в неделю при ~100 запросах.
- **ЮKassa:** 3,5% с оплат картами.
- **Реклама:** по ступеням [совет].
- **Хостинг статики:** копейки (не оценивалось).

Предохранители: лимит workspace Console; `--max-budget-usd` на стадию при запусках `-p` — это клиентская оценка, «Spend can pass the cap, so leave headroom» ([cli-reference](https://code.claude.com/docs/en/cli-reference)); `deniedModels` для Fable в `-p`, где она списывается без запроса ([model-config](https://code.claude.com/docs/en/model-config)).

## 16. Риски и меры

| Риск | Мера |
|---|---|
| Доступ к Claude Code: «Location: Anthropic supported countries» ([setup](https://code.claude.com/docs/en/setup)); сообщения о блокировках российских аккаунтов в 2026 году (по сниппету поиска, второй отчёт) | Всё состояние — в git; скиллы — максимально по открытому стандарту; путь в вариант B (раздел 18) |
| Ошибки модели в расчётах и данных | Формулы и пороги — только в скриптах с тестами; схемы; у каждой цифры — источник |
| Prompt injection из веб-страниц | У агентов нет пишущих токенов; скаут без MCP; публикация и ЮKassa — с подтверждением |
| Смещение судьи своей семьи моделей | Обе перестановки, одинаковые карточки, ничьи; позже — судья другой семьи |
| Хуки ненадёжны как гейт | Хуки только для аудита; гейты — токены и человек |
| Цепочка поставок скиллов и MCP | Форк, закреплённый коммит, чтение всех скриптов, без автообновления |
| Закрытие Live 4 | Запасной путь — ручной прогноз в кабинете Директа |
| Юридические риски предзаказа | Чек-лист раздела 11.2; разовая консультация юриста до первой ступени 2 |
| Время человека | 2–4 часа в неделю (оценка); если больше — переход к варианту B |

## 17. Открытые вопросы — проверить в первую неделю

1. Работает ли прогноз Live 4 под токеном представителя «только чтение». Если нет — отдельный пустой аккаунт Директа без денег только для прогнозов (предложение; доступ к API требует хотя бы черновика кампании).
2. Отдаёт ли API Метрики клики и расходы Директа этому логину.
3. ЮKassa: оплата по многоразовому счёту со стороннего лендинга; нужна ли модерация каждого лендинга; можно ли один магазин на несколько лендингов; когда формируется чек; есть ли холд у счетов.
4. Самозанятость в ЮKassa: источники противоречат друг другу — уточнить у менеджера (второй отчёт).
5. Единицы `line_2110` и семантика `okved` в RFSD; HHI на трёх известных нишах.
6. Как модерация Директа принимает лендинг предзаказа с fake door.
7. Реальная стоимость цикла в токенах после первого сухого прогона.
8. Поведение `disable-model-invocation`, правил `deny`/`ask` и хука аудита в вашей версии Claude Code.

## 18. После MVP: путь в гибридный вариант

Переход по [второму отчёту](claude-code-harness.md), вариант B: роли и регламенты — переносимые артефакты (скиллы по стандарту Agent Skills с 6 полями, роли в одном YAML с генерацией под разные harness, хуки — отдельные скрипты); деньги, состояние цикла, расписание, журнал решений и шлюз трат — в своём ядре; исполнитель в продакшене — открытый harness на модели, доступной из РФ, по результатам eval.

Триггеры перехода:
- блокировка аккаунта или изменение условий Anthropic;
- цикл должен работать без человека за клавиатурой;
- больше одного smoke-теста одновременно;
- нужен холд ЮKassa или автоматическое управление бюджетом;
- ручная работа человека стабильно выше 4 часов в неделю.

## 19. Как запустить разработку

### Вариант 1. Обычная сессия Claude Code

1. Создать репозиторий компании, например `llm-company`.
2. Положить этот файл как `docs/mvp-spec.md`. Оба отчёта и заметки — в `docs/research/`, чтобы ссылки работали.
3. Открыть Claude Code в репозитории и отправить стартовый промпт.

```markdown
# Задача
Собери MVP «LLM-компании» строго по спецификации `docs/mvp-spec.md`.

# Правила
- Работай по фазам из раздела 13. Одна фаза — одна ветка и один PR.
- Перед фазой перечитай её задачи и критерии приёмки. После фазы — тесты и проверка критериев.
- Формулы и пороги — только в `scripts/` с тестами. Не считай числа в тексте.
- Токены — только из таблицы раздела 9.1. Ни одного токена с правом записи в Директ или ЮKassa. Секреты — в `.env`, не в git.
- Сторонние скиллы и MCP — только форк или закреплённый коммит; прочитай все их скрипты до подключения.
- Публикация лендинга и создание ссылок ЮKassa — только с моим подтверждением.
- Если в спецификации пробел или противоречие — остановись и спроси.

# Начни с фазы 1
Каркас репозитория, схемы, скрипты с тестами, роли, `settings.json` и хук аудита.
```

### Вариант 2. Через OpenSpec

1. В новом репозитории инициализировать OpenSpec.
2. `/opsx:propose` с описанием «реализовать фазу 1 из `docs/mvp-spec.md`».
3. `/opsx:run` — план-ревью, реализация, код-ревью, исправления, архив.
4. Каждая фаза раздела 13 — отдельный change.
