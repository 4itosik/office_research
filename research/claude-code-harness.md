# Claude Code потянет мозги компании, но не кассу

Строить компанию на скиллах, субагентах и командах можно, но только её «мозги»: роли, регламенты стадий и исследовательский конвейер. Деньги, состояние цикла между неделями, журнал решений совета и надёжное расписание примитивы Claude Code не держат. Продакшен-рантаймом из РФ Claude Code быть не должен: условия Anthropic не выполняются ни в одной конфигурации. Технически совпадение хорошее. Роли ложатся на субагентов с минимальными правами, директор — на агента главной сессии, SOP — на скиллы со скриптами, фан-аут 50 идей — на воркфлоу со схемами, устав — на CLAUDE.md и managed settings под root. Но защита работает на клиенте. Хуки при сбое по умолчанию пропускают действие, а опция `onFailure: "block"` появилась только в v2.1.295 и описана лишь в changelog ([changelog](https://code.claude.com/docs/en/changelog#2-1-295)). Одобрение в Claude Code — это решение о вызове инструмента, без суммы. Бюджеты — клиентская оценка в USD, и документация прямо пишет: не принимать по ним финансовых решений ([cost-tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)). Главное «но» — регион. В системных требованиях самого клиента записано «Location: Anthropic supported countries» ([setup](https://code.claude.com/docs/en/setup)), России в списке нет ([supported countries](https://www.anthropic.com/supported-countries)), и подмена модели на GigaChat через прокси этого не меняет. Рекомендация — вариант B (предложение): компания как репозиторий переносимых артефактов плюс своё ядро для денег, состояния, расписания и одобрений. Артефакты — скиллы по открытому стандарту Agent Skills, роли из одного источника, хуки-скрипты и свои MCP-серверы. Claude Code остаётся мастерской: в нём основатель пишет и проверяет эти артефакты. Продакшен-исполнитель — открытый harness (Goose или OpenCode) на модели, доступной из РФ, выбранный по eval; при такой дисциплине смена исполнителя занимает дни. Готовая экосистема закрывает Яндекс (polyakov-claude-skills) и маркетинговые методики, но не стоп-фильтр, экономику и турнир. Недельный цикл на моделях Claude стоил бы $13–27 по API-тарифам (оценка), так что цена токенов здесь — не главный риск.

> **Как читать.** «Не проверено» — нет подтверждения первичным источником. «По сниппету поиска» — факт подтверждён только сводкой поисковой выдачи, страница не открывалась. «По листингу GitHub» — заголовок issue со страницы поиска GitHub; это сообщения пользователей, Anthropic их не подтверждала. «Предложение» — собственный синтез или рекомендация отчёта. Прогнозы и допущения помечены словами «оценка» и «допущение». Зрелость функций указана так, как её помечает документация Claude Code: research preview, beta, experimental. **GA\*** — пометок нет, но и явного объявления GA нет (классификация заметок). Все метрики активности — на 2026-10-09. Версия Claude Code — v2.1.295 от 2026-10-08. Цены — в USD, как в первоисточниках. Отчёт продолжает [первый отчёт](ready-made-office.md): его выводы здесь не повторяются, а даются ссылкой на раздел. Подробные заметки и все источники — в [research/notes/claude-code-harness/](notes/claude-code-harness/): [c1 — примитивы](notes/claude-code-harness/c1-primitives.md), [c2 — работа без человека](notes/claude-code-harness/c2-unattended-ops.md), [c3 — экосистема](notes/claude-code-harness/c3-ecosystem.md), [c4 — РФ и переносимость](notes/claude-code-harness/c4-ru-viability-portability.md).

## Референс-архитектура: репозиторий хранит регламенты, ядро — деньги и состояние

Это предложение: синтез заметок c1, c2, c4 и [первого отчёта](ready-made-office.md). Принцип простой. Всё, что описывает работу ролей, лежит в git-репозитории в переносимом виде. Всё, что меняет деньги и статус цикла, живёт в ядре на Rails или Go (первый отчёт, разделы «Деньги и токены» и «Слой 6»). Harness — сменный исполнитель одной стадии.

### Раскладка: один источник ролей, генерация под каждый harness

```
company/                            git-репозиторий «компании» (предложение)
├── AGENTS.md                       устав: миссия, роли, стоп-факторы, правила совета
├── CLAUDE.md                       одна строка: @AGENTS.md (+ Claude-специфика, если нужна)
├── roles/                          единый источник ролей: промпт, скиллы, модель, лимиты, инструменты
│   ├── director.yaml
│   ├── scout.yaml
│   ├── analyst.yaml
│   ├── marketer.yaml
│   └── judge.yaml                  судья турнира (вызывается ядром, не harness)
├── .claude/
│   ├── skills/                     SOP стадий; frontmatter — только 6 полей стандарта
│   │   ├── scout-ideas/            SKILL.md, references/
│   │   ├── stop-filter/            SKILL.md, scripts/concentration.py
│   │   ├── collect-market-data/    SKILL.md
│   │   ├── unit-economics/         SKILL.md, scripts/max_cpc.py
│   │   ├── board-pack/             SKILL.md
│   │   └── smoke-test-plan/        SKILL.md
│   ├── agents/                     сгенерировано из roles/ для Claude Code

├── .agents/skills -> ../.claude/skills    для Goose и Codex
```

Почему так. Скиллы лежат в `.claude/skills`, потому что этот каталог читают напрямую OpenCode, Goose и Crush ([OpenCode](https://github.com/anomalyco/opencode/blob/dev/packages/web/src/content/docs/skills.mdx), [Goose](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/context-engineering/using-skills.md), [Crush](https://github.com/charmbracelet/crush/blob/main/README.md)). Устав — в `AGENTS.md`. Claude Code читает его, только если рядом нет `CLAUDE.md` ([memory](https://code.claude.com/docs/en/memory)), поэтому `CLAUDE.md` сводится к импорту `@AGENTS.md`; OpenCode берёт `CLAUDE.md` как запасной вариант ([rules.mdx](https://github.com/anomalyco/opencode/blob/dev/packages/web/src/content/docs/rules.mdx)). Роли описаны один раз в YAML. Из него генерируются файлы агентов под каждый harness, потому что поля различаются: в OpenCode это `permission` и `model: provider/model-id` ([agents.mdx](https://github.com/anomalyco/opencode/blob/dev/packages/web/src/content/docs/agents.mdx)), в Goose — рецепты ([subagents](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/context-engineering/subagents.mdx)). Хуки — скрипты с exit 2: ту же модель событий понимают Goose и Qwen Code ([goose hooks](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/context-engineering/hooks.md), [Qwen hooks](https://github.com/QwenLM/qwen-code/blob/main/docs/users/features/hooks.md)), для OpenCode нужна JS-обёртка на `tool.execute.before` ([plugins.mdx](https://github.com/anomalyco/opencode/blob/dev/packages/web/src/content/docs/plugins.mdx)).

Обёртка `run-stage` вызывает стадию одним из трёх способов. Для Claude Code шаблон из заметок c1:

```
claude --bare -p "<стадия>" --agents ./build/claude-agents.json \
  --mcp-config ./mcp/read.json --strict-mcp-config --settings ./build/settings.json \
  --permission-mode dontAsk --json-schema "$(cat schemas/<стадия>.json)" \
  --max-turns 40 --max-budget-usd 3 --output-format json
```

`--bare` отключает автообнаружение хуков, скиллов, MCP и CLAUDE.md, поэтому прогон воспроизводим; документация называет его «the recommended mode for scripted and SDK calls» ([headless](https://code.claude.com/docs/en/headless#start-faster-with-bare-mode)). `dontAsk` отклоняет всё, что потребовало бы запроса, — режим для «locked-down CI and scripts» ([permission-modes](https://code.claude.com/docs/en/permission-modes#allow-only-pre-approved-tools-with-dontask-mode)). Для открытых harness — `opencode run --format json` ([cli.mdx](https://github.com/anomalyco/opencode/blob/dev/packages/web/src/content/docs/cli.mdx)) или `goose run --recipe … --output-format json --max-turns` ([goose CLI](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/goose-cli-commands.md)). Результат стадии — JSON по схеме; ядро кладёт его в БД.

Туда же входят сборка и хостинг лендинга, платёжный сервис и вебхуки, мост «вебхук → офлайн-конверсия» в Метрику, хранилище аудита с алертами и хранилище секретов. Этот список совпадает с разделом 3 заметок c1 («что не покрывается примитивами») и с картой покрытия первого отчёта. Шлюз трат — единственный держатель write-токена Директа и секретного ключа ЮKassa; агенты получают только MCP-инструменты «предложить» (первый отчёт, «Деньги и токены»).

### Турнир: судья — прямой вызов из ядра, а не субагент

Здесь сходятся три источника. Первый отчёт предложил схему: Swiss на 4–5 раундов, каждый матч в двух порядках, ничья 0,5 при расхождении, судья из другого семейства моделей, карточки одинаковой длины (раздел «AI-Researcher: Swiss-турнир как образец»). Заметки c1 показывают ограничение Claude Code: «the workers are Claude sessions. To involve a different tool, expose it to Claude as an MCP server» ([agents](https://code.claude.com/docs/en/agents)). Значит, судья-субагент — всегда Claude. Opus в роли судьи при Sonnet-генераторе — та же семья, и смещение в пользу «своего» не снимается. Заметки c2 считают цену. 50 судейств на Opus 5.5 стоят $4,30 прямыми вызовами, $2,15 через Batch API со скидкой 50% и $8,05 субагентами Claude Code: накладные сессии почти удваивают цену (оценка c2; [pricing](https://platform.claude.com/docs/en/about-claude/pricing)).

**Сведение (предложение).** Сетка, перестановки и подсчёт (Swiss плюс Bradley–Terry) — детерминированный скрипт ядра. Судьи — прямые вызовы API без harness: два судьи разных семейств, оба порядка, при расхождении — 0,5. В РФ-контуре это пары вроде GigaChat и YandexGPT или open-weight модели. Batch API Anthropic — рычаг экономии только там, где Claude используется в рамках условий. В открытых harness разные модели по ролям есть и внутри: в OpenCode у каждого агента своя `model` ([agents.mdx](https://github.com/anomalyco/opencode/blob/dev/packages/web/src/content/docs/agents.mdx)), в Goose — `GOOSE_SUBAGENT_PROVIDER` ([subagents](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/context-engineering/subagents.mdx)). Но турниру harness не нужен. **Плюсы:** дешевле, повтор детерминирован, судья действительно из другого семейства. **Минусы:** качество российских моделей в роли судьи не проверено; калибровать на размеченном наборе прошлых недель.

### Топ-3: Яндекс, оргчарт ролей, библиотека маркетолога

**polyakov-claude-skills — единственная живая упаковка Яндекса под Claude Code.** 22 плагина на русском, из них пять — Яндекс: Директ, Wordstat, Метрика, Search API, Вебмастер; рядом `sourcecraft-publisher` для статики на SourceCraft Sites ([marketplace.json](https://github.com/artwist-polyakov/polyakov-claude-skills/blob/main/.claude-plugin/marketplace.json)). Wordstat ходит в Yandex Cloud Search API v2 и проверяет интент запроса веб-поиском до пометки «целевой» ([SKILL.md](https://github.com/artwist-polyakov/polyakov-claude-skills/blob/main/plugins/yandex-wordstat/skills/yandex-wordstat/SKILL.md)). Директ показывает план «было → станет», `--apply` выполняет правку и перечитывает объект, правки пишутся в `audit-log.jsonl` ([SKILL.md](https://github.com/artwist-polyakov/polyakov-claude-skills/blob/main/plugins/yandex-direct/skills/yandex-direct/SKILL.md), [writer.py](https://github.com/artwist-polyakov/polyakov-claude-skills/blob/main/plugins/yandex-direct/skills/yandex-direct/scripts/lib/writer.py)). Прогноза бюджета нет: методы Live 4 есть только в карте API ([API_MAP.md](https://github.com/artwist-polyakov/polyakov-claude-skills/blob/main/plugins/yandex-direct/skills/yandex-direct/references/API_MAP.md)). **Плюсы:** нативные API Яндекса, живой темп, MIT. **Минусы:** около 330 исполняемых скриптов; токены лежат в `config/.env` внутри каталога скилла; фраза «Если пользователь уже поручил конкретное действие, повторное подтверждение не требуется» противоречит гейту совета ([SKILL.md](https://github.com/artwist-polyakov/polyakov-claude-skills/blob/main/plugins/yandex-direct/skills/yandex-direct/SKILL.md)); в community-маркетплейсе Anthropic пакета нет, автоматическое сканирование он не проходил. **Как брать:** форк, SHA в своём `marketplace.json`, у агентов — токен Директа без права записи, прогноз Live 4 — дописать по образцу yamcp (первый отчёт, слой 4).

**anthropics/knowledge-work-plugins — официальный «оргчарт» ролей.** «Every component is file-based — markdown and JSON, no code» ([README](https://github.com/anthropics/knowledge-work-plugins/blob/main/README.md)). Для компании полезны product-management (write-spec → карточка идеи, stakeholder-update → отчёт совету), data и marketing. Плагин small-business — лучший официальный образец гейта: «nothing sends, posts, or gets paid without your say-so» ([README](https://github.com/anthropics/knowledge-work-plugins/blob/main/small-business/README.md)). Паттерн самой Anthropic для рекламы — скиллы бренда и правил площадки, команда `/rsa`, CSV и ручная проверка перед загрузкой; создание объявления сократилось «from 30 minutes to 30 seconds» ([claude.com](https://claude.com/blog/how-anthropic-uses-claude-marketing)). Он прямо переносится на Директ. **Плюсы:** Apache-2.0, официальный уровень, автообновление для этого маркетплейса по умолчанию выключено ([install](https://code.claude.com/docs/en/plugins/install)). **Минусы:** в 21 плагине `.mcp.json` к западным SaaS, российских нет; finance — бухгалтерия без max CPC; legal — американское право. **Как брать:** форк Markdown без `.mcp.json`, свои MCP вместо коннекторов.

**coreyhaines31/marketingskills — библиотека маркетолога.** 50 скиллов; для smoke-теста нужны offers, pricing, copywriting, ad-creative, cro, ab-testing и launch ([skills](https://github.com/coreyhaines31/marketingskills/tree/main/skills)). **Плюсы:** MIT, 51 автор, методики переносимы. **Минусы:** скилл `ads` — только про «Google Ads, Meta (Facebook/Instagram), LinkedIn, Twitter/X» ([ads](https://github.com/coreyhaines31/marketingskills/blob/main/skills/ads/SKILL.md)); `marketing-council` — панель мнений «legendary marketers», а не турнир ([marketing-council](https://github.com/coreyhaines31/marketingskills/blob/main/skills/marketing-council/SKILL.md)); при 464 коммитах в месяц без закреплённой версии содержимое «плывёт». **Как брать:** выборочно, SHA закрепить, площадки заменить на Директ и Метрику, тексты прогонять через ru-text.

| Лестница smoke-теста и шлюз трат | small-business; план → `--apply` у polyakov |
| Скилл предоплаты ЮKassa | Официальный MCP ЮKassa только на чтение (первый отчёт, слой 5) |
| Юридические чек-листы 152-ФЗ и 38-ФЗ | Готовых скиллов не найдено |
| Роли и генератор файлов агентов под 2–3 harness | knowledge-work (PM, data, marketing), board-meeting ([SKILL.md](https://github.com/alirezarezvani/claude-skills/blob/main/c-level-advisor/skills/board-meeting/SKILL.md)), office-hours ([SKILL.md](https://github.com/garrytan/gstack/blob/main/office-hours/SKILL.md)) |
| Свой маркетплейс-зеркало с закреплёнными SHA | Поле `sha` в `marketplace.json` ([marketplace-reference](https://code.claude.com/docs/en/plugins/marketplace-reference)) |

### Paperclip + Claude Code: одна библиотека скиллов, сменный адаптер

Первый отчёт предлагал Paperclip пилотом на 1–2 цикла: UI совета, approvals, LLM-бюджеты, роли через `opencode_local` на OpenAI-совместимом эндпоинте российских моделей (раздел «Paperclip: пилот…»). Заметки c3 добавляют второй адаптер. `claude_local` запускает Claude Code как «сотрудника», подкладывает скиллы компании через `--add-dir` и сохраняет сессию между запусками ([claude-local.md](https://github.com/paperclipai/paperclip/blob/master/docs/adapters/claude-local.md)). Скиллы живут в библиотеке компании: импорт из Git только с 40-символьным SHA, уровень доверия выводится из файлов, «Importing never executes scripts» ([skills-store.md](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/skills-store.md)).

**Как сочетаются (предложение).** Paperclip — оболочка совета и библиотека скиллов поверх сменного исполнителя. Один набор скиллов раздаётся ролям. `claude_local` — для эталонного прогона в среде разработки, `opencode_local` — для продакшен-ролей на моделях, доступных из РФ. Денег в Paperclip нет: его бюджеты считают только LLM (первый отчёт). Оговорка по гейтам: `claude_local` по умолчанию ставит `dangerouslySkipPermissions: true` — «required for headless runs where interactive approval is impossible» ([claude-local.md](https://github.com/paperclipai/paperclip/blob/master/docs/adapters/claude-local.md)). В этом режиме держат только deny-правила и инструменты с `requiresUserInteraction` ([permission-modes](https://code.claude.com/docs/en/permission-modes#actions-no-mode-auto-approves)). Есть сообщение, что `ask`-правила для Bash под `--dangerously-skip-permissions` перестают работать (по листингу GitHub) ([#95741](https://github.com/anthropics/claude-code/issues/95741)). Совместим ли `claude_local` с `disableBypassPermissionsMode` в managed settings — не проверено. Авторизация — API-ключ: подписочный токен в стороннем оркестраторе — серая зона условий (следующий раздел). **Плюсы:** готовый UI совета и библиотека скиллов с закреплением версий; A/B исполнителей на одних скиллах. **Минусы:** третий рантайм (Node) рядом с ядром; молодой код с бешеным темпом релизов (первый отчёт).

**Правило приёма сторонних скиллов (предложение).** Только форк с закреплённым SHA в своём маркетплейсе, автообновление выключено. Перед закреплением — прочитать целиком SKILL.md, `allowed-tools`, `hooks.json`, `.mcp.json`, `bin/` и все скрипты. Ключей с правом записи рядом со скиллом нет. Подробности угроз — в разделе «Риски».

## Без человека: Claude Code умеет запускаться и ждать, но тратить деньги ему нельзя

### Расписание: routines и `/loop` для цикла с деньгами не годятся

Routines чинили прямо перед датой отчёта. Changelog фиксирует три исправления. Запуски, чья облачная сессия не стартовала, показывались как Succeeded (2.1.286, 2026-09-30). Запуски часами висели в статусе running (2.1.292, 2026-10-06). «Some older routines starting their runs without ever giving Claude their saved prompt» (2.1.295, 2026-10-08) ([changelog](https://code.claude.com/docs/en/changelog)). Документация сама предупреждает: «A green status… does not mean the task in your prompt succeeded» ([routines](https://code.claude.com/docs/en/routines)).

### Подписка или API-ключ: автоматизация — по API-ключу, и это не снимает вопрос региона

Заметки c2 и c4 сходятся в главном. Consumer Terms для Free, Pro и Max запрещают автоматический доступ, «Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it» ([Consumer Terms](https://www.anthropic.com/legal/consumer-terms)). Лимиты Pro и Max рассчитаны на «ordinary, individual usage of Claude Code and the Agent SDK». Продуктам на Agent SDK документация велит «use API key authentication» ([legal-and-compliance](https://code.claude.com/docs/en/legal-and-compliance)). Явно разрешённая подписочная автоматизация — это инструменты самой Anthropic: routines, `claude -p` с токеном `claude setup-token` «For CI pipelines, scripts», OAuth-токен в GitHub Actions ([authentication](https://code.claude.com/docs/en/authentication), [github-actions](https://code.claude.com/docs/en/github-actions)). Сторонним разработчикам запрещено «route requests through Free, Pro, or Max plan credentials on behalf of their users» ([legal-and-compliance](https://code.claude.com/docs/en/legal-and-compliance)). В 2026 году запрет применяли. 19 марта OpenCode удалил подписочный OAuth по «anthropic legal requests» ([PR #18186](https://github.com/sst/opencode/pull/18186)). 4 апреля, по сообщениям, OpenClaw и другие сторонние harness лишились лимитов подписки (по сниппету поиска) ([TechRadar](https://www.techradar.com/pro/bad-news-claude-users-anthropic-says-youll-need-to-pay-to-use-openclaw-now)).

**Противоречие, которое заметки не сняли.** Справка Anthropic от 7 октября 2026 года пишет: «You can still use the Claude Agent SDK, claude -p, and third-party apps with your subscription limits» ([support 15036540](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)). Это расходится с апрельскими сообщениями и с запретом на юридической странице. Какие «third-party apps» имеются в виду, из текста не ясно — вероятно, одобренные интеграции (не проверено). Правила программного использования за 2026 год менялись минимум четыре раза: январь, апрель, май–июнь (анонс перевода `-p` и SDK на отдельный кредит и его пауза), октябрь ([c4](notes/claude-code-harness/c4-ru-viability-portability.md)).

**Практический вывод (предложение).** Подписка — только для интерактивной работы основателя. Любая автоматизация компании, если в ней вообще есть Claude, — только по API-ключу на Commercial Terms: отдельный workspace Console с месячным лимитом и `claude --bare -p`, который OAuth и не читает ([headless](https://code.claude.com/docs/en/headless)). Месячные API-кредиты Max — $100 у 5x и $200 у 20x — зачисляются в Console и покрывают `claude -p`, Agent SDK и API. Без докупки запросы просто останавливаются: «API requests stop until your next monthly credits arrive» ([support 17154008](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-and-team-plans)). Это естественный жёсткий потолок. Подписочный токен не передавать ни в Paperclip, ни в OpenCode, ни в другой сторонний harness. **Плюс:** вопрос условий использования закрыт одной схемой. **Минус:** вопрос региона она не закрывает — Commercial Terms тоже требуют поддерживаемой страны (раздел «РФ»).

**Что значит подписочность routines для продакшена.** Routines работают только на подписке claude.ai и принадлежат «your individual claude.ai account» ([routines](https://code.claude.com/docs/en/routines)). Отсюда пять следствий. Их нельзя ограничить лимитом workspace Console. Их нельзя запустить на не-Claude модели: облачные сессии «always use your subscription credentials» ([authentication](https://code.claude.com/docs/en/authentication)). Они работают без запросов разрешений. Коммиты и PR идут от GitHub-личности основателя — «commits and pull requests carry your GitHub user» ([routines](https://code.claude.com/docs/en/routines)), — поэтому merge человека и агента технически не различить. На паузе подписки routines стоят. Итог: потеря одного личного аккаунта остановила бы расписание компании, поэтому routines — не планировщик продакшен-цикла.

### Гейты: жёсткие — вне harness, второй рубеж — внутри

Claude Code даёт три способа дождаться совета. Асинхронный — PR: агент кладёт пакет совета в PR, merge запускает исполнение; в Actions агент коммитит как `claude[bot]` ([action.yml](https://github.com/anthropics/claude-code-action/blob/main/action.yml)), и workflow может проверить `merged_by`. Интерактивный — Remote Control или Telegram-канал: работает, только пока жив локальный процесс ([remote-control](https://code.claude.com/docs/en/remote-control), [channels](https://code.claude.com/docs/en/channels)). Программный — `defer` или `canUseTool`. `defer` завершает `claude -p` с `stop_reason: "tool_deferred"`, совет отвечает вне Claude Code, затем `--resume`; «There is no timeout or retry limit», но только при одном вызове инструмента в ходе ([hooks](https://code.claude.com/docs/en/hooks#defer-a-tool-call-for-later)). `canUseTool` в SDK может ждать бесконечно ([user-input](https://code.claude.com/docs/en/agent-sdk/user-input)). Все три одобряют вызов инструмента, а не сумму с бизнес-контекстом (вывод c2).

Надёжность слоёв разная. Хуки `command` и `http` по умолчанию пропускают действие при exit 1, при опечатке в пути («leaves the gate silently disabled»), при таймауте («don't count on a stalled hook to act as a gate») и при ответе HTTP не-2xx ([hooks](https://code.claude.com/docs/en/hooks#exit-code-output), [timeouts](https://code.claude.com/docs/en/hooks#timeouts), [http](https://code.claude.com/docs/en/hooks#http-response-handling)). Опция `onFailure: "block"` вышла 2026-10-08 и описана только в changelog ([changelog](https://code.claude.com/docs/en/changelog#2-1-295)). Есть сообщения, что PreToolUse-хуки не срабатывают в VS Code и Desktop и «silently stops firing mid-session» (по листингу GitHub) ([#92074](https://github.com/anthropics/claude-code/issues/92074), [#95833](https://github.com/anthropics/claude-code/issues/95833), [#88738](https://github.com/anthropics/claude-code/issues/88738)). Флаг MCP `_meta["anthropic/requiresUserInteraction"]` надёжнее: запрос показывается на каждый вызов даже в bypass, allow-правила его не снимают, хук не может ответить за человека, `dontAsk` вызов отклоняет; одобрить может человек или `canUseTool` в SDK ([mcp](https://code.claude.com/docs/en/mcp#require-approval-for-a-specific-tool), [hooks](https://code.claude.com/docs/en/hooks#pretooluse-decision-control)). Колбэк-хук SDK при таймауте блокирует вызов, то есть закрывается при сбое ([agent-sdk/hooks](https://code.claude.com/docs/en/agent-sdk/hooks#hook-timeout)).

**Одна рекомендация (предложение).** Деньги никогда не решаются внутри harness. Каждый гейт внутри harness дублируется снаружи. Гейты harness нужны, чтобы рано остановить прогон и оставить след в аудите, а не чтобы защищать деньги.

| Рубеж | Механизм | Где живёт | Почему держит или не держит |
|---|---|---|---|
| **Жёсткий** | У агентов нет пишущих токенов: write-токен Директа и секретный ключ ЮKassa — только в шлюзе на другом хосте | Ядро | Нечего обходить: ни prompt injection, ни сбой хука не потратят деньги. Заметки c3 вместе с deny-правилами называют это единственным надёжным гейтом и при Paperclip |
| **Жёсткий** | Шлюз трат: белый список логинов, лимит ступени, ключи идемпотентности, readback, рублёвый реестр | Ядро | Инварианты — в одном коде (первый отчёт, «Деньги и токены») |
| **Жёсткий** | Одобрение совета как запись: кто, что, сумма, обоснование; бот в Telegram или Rails UI; для плана — merge PR с проверкой `merged_by` | Ядро или GitHub | Claude Code одобряет вызов без суммы и не хранит одобрения как объекты |
| **Жёсткий** | Автомат цикла: стадия `smoke` недоступна без записи GO | Ядро | Состояние не зависит от сессии harness |
| **Жёсткий** | Серверный лимит LLM: месячный лимит workspace или кредиты без auto-reload | Биллинг провайдера | Отказ 429 или 400 на стороне сервера ([rate-limits](https://platform.claude.com/docs/en/api/rate-limits)) |
| Второй рубеж | Managed settings под root: deny на прямые пишущие инструменты, `disableBypassPermissionsMode`, `allowManaged*Only`, `strictKnownMarketplaces` | Claude Code | Deny действует во всех режимах, включая bypass ([permission-modes](https://code.claude.com/docs/en/permission-modes#available-modes)); но только для вызовов через Claude Code; вне managed settings mod может одобрить вызов поверх deny ([permissions](https://code.claude.com/docs/en/permissions#extend-permissions-with-hooks)) |
| Второй рубеж | `requiresUserInteraction` на инструментах шлюза «предложить трату» | MCP-сервер шлюза | Автономный прогон их не пройдёт; поддержка `_meta` в Ruby MCP SDK — не проверено |
| Второй рубеж | PreToolUse-хук `spend_guard` с `onFailure: "block"` и exit 2 | Claude Code; в Goose — `on_failure: "block"` ([goose hooks](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/context-engineering/hooks.md)) | Закрывается при сбое только с этой опцией и только по changelog; проверить вживую |
| Второй рубеж | `dontAsk` + allowlist по ролям; `--max-turns`; `--max-budget-usd`; `deniedModels` | Claude Code | Детерминированно, но бюджет — оценка |
| Не гейт | Текст CLAUDE.md и скиллов | — | «context, not enforced configuration» ([memory](https://code.claude.com/docs/en/memory)) |
| Не гейт | Классификатор auto mode | — | «does not guarantee safety» ([permission-modes](https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode)); отдельного правила про траты в списке по умолчанию нет ([c4](notes/claude-code-harness/c4-ru-viability-portability.md)) |
| Не гейт | Пересылка запросов в Telegram-канал, Remote Control | — | Одобряют вызов без суммы; «Anyone who can reply through the channel can approve» ([channels](https://code.claude.com/docs/en/channels#security)); нужна живая сессия |
| Снимает средний слой | Paperclip `claude_local` по умолчанию | — | `dangerouslySkipPermissions: true`; остаются deny и `requiresUserInteraction` (раздел «Экосистема») |

### Аудит: сырые события есть, неизменяемый журнал — свой

Источник событий — OpenTelemetry: «OpenTelemetry events are the audit data source for Claude Code activity». Событие `tool_decision` пишет решение и его источник: `config`, `hook`, `user_permanent`, `user_temporary`, `user_abort`, `user_reject`. Без `OTEL_LOG_TOOL_DETAILS=1` имена MCP-инструментов заменяются на `"mcp_tool"`, и вызовы шлюза неразличимы. Хранение и алерты — на вас: «Claude Code emits the raw event stream only» ([monitoring-usage](https://code.claude.com/docs/en/monitoring-usage)). Транскрипты JSONL удаляются через 30 дней, а их формат «internal to Claude Code and changes between versions» ([sessions](https://code.claude.com/docs/en/sessions), [claude-directory](https://code.claude.com/docs/en/claude-directory)). В GitHub Actions опция `show_full_output` может вывести секреты в логи, которые «publicly visible» в публичном репо ([action.yml](https://github.com/anthropics/claude-code-action/blob/main/action.yml)). Дашборды расходов есть только на Team, Enterprise и в Console ([analytics](https://code.claude.com/docs/en/analytics)).

**Предложение.** HTTP-хук `audit.sh` и OTel с `OTEL_LOG_TOOL_DETAILS=1` пишут в append-only журнал ядра вне машины агентов; сверка — по `tool_use_id`. Копии транскриптов и артефактов стадий уходят в неизменяемое хранилище до истечения 30 дней. Журнал одобрений — в БД ядра. Если в промптах есть персональные данные, коллектор стоит в РФ (152-ФЗ; первый отчёт, «Юридические риски smoke-теста»). **Плюсы:** независимый поток событий и журнал, который агент не перепишет. **Минусы:** хранилище и алерты — свой код; формат транскриптов меняется.

### Бюджеты LLM: жёсткие лимиты есть только у биллинга

Серверные лимиты жёсткие. У тиров Console месячные потолки — Start $500, Build $1 000, Scale $200 000; после потолка API отвечает 429 до 1-го числа, а свой лимит ниже потолка даёт HTTP 400 ([rate-limits](https://platform.claude.com/docs/en/api/rate-limits)). Месячный лимит ставится на workspace, но не на Default Workspace; лимита на отдельный ключ не найдено ([workspaces](https://platform.claude.com/docs/en/build-with-claude/workspaces)). У подписок Pro и Max — окно в 5 часов и недельный лимит, у Max ещё отдельный недельный лимит на Fable ([support 11145838](https://support.claude.com/en/articles/11145838-using-claude-code-with-your-pro-or-max-plan)); квоты в токенах не публикуются. Клиентские лимиты не жёсткие. Про `--max-budget-usd` документация пишет: «Spend can pass the cap, so leave headroom»; после `--resume` восстановленные суммы не считаются ([cli-reference](https://code.claude.com/docs/en/cli-reference)). Есть ловушка. На части планов Fable списывается из usage credits, и в `-p` «Claude Code never asks for consent… bills it without asking»; запретить модель можно через `deniedModels` с v2.1.283 ([model-config](https://code.claude.com/docs/en/model-config)).

**Предложение.** Две линии. Жёсткая — отдельный workspace под компанию с месячным лимитом или кредиты без auto-reload. Мягкая — `--max-budget-usd` на стадию с запасом около 20%, `--max-turns` и `deniedModels` для Fable. Рубли — только в реестре ядра. Есть ли у российских провайдеров серверный аналог лимита, заметки не разбирали — не проверено.

### Надёжность: exactly-once нет ни в одном режиме

Облачная VM при повторном открытии не восстанавливает «background work… such as subagents and shell commands» ([claude-code-on-the-web](https://code.claude.com/docs/en/claude-code-on-the-web)). Cron GitHub задерживается и теряет запуски ([schedule-delay](https://github.com/github/docs/blob/main/data/reusables/actions/schedule-delay.md)). `/loop` не догоняет пропуски ([scheduled-tasks](https://code.claude.com/docs/en/scheduled-tasks)). `claude -p` по SIGTERM выходит с кодом 143; прерванный ход продолжает `CLAUDE_CODE_RESUME_INTERRUPTED_TURN=1`; событие `system/api_retry` сообщает категории `rate_limit`, `billing_error`, `account_on_hold` ([headless](https://code.claude.com/docs/en/headless)). ID сессии задаётся заранее через `--session-id`, резервные модели — через `--fallback-model` ([cli-reference](https://code.claude.com/docs/en/cli-reference)). В v2.1.225 исправляли баг: временный 401 подменял долгоживущий `CLAUDE_CODE_OAUTH_TOKEN`, «breaking headless sessions until restart» ([changelog](https://code.claude.com/docs/en/changelog)).

**Предложение.** Каждая стадия пишет артефакт с хешем входов и перед стартом проверяет, нет ли готового. ID сессии стадии детерминирован: UUIDv5 от «неделя + стадия». Сторож шлёт алерт в Telegram, если к сроку нет артефакта. События `account_on_hold` и `billing_error` — триггер переключения исполнителя (раздел «Сравнение»). Всё денежное — с ключами идемпотентности в шлюзе. **Плюсы:** перезапуск не повторяет трат и не теряет неделю. **Минусы:** это код ядра, а не настройка.

## РФ: условия не выполняются ни в одной конфигурации, а компания из скиллов переезжает за дни

### Регион: ограничение записано в требованиях к самому клиенту

Первый отчёт показал: России нет в списке поддерживаемых стран, условия разрешают приостановить доступ, а в мае и 2 октября 2026 года СМИ сообщали о блокировках российских аккаунтов, включая Claude Code (по сниппету поиска) ([SecurityLab](https://www.securitylab.ru/news/572607.php), [Новая газета Европа](https://novayagazeta.eu/articles/2026/10/02/polzovateli-claude-iz-rossii-i-gonkonga-pozhalovalis-na-blokirovki-akkauntov-posle-podkliucheniia-cherez-vpn-news); первый отчёт, «Доступ к LLM»). Заметки c4 добавляют решающую деталь: ограничение относится не к модели, а к самому клиенту. В системных требованиях Claude Code указано «Location: Anthropic supported countries» ([setup](https://code.claude.com/docs/en/setup)). Лицензия: «Use is subject to Anthropic's Commercial Terms of Service» ([LICENSE.md](https://github.com/anthropics/claude-code/blob/main/LICENSE.md)). Юридическая страница: Claude Code подчиняется стандартным условиям Anthropic «regardless of the platform through which it is accessed» ([legal-and-compliance](https://code.claude.com/docs/en/legal-and-compliance)). Commercial Terms D.2 включают Supported Regions Policy и обязанность подтверждать личность по запросу ([Commercial Terms](https://www.anthropic.com/legal/commercial-terms)). При постоянной ошибке подключения документация сама допускает, что сервис «may not be available in your country» ([errors](https://code.claude.com/docs/en/errors)).

Следствие. Ни API-ключ, ни подписка, ни подмена модели на GigaChat, ни запуск в облаке Anthropic или на раннерах GitHub не делают Claude Code допустимым продакшен-рантаймом из РФ: политика регионов привязана к клиенту и заказчику (вывод c2 и c4). Разработка через Claude Code — текущая рабочая настройка основателя. Отчёт оценивает другое — последствия остановки. При блокировке разработка теряет темп. Продакшен-цикл с реальными деньгами встаёт посреди лестницы бюджета.

### Usage Policy: трата своего бюджета не high-risk, но за агентов отвечает пользователь

Трата собственного рекламного бюджета не попадает в high-risk области Usage Policy. «Finance» там — персональные инвестиционные рекомендации, а в исключениях — «Business operations that do not advise or decide about a specific individual» ([AUP](https://www.anthropic.com/legal/aup)). Обязательного «qualified human-in-the-loop» нет. Но «Users are responsible for ensuring that agents they build or deploy, including actions those agents take through tools… comply with this Usage Policy» (там же). Consumer Terms предупреждают: «Actions may not be error free» ([Consumer Terms](https://www.anthropic.com/legal/consumer-terms)). Если маркетолог пишет покупателям, агент обязан раскрыть, что он ИИ. Нарушать правила других площадок — Директа, ЮKassa — тоже запрещено: «circumvent the guardrails or terms of other platforms» ([AUP](https://www.anthropic.com/legal/aup)). Страница показывает редакцию с 12 ноября 2026 года; действующая до этой даты не открывалась — не проверено.

| 3. Постоянно | Зафиксировать версии: Claude Code (канал stable, который «typically about a week behind» ([setup](https://code.claude.com/docs/en/setup)), или `DISABLE_AUTOUPDATER`), OpenCode, Goose, gpt2giga, LiteLLM. Обновлять раз в 2–4 недели после eval | Релизы ломают прокси и умолчания |
| 4. По триггеру | Переключить исполнителя в автомате (правило — в разделе «Сравнение») | Переезд за дни, а не переписывание |

**Плюсы:** нет единой точки отказа в Anthropic; переключение — смена исполнителя. **Минусы:** нужны генератор конфигов под 2–3 harness, общий eval-набор и дисциплина; в продакшене не будет `context: fork`, воркфлоу, routines, WebSearch и plugin eval.

## Сравнение: A быстрее на пару недель, B переживёт потерю аккаунта, C меньше всех зависит от вендоров

Время и стоимость — оценка. Допущение: основатель работает над этим полный день и пишет код с Claude Code. Клиенты Яндекса, лендинг и платёжный сервис одинаковы для всех вариантов (первый отчёт), поэтому в строке smoke-теста они учтены одной оценкой вместе со шлюзом трат.

| | A. Всё на Claude Code | B. Гибрид: переносимые роли + своё ядро | C. Rails-ядро + RubyLLM + Paperclip-пилот |
|---|---|---|---|
| Суть | Роли — субагенты, SOP — скиллы, конвейер — воркфлоу, расписание — routines или cron, гейты — хуки и `requiresUserInteraction`; вне Claude Code только платежи и лендинг | Роли и SOP — переносимые артефакты; исполнитель стадий — Claude Code в разработке и открытый harness с моделью из РФ в продакшене; деньги, состояние, расписание, журнал решений и шлюз — в ядре | Роли — агенты RubyLLM в Rails на YandexGPT или GigaChat; Paperclip — UI совета пилотом; агентного harness в продакшене нет (первый отчёт) |
| Плюсы | Быстрее всего: основатель уже живёт в этой среде; лучшие примитивы оркестрации; eval из коробки | Деньги и состояние под контролем; смена исполнителя — дни; привычная среда остаётся мастерской; готовые скиллы переиспользуются всеми исполнителями | Максимальный контроль; один стек и одна БД; российские модели — внутри процесса; Anthropic в рантайме нет |
| Минусы | Хуки клиентские; одобрения без сумм; состоянию и расписанию негде надёжно жить; lock-in на routines, channels, плагины | Генератор конфигов и общий eval-набор; часть удобств Claude Code в продакшене не используется; качество российских моделей в агентном harness не проверено | Больше всего своего кода: провайдеры, промпты, инструменты; агентная гибкость ниже; у RubyLLM один мейнтейнер и свежий мажор 2.0 (первый отчёт) |
| Риск РФ | Максимальный: условия клиента не выполняются, блокировки 2026 года, функции claude.ai | Низкий в продакшене; в разработке — как сейчас | Низкий |
| LLM в месяц (оценка) | $59–115 по API-тарифам, дорогой сценарий — до $352 | Как у A, пока работает Claude; на моделях из РФ — в рублях, не оценивалось | В рублях; ориентир GigaChat Lite — около 0,065 ₽ за 1 000 токенов (по сниппету поиска, первый отчёт) |
| До первого пакета совета (оценка) | 1–2 недели | 3–4 недели | 5–8 недель |
| До первого smoke-теста с деньгами (оценка) | +3–5 недель на шлюз, лендинг и платёжный сервис; или первая ступень руками через кабинет Директа | Так же | Так же |

**Рекомендация: вариант B** (предложение). Писать компанию в Claude Code — там, где основатель уже работает, — но в переносимой форме и с ядром под деньги и состояние. В продакшен ставить открытый harness на модели, доступной из РФ, по результатам eval. **Плюсы:** деньги, состояние и решения совета не зависят ни от harness, ни от модели. Привычная среда — memory-bank, скиллы, субагенты в worktree — остаётся мастерской. Готовые и свои скиллы — один набор для всех исполнителей. Смена исполнителя — смена поля в автомате, а не переписывание компании. **Минусы:** первый пакет совета — примерно на две недели позже, чем в A (оценка). Нужны генератор конфигов, общий eval-набор и дисциплина frontmatter. Главная неизвестная — качество вызова инструментов у GigaChat и YandexGPT в агентном цикле — не снята ни одним источником (первый отчёт, c4).

**Правило переключения (предложение).** Исполнитель стадии — поле автомата в ядре: harness и модель. Работают три правила.

Продакшен переводится на резервную пару (другой harness или другую модель), если выполнено любое условие. Eval роли после обновления модели или harness упал ниже порога, утверждённого советом. Релиз ломает стадию дольше одного недельного цикла, и откат версии не помог. Провайдер недоступен в окне стадии или цена шага выросла выше порога совета. Резервная пара два ежемесячных прогона подряд обгоняет текущую на eval. Стартовый порог — 80% успешных многошаговых сценариев от уровня эталона на том же наборе (допущение, калибровать).

Среда разработки уходит с Claude Code на OpenCode, если аккаунт Anthropic заблокирован или запрошена верификация личности, если в `system/api_retry` пошли `account_on_hold` или `billing_error`, если правила программного использования снова изменились не в пользу основателя, или если релиз ломает рабочий процесс дольше недели. Переход подготовлен заранее: OpenCode читает `CLAUDE.md`, `.claude/skills` и MCP как есть.

Нижняя граница. Если ни одна доступная пара не проходит минимальный порог eval, автономию ролей сужать до узких вызовов из ядра — это вариант C. Возвращать продакшен на Claude Code правило не предусматривает: условия клиента из РФ не выполняются.

## Резюме

Вопрос «строить ли на Claude Code» распадается на два. Строить ли регламенты компании как скиллы и субагентов — да: это открытый стандарт, который читают десятки harness, и формат, в котором основатель уже работает. Делать ли Claude Code продакшен-рантаймом — нет: деньги, состояние и расписание он не держит, а из РФ не выполняются условия его собственной лицензии. Отсюда главный вывод. Ценность Claude Code для компании — не рантайм, а мастерская и эталон. В нём быстрее всего писать и отлаживать скиллы, гонять eval и задавать планку качества. Эту планку должен догнать открытый harness на модели, доступной из РФ. Если не догонит, автономия сужается до узких вызовов из ядра, а не возвращается к Claude Code.

**Порядок работ (предложение).** Неделя 1: форк polyakov, роли в YAML, скиллы стадий и eval-кейсы — в Claude Code. Неделя 2: ядро-минимум обычным циклом OpenSpec — автомат цикла, планировщик, бот одобрений, журнал аудита. Недели 2–3: тот же eval на Goose + GigaChat и OpenCode + YandexGPT. После выбора пары — первый исследовательский цикл и пакет совета; затем шлюз трат и первая ступень smoke-теста. **Плюс:** компания и деньги не зависят от одного аккаунта. **Минус:** первый пакет совета примерно на две недели позже, чем при «всё на Claude Code» (оценка).
