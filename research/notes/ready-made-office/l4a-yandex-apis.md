## 1. Реальность API в 2026: доступ, квоты, прогноз бюджета, Wordstat, Метрика, официальные MCP

### Takeaway
Все четыре нужных основателю функции есть в официальных API, но разнесены по трём поколениям: Директ API v5/v501 (кампании, ставки, отчёты), устаревший v4/Live 4 (прогноз бюджета, а также старый способ получать Wordstat; аналогов в v5 нет) и Wordstat в Yandex Cloud AI Studio Search API v2 (по API-ключу сервисного аккаунта, около 20 ₽ за 1000 запросов). Метрика (отчёты, Logs API, управление, загрузка офлайн-конверсий) стабильна и хорошо документирована. Официальных MCP-серверов Яндекса для Директа, Метрики и Wordstat не найдено.

### Cited Findings

**1.1. Директ API v5: доступ и заявка**
- Эндпоинты, которые используют живые проекты: боевой `https://api.direct.yandex.com/json/v5`, песочница `https://api-sandbox.direct.yandex.com/json/v5`, `https://api.direct.yandex.com/json/v501` (версия, через которую проекты создают ЕПК), v4 — `https://api.direct.yandex.ru/v4/json/`, Live 4 — `https://api.direct.yandex.ru/live/v4/json/` — [Lermont/yamcp, client.py (по коду)](https://github.com/Lermont/yamcp/blob/main/src/yadirect_mcp/client.py). Официальную страницу v501 не проверял (не проверено).
- Порядок доступа: зарегистрировать приложение в Яндекс OAuth и подать заявку в «Настройки API → Мои заявки». Есть два типа. «Тестовый доступ» открывает только Песочницу. «Полный доступ» даёт управление реальными кампаниями и Песочницу. Тип тестовой заявки поменять нельзя, для полного доступа подаётся новая заявка — [Заявка на доступ, yandex.ru/dev/direct](https://yandex.ru/dev/direct/doc/ru/troubleshooting/register) (по сниппету поиска).
- Условия: страница настроек API открывается, только если в веб-интерфейсе Директа есть хотя бы одна кампания (достаточно черновика с одной фразой). При первом входе нужно принять пользовательское соглашение. Заявку подаёт разработчик приложения, а не каждый его пользователь; агентство может подавать с логина главного представителя — [Заявка на доступ](https://yandex.ru/dev/direct/doc/ru/troubleshooting/register) (по сниппету поиска).
- Сроки: заявки рассматривают в рабочие дни РФ с 10:00 до 19:00, от часа до трёх рабочих дней, в пик до семи. В другой версии страницы сказано «до 7 дней» — [Заявка на доступ](https://yandex.ru/dev/direct/doc/ru/troubleshooting/register) и [Регистрация приложения (v4)](https://yandex.ru/dev/direct/doc/dg-v4/ru/concepts/register) (по сниппету поиска; версии страниц расходятся).
- Песочница имитирует API без реальных показов и не расходует баллы — [AdPump: Песочница API](https://adpump.ru/instructions/yandex-direct-api-pesochitsa) (по сниппету поиска, неофициально). Песочница появилась давно — [yandex.by/adv/news/295](https://yandex.by/adv/news/295) (по сниппету поиска).

**1.2. Баллы (units) и квоты Директа**
- Каждому рекламодателю и агентству выдаётся индивидуальный суточный лимит баллов. Он зависит от активности кампаний (показы, клики, расход) и пересчитывается раз в сутки. Баллы начисляются раз в 60 минут, у каждого рекламодателя своё расписание. HTTP-заголовок `Units` в ответе имеет вид «израсходовано/остаток/суточный лимит». Если баллов не хватает, запросы не выполняются — [Ограничения при работе с API](https://yandex.ru/dev/direct/doc/ru/troubleshooting/limits), [Ограничения, баллы](https://yandex.ru/dev/direct/doc/dg/concepts/units.html), [Ошибка 152 «Недостаточно баллов»](https://yandex.ru/dev/direct/doc/ru/php5-file_get_contents-points) (всё по сниппету поиска). Точной формулы лимита в документации не найдено.
- В v5 сняли почти все ограничения на число запросов к одному методу; ограничивают в основном баллы — [Новость о запуске v5](https://b2b.yandex.ru/adv/news/2312) (по сниппету поиска).
- Баллы v4 считаются отдельно от v5: Wordstat-отчёты v4 не попадают в `Units` v5. В примере ответа в README суточный лимит равен `"daily": 64000`, это иллюстрация, а не норма — [Lermont/yamcp README (по README)](https://github.com/Lermont/yamcp).

**1.3. Агентский и клиентский аккаунт**
- С токеном представителя агентства клиентский кабинет выбирают логином клиента в каждом вызове (`client_login` / Client-Login) — [yamcp README](https://github.com/Lermont/yamcp), [askads/mcp-yandex-direct README: `YANDEX_DIRECT_LOGIN` — «иначе API покажет аккаунт агентства»](https://github.com/askads/mcp-yandex-direct) (по README).
- В OAuth для Директа во всех просмотренных проектах фигурирует один scope `direct:api`. Отдельного read-only scope для Директа не встретилось. У Метрики scopes раздельные: `metrika:read` и `metrika:write` — [stufently/yandex-mcp README](https://github.com/stufently/yandex-mcp), [dsbugaev/yandex-mcp README](https://github.com/dsbugaev/yandex-mcp) (по README; официальный список scopes не проверено).

**1.4. Прогноз бюджета: v4 Live жив, замены в v5 нет**
- По официальной таблице соответствий методов Live 4 и v5, прогноз бюджета и подбор фраз в v5 не реализованы, рекомендуется использовать v4 или Live 4 — [Method equivalents — Yandex Direct API](https://yandex.ru/dev/direct/doc/en/concepts/methods) (по сниппету поиска).
- Как это работает сейчас (код от сентября 2026): `CreateNewForecast` с параметрами `{"Phrases", "GeoID", "Currency": "RUB", "AuctionBids": "Yes"}`, затем опрос `GetForecastList`, затем `GetForecast`, затем `DeleteForecastReport`, всё на `https://api.direct.yandex.ru/live/v4/json/`. Автоматического повтора `create` нет, потому что прерванный вызов мог дойти до сервера — [yamcp forecast.py](https://github.com/Lermont/yamcp/blob/main/src/yadirect_mcp/forecast.py), [yamcp client.py](https://github.com/Lermont/yamcp/blob/main/src/yadirect_mcp/client.py) (по коду). Функция добавлена в changelog 2026-09-28 как «месячный прогноз Live 4 в RUB», до 50 фраз за вызов — [yamcp README](https://github.com/Lermont/yamcp).
- R-обёртка ryandexdirect принимает до 100 фраз на прогноз; если регионы не заданы, прогноз строится по всем — [ryandexdirect](https://selesnow.github.io/ryandexdirect/) (по сниппету поиска). Та же цепочка CreateNewForecast → GetForecastList → GetForecast → DeleteForecastReport описана в практическом разборе с Claude Code Skills — [pavezlo.ru](https://pavezlo.ru/marketing/prognoz-byudzheta-direkt-iz-excel/) (по сниппету поиска).
- Объявлений 2025–2026 об отключении прогнозных методов не найдено. В 2016 году Яндекс закрыл 24 метода Live 4 (кампании, фразы, ставки), прогноза среди них не было — [gdetraffic: «Яндекс.Директ закрыл 24 устаревших метода API»](https://gdetraffic.com/Novosti/Svezhie_novosti/YandeksDirekt_zakryl_24_ustarevshih_metoda_API) (по сниппету поиска). Официальный changelog API за 2026 год открыть не удалось (не проверено).
- Частичная замена в v5: `KeywordBids.get` с `SearchFieldNames: ["AuctionBids"]` возвращает для каждой фразы `AuctionBidItems{TrafficVolume, Bid, Price}`. Для автотаргетинга и групп со статусом RARELY_SERVED приходит null, деньги передаются ×1 000 000. Это работает только для фраз, уже добавленных в кампании — [KeywordBids.get](https://yandex.ru/dev/direct/doc/ru/keywordbids/get) (по сниппету поиска).
- Ещё в v5 есть сервис `keywordsresearch` с методами `hasSearchVolume` (YES/NO по типам устройств; в описании инструмента сказано «Max 10000 keywords, max 20 requests per 60 seconds») и `deduplicate` — [Yurich-ru/yandex-ads-mcp server.py (по коду)](https://github.com/Yurich-ru/yandex-ads-mcp/blob/master/server.py). Официальную страницу KeywordsResearch не проверено (кончился лимит поиска).
- В веб-интерфейсе Директа инструмент «Прогноз бюджета» есть в разделе «Инструменты» — по сниппету поиска; источник в выдаче точно не установлен, это одна из статей [Promopult](https://blog.promopult.ru/ppc/prognoz-byudzheta-v-yandeks-direkte-kak-on-rabotaet.html) или [Ingate](https://ingate.ru/blog/prognoz-byudzheta-ot-yandeks-direkta-chto-eto-zachem-nuzhno-kak-polzovatsya/).

**1.5. Wordstat: три пути, статус каждого спорный или разный**
- (A) Wordstat через v4 Директа: `CreateNewWordstatReport` → `GetWordstatReportList` → `GetWordstatReport` → `DeleteWordstatReport`. В одном отчёте не больше 10 фраз (ошибка 241). Неудалённые отчёты копятся в очереди аккаунта и ломают следующий вызов, поэтому удаление делают в `finally`. Регионы не валидируются. В песочнице метод недоступен — [yamcp wordstat.py](https://github.com/Lermont/yamcp/blob/main/src/yadirect_mcp/wordstat.py), [yamcp README](https://github.com/Lermont/yamcp) (по коду, работоспособно в августе–октябре 2026). По старым описаниям: 1000 фраз в сутки, не больше 5 отчётов на сервере, отчёты удаляются через 5 часов — одна из статей выдачи, например [eLama](https://help.elama.ru/article/82321) (по сниппету поиска; источник старый, точная атрибуция в выдаче неясна, не проверено).
- (B) «API Вордстата» (`api.wordstat.yandex.net/v1/...`): в июне 2025 года запущена бесплатная бета по заявке — [ppc.world](https://ppc.world/news/yandeks-zapustil-besplatnyy-api-dlya-vordstata/), [Хабр/Click.ru](https://habr.com/ru/articles/917394), [comss.ru](https://www.comss.ru/page.php?id=16659) (по сниппету поиска). Официальная справка: квота общая и персональная, привязанная к OAuth-токену (запросы в секунду и в сутки). При превышении общей приходит 503, персональной — 429 с «Time to refill». `topRequests` расходует 1 единицу дневной квоты, `getRegionsTree` дневную квоту не расходует. Для подключения нужно написать в поддержку Директа, указав логин и ClientId — [Wordstat API (support2)](https://yandex.ru/support2/wordstat/en/content/api-wordstat), [Structure of the API](https://yandex.com/support2/wordstat/en/content/api-structure) (по сниппету поиска). По гайдам базовая квота 10 запросов/с и 1000 в сутки, увеличение по запросу — [osipenkov.ru](https://osipenkov.ru/api-wordstat/), [TopSite](https://topsite-program.ru/blog/wordstat-api-settings) (по сниппету поиска, неофициально). Подать заявку можно только с аккаунта Директа, где есть хотя бы одна кампания — по сниппету поиска; какая именно статья выдачи это утверждает ([rush-analytics](https://www.rush-analytics.ru/blog/api-wordstat), [osipenkov.ru](https://osipenkov.ru/api-wordstat/) или [TopSite](https://topsite-program.ru/blog/wordstat-api-settings)), не установлено (не проверено). Вызов в коде: `POST https://api.wordstat.yandex.net/v1/topRequests`, `Authorization: Bearer <token>` — [yamcp client.py](https://github.com/Lermont/yamcp/blob/main/src/yadirect_mcp/client.py).
- Статус пути (B) в 2026 спорный. В PR от 2026-09-04 `api.wordstat.yandex.net` назван «неработающим», навык переведён только на Cloud API — [artwist-polyakov/polyakov-claude-skills PR #141](https://github.com/artwist-polyakov/polyakov-claude-skills/pull/141). Ключ Яндекс Облака старый адрес не принимает — [egeg23 PR #210](https://github.com/egeg23/DevUZ-perfect-/pull/210) (по сниппету поиска). Проекты массово ушли с этого пути: Yurich-ru — «Fix Wordstat endpoints» 2026-05-30 ([commits](https://github.com/Yurich-ru/yandex-ads-mcp/commits/master)), altrr2 — «migrate yandex-wordstat-mcp to Wordstat v2» 2026-06-08 ([commits](https://github.com/altrr2/yandex-tools-mcp/commits/main)), stufently — «Wordstat MCP migrated to Yandex Cloud Search API v2» 2026-07-03 ([commits](https://github.com/stufently/yandex-mcp/commits/main)). В askads прямо сказано: «Старый отдельный Wordstat API с OAuth не используется» ([README](https://github.com/askads/mcp-yandex-wordstat)). С другой стороны, yamcp в октябре 2026 оставляет путь через `YD_WORDSTAT_TOKEN` ([README](https://github.com/Lermont/yamcp)). Официального объявления об отключении не найдено.
- (C) Wordstat в Yandex Cloud AI Studio Search API v2 — основной путь в 2026. Эндпоинт `https://searchapi.api.cloud.yandex.net/v2/wordstat/` (topRequests, dynamics, regions, getRegionsTree), заголовок `Authorization: Api-Key …`, `folderId` в теле запроса — [977ADAM client.go (по коду)](https://github.com/977ADAM/yandex-wordstat-mcp-golang/blob/main/internal/wordstat/client.go), [Yurich-ru server.py](https://github.com/Yurich-ru/yandex-ads-mcp/blob/master/server.py). Сервисному аккаунту нужна роль `search-api.webSearch.user` ([askads README](https://github.com/askads/mcp-yandex-wordstat), [stufently README](https://github.com/stufently/yandex-mcp)) или `search-api.executor` ([Yurich-ru README](https://github.com/Yurich-ru/yandex-ads-mcp)). Wordstat работает через API только синхронно и находится в статусе Preview — [Yandex Cloud: Wordstat](https://yandex.cloud/en/docs/search-api/concepts/wordstat) (по сниппету поиска).
- Цены (C) по официальной странице тарифов AI Studio: GetTop и GetDynamics — 20 ₽ за 1000 запросов с НДС, GetRegionsDistribution — 50 ₽, GetRegionsTree бесплатно. Запросы, упавшие с внутренней ошибкой сервера или ошибкой авторизации, не тарифицируются. Ночью для некоторых типов запросов действуют льготные тарифы — [Search API pricing](https://aistudio.yandex.ru/ru/docs/search-api/pricing) (по сниппету поиска). Данные расходятся: статья на Хабре 2026 года пишет, что Wordstat на момент написания бесплатен ([Хабр 1030276](https://habr.com/ru/articles/1030276/), по сниппету). Yurich-ru пишет: «нужен платёжный аккаунт (карта не списывается, есть бесплатная квота)» ([README](https://github.com/Yurich-ru/yandex-ads-mcp)). У JSON SEO указано 0.01 ₽ за страницу ([jsonseo](https://jsonseo.ru/blog/wordstat-api), по сниппету; похоже, это про поиск, а не про Wordstat).
- Квоты (C): общая страница лимитов Search API обновлялась 2024-11-20 и описывает поиск (1000 синхронных v1-запросов в сутки по умолчанию, v2 deferred — 10 000 в час и 10 в секунду). Квоты меняются через поддержку — [Quotas and limits in Yandex Search API](https://yandex.cloud/en/docs/search-api/concepts/limits) (по сниппету поиска). Отдельных цифр для Wordstat нет (не проверено). В askads отмечено, что квота общая для одного ключа ([README](https://github.com/askads/mcp-yandex-wordstat)).
- Важно для (C): с 1 июня 2026 сервис аутентификации Yandex Cloud не принимает новые OAuth-токены, полученные через Яндекс ID. Старые действуют до конца срока жизни. Рекомендуется сервисный аккаунт или IAM. Страница обновлена 2026-07-20 — [Yandex Cloud: OAuth-токен](https://yandex.cloud/ru/docs/iam/concepts/authorization/oauth-token) (по сниппету поиска). Yurich-ru это подтверждает: `YC_API_KEY` «обязателен для OAuth-токенов, выпущенных после 01.06.2026 — Яндекс Облако больше не меняет их на IAM» ([README](https://github.com/Yurich-ru/yandex-ads-mcp)).

**1.6. Метрика: Reporting / Logs / Management / офлайн-конверсии**
- Квоты: 30 запросов/с с одного IP (в Logs API ниже, 10/с), 5000 запросов в сутки на `user_login` (сброс в 00:00 GMT), не больше 3 параллельных запросов на пользователя. На `/stat/v1/data` отдельно 200 запросов за 5 минут. При превышении — 429 с типом квоты в теле ответа — [Квотирование API Метрики](https://yandex.ru/dev/metrika/doc/api2/intro/quotas.html) (по сниппету поиска).
- Офлайн-конверсии: `POST https://api-metrika.yandex.net/management/v1/counter/{counterId}/offline_conversions/upload`, параметр `client_id_type` (например `CLIENT_ID`), CSV с колонками `ClientId,Target,DateTime,Price,Currency` в multipart/form-data, `DateTime` в Unix-времени и только в прошлом. Нужен хотя бы один из идентификаторов ClientID / UserID / yclid / PurchaseId. Цель создаётся заранее как JS-событие. Обработка занимает до 24 часов, статус — `GET …/offline_conversions/uploading/{id}`, список — `…/uploadings` — [Upload offline conversions](https://yandex.com/dev/metrika/doc/api2/management/yclid_conversion/upload.html), [offline-conv](https://yandex.ru/dev/metrika/ru/management/offline-conv.md), [findById](https://www.yandex.com/dev/metrika/en/management/openapi/offline_conversions/findById_1) (по сниппету поиска). Потерю до 20% конверсий при сопоставлении автор на Хабре считает нормой — [Хабр 940720](https://habr.com/en/articles/940720) (по сниппету, мнение).
- Цели Метрики в отчётах Директа: параметр `Goals` (+ `AttributionModels`, только вместе с `Goals`, по умолчанию LSC) порождает колонки `Conversions_<goal>_<model>`, `CostPerConversion_<goal>_<model>`, `ConversionRate_<goal>_<model>`, а также `Revenue` и `GoalsRoi`. Устаревшие модели атрибуции отключены — [Report content](https://yandex.ru/dev/direct/doc/en/report-format), [Пример: данные Метрики](https://yandex.ru/dev/direct/doc/reports/example-metrika-docpage/) (по сниппету поиска).

**1.7. Официальные MCP от Яндекса**

- В Yandex Cloud AI Studio есть «MCP Hub». Туда можно подключить существующий MCP-сервер, собрать сервер поверх REST API или Cloud Functions либо взять шаблон партнёров. Hub умеет ограничивать набор инструментов, требовать подтверждение вызова, вести логи и мониторинг — [AI Studio: create from template](https://aistudio.yandex.ru/docs/en/ai-studio/operations/mcp-servers/create-from-template.html), [блог Yandex Cloud про MCP Hub](https://yandex.cloud/ru-kz/blog/mcp-yandex-ai-studio-ai-agents-automation) (по сниппету поиска). ### Inferences
- Объём Wordstat у основателя мал. 50 идей × (topRequests + dynamics) — около 100 платных запросов в неделю, то есть примерно 2 ₽ в неделю по тарифу 20 ₽/1000. Даже 1000 фраз в неделю — около 20 ₽. Деньги здесь не ограничение. Ограничения — Preview-статус и общая квота на ключ.
- Прогноз бюджета зависит от legacy Live 4, и это главный технологический риск слоя: аналога в v5 нет, объявлений о закрытии тоже нет. Нужен изолированный адаптер и запасной путь: ручной прогноз в интерфейсе или `KeywordBids.AuctionBids` по фразам в остановленной или черновой кампании. Второй вариант не гарантирован, потому что для RARELY_SERVED приходит null.
- Путь (B) `api.wordstat.yandex.net` для новой разработки брать не стоит: статус спорный, доступ через поддержку. Путь (A) через v4 годится как запасной (10 фраз на отчёт, очередь из 5 отчётов).
- Отдельного read-only scope для Директа, похоже, нет. Значит, запрет записи для агента придётся обеспечивать кодом: шлюз и режимы MCP. На права токена тут не опереться.
- Сторонние MCP со встроенным OAuth-приложением (askads: встроенный `client_id`) на практике позволяют работать с API Директа без своей заявки на доступ. Но тогда токен выдан чужому приложению с полным `direct:api` — для кабинета с реальными деньгами это компромисс.
- Если предоплата проходит не на сайте (платёжный провайдер, счёт), её можно учесть конверсией в Метрике и в отчётах Директа через загрузку офлайн-конверсий по ClientId/yclid. Для этого ClientId надо сохранять при заявке. Данные будут с задержкой до 24 часов.

### Gaps
- Не проверены официальные страницы: changelog API Директа 2025–2026 (сроки жизни v4/Live 4), документация `KeywordsResearch` и `v501`, отдельные квоты Wordstat в Search API, минимальные дневные и недельные бюджеты кампаний через API. Причины: WebFetch не открывает yandex.ru/yandex.cloud, а лимит WebSearch этого прогона исчерпан.
- Официально работает ли `api.wordstat.yandex.net` на октябрь 2026, установить не удалось: источники противоречат друг другу (см. 1.5).
- Цена Wordstat в AI Studio: официальная таблица (20/20/50 ₽ за 1000) противоречит «бесплатно» на Хабре и «бесплатной квоте» у Yurich-ru. Размер бесплатной квоты не найден.
- Точной формулы суточного лимита баллов Директа в открытых источниках нет.

## 2. Кандидаты: MCP-серверы и API-клиенты — сопоставление имён, скрининг, таблица (≤6)

### Takeaway
Ни один готовый MCP не закрывает все четыре стадии сразу. Ближе всех Lermont/yamcp («yadirect-mcp»): это единственный проект с прогнозом Live 4, Wordstat, защищённым созданием кампаний (бюджетный лимит, подтверждение по хешу плана, MCP elicitation) и отчётами. Но ему три месяца, у него один автор и 2★. Самый популярный широкий сервер — Yurich-ru/yandex-ads-mcp (43★: Директ, Метрика с офлайн-конверсиями, Wordstat Cloud). Защита записи там включается флагами, прогноза нет. Семейство Ask Ads (npm `mcp-yandex-direct`, `mcp-yandex-wordstat`, `mcp-yandex-metrica`) — самое аккуратное по упаковке и OAuth, но прогноза у него нет, бюджетных лимитов нет, телеметрия включена по умолчанию. Все проекты появились в 2025–2026 годах и держатся на одном-двух авторах.

### Inferences
- Вся ниша молодая (появилась в 2025–2026) и держится на одном-двух людях. Звёзд единицы или десятки, максимум у altrr2 — 65★, и тот три месяца без коммитов. Брать что-либо стоит только с фиксацией версии или коммита и с собственным форком.
- Гейт расходов в смысле «человек утверждает бюджет» реализован только в yamcp: лимит `client_budget`, одноразовое подтверждение по SHA-256 плана, форма MCP elicitation, отказ от автостарта. У Yurich-ru и stufently есть подтверждение мутаций, но лимитов бюджета нет. У askads подтверждение зависит от клиента, а у `raw_request` — от флага `confirmWrite`.
- Прогноз Live 4 есть только у yamcp. Остальные либо его не трогают, либо подменяют аукционными ставками v5 по уже созданным фразам.
- Нативной интеграции MCP-серверов с Rails или Go нет и не нужно. MCP — интерфейс для агентов Claude Code. Бэкенду проще ходить в REST/JSON API Яндекса напрямую.

- Не сняты: звёзды и активность baltic-tea, 5iNeX/georgy-agaev, vtka, theYahia, LidFly; скачивания npm/PyPI (403); путь хранения токена у `mcp-yandex-direct` (по аналогии с `mcp-yandex-metrica` и коммиту «Atomic credential writes, refresh token fix» — скорее всего файл в `~/.config`, не проверено).
- Каталоги MCP (glama.ai, mcp.so, smithery.ai, pulsemcp.com) целиком не просматривались. Кандидаты найдены через веб-поиск и GitHub, поэтому малоизвестные серверы могли выпасть.

## 3. Deep-dive топ-3: Lermont/yamcp, Yurich-ru/yandex-ads-mcp, семейство Ask Ads

### Takeaway
yamcp архитектурно ближе всего к нуждам основателя: прогноз, Wordstat и человеко-подтверждаемый запуск. Но он заточен под агентские отчёты клиентам, у него один автор и он «тяжёлый» (79 модулей). Yurich-ru — самый широкий по покрытию API (включая офлайн-конверсии) с простыми флагами READONLY/CONFIRM. Ask Ads — лучший UX подключения: OAuth в чате, PKCE, refresh, файл с правами 0600, но для записи он слабее и не умеет прогноз.

### Cited Findings

**3.1. Lermont/yamcp («yadirect-mcp»)** — [репозиторий](https://github.com/Lermont/yamcp)
- Режимы: по умолчанию `YD_MODE=report` — «все доступные инструменты только читают данные», и write-инструмент в этом режиме даже не регистрируется в MCP. Создание кампаний включается явно через `YD_MODE=campaign_setup`, «требует preview и точного подтверждения и никогда автоматически не запускает показы» — [README](https://github.com/Lermont/yamcp).
- Защищённая запись устроена так: план → live preflight → одноразовая confirmation, связанная с хешем плана (SHA-256), со сроком 30 минут → MCP elicitation (форма человеку) → фоновое применение через v501 → независимый readback. Неизвестный клиент или отсутствие form elicitation блокируют согласование. Режим `YD_APPROVAL_MODE=task_authorized` выполняет поручение без повторных форм — [README](https://github.com/Lermont/yamcp). Это риск: такой режим нельзя включать агенту.
- Бюджет: общий `client_budget` ограничивает только кампании создаваемого плана. Для профилей v3/v4 по умолчанию это 30 000 RUB с НДС на 14 дней. После записи фактические бюджеты новых кампаний сверяются, при расхождении запись блокируется. Ещё есть `YD_ALLOWED_LOGINS` — белый список клиентских логинов. В preview входит `api_units_estimate`, в ответах — `units_usage` по заголовкам `Units` — [README](https://github.com/Lermont/yamcp).
- Инструменты (по README): `direct_wordstat`, `direct_forecast`, `direct_report`/`direct_read_report`, `direct_campaign_plan`/`direct_campaign_apply`, `direct_ad_resume`, `direct_goal_catalog`, `direct_regions`, `direct_campaigns`, `direct_keywords`, `direct_audience_interests` и другие ([README](https://github.com/Lermont/yamcp)). В каталоге `src/yadirect_mcp` 79 модулей, среди них `forecast.py`, `wordstat.py`, `approval.py`, `limits.py`, `api_units.py` ([tree](https://github.com/Lermont/yamcp/tree/main/src/yadirect_mcp)).
- Wordstat: до 50 фраз за вызов, они режутся на батчи по 10 (ограничение `CreateNewWordstatReport`); полный список пишется в TSV и `.meta.json` с SHA-256 в `YD_OUT_DIR`; `shows` — это месячный спрос, а не прогноз показов кампании — [README](https://github.com/Lermont/yamcp), [wordstat.py](https://github.com/Lermont/yamcp/blob/main/src/yadirect_mcp/wordstat.py).
- Прогноз: месячный прогноз Live 4 в RUB, до 50 фраз. Регионы нужно указать явно и проверить. Исходный ответ сохраняется, временный прогноз удаляется. Модель предупреждает, что Bid ≠ Price и что результат не готовый медиаплан — [forecast.py](https://github.com/Lermont/yamcp/blob/main/src/yadirect_mcp/forecast.py).
- Метрика: используется только management API счётчиков (`api-metrika.yandex.net/management/v1/counter/{id}`) — [client.py](https://github.com/Lermont/yamcp/blob/main/src/yadirect_mcp/client.py).
- Специализация: шаблоны отчётов «от агентства клиенту», бизнес-профили (`*_new_v4`/`*_established_v4`), публикация HTML-отчётов по SSH (`YD_CREATE_REPORT_SSH_HOST`, «Путь `/create/` не является средством авторизации») — [README](https://github.com/Lermont/yamcp).
- Активность: 19 коммитов с 2026-07-16 по 2026-10-03; 2026-10-03 — переход на MCP Python SDK v2 ([commits](https://github.com/Lermont/yamcp/commits/main)).

**3.2. Yurich-ru/yandex-ads-mcp** — [репозиторий](https://github.com/Yurich-ru/yandex-ads-mcp)

- Активность и люди: 43★, 14 форков, 28 коммитов (2026-04-14 → 2026-10-04), 3–4 автора, релизы 1.1.1, 1.2.0 и 1.3.0 видны в сообщениях коммитов — [commits](https://github.com/Yurich-ru/yandex-ads-mcp/commits/master).

### Inferences
- Для «LLM-компании» основателя логичный раздел такой: агент Claude Code читает (Wordstat, Метрика, отчёты Директа) через готовые MCP в read-only режиме, а всё, что тратит деньги, идёт через собственный шлюз в бэкенде. Схема шлюза — по образцу yamcp: план → хеш → одноразовое подтверждение человеком → применение → readback.
- Брать yamcp целиком как зависимость рискованно. Автор один, проекту 3 месяца, много агентской специфики (HTML-отчёты клиентам, бизнес-профили, 30 000 ₽/14 дней по умолчанию). Ценность — в `forecast.py`, `wordstat.py`, `approval.py` и `api_units.py` как готовом знании о подводных камнях Live 4 и v4: 10 фраз на отчёт, обязательное удаление, отсутствие повтора `create`, раздельные баллы.
- Yurich-ru с `YD_READONLY=true` — самый простой способ дать агенту широкое чтение Директа и Метрики. Офлайн-конверсии (предоплаты) при этом лучше грузить из бэкенда, а не агентом, потому что это запись.

### Gaps
- Код защит Yurich-ru и askads целиком не читался, проверены только README и фрагменты `server.py`. Как ведёт себя `YD_CONFIRM` на мутациях через `raw`-вызовы — не проверено.
- Устойчивость yamcp на «чистом» клиентском аккаунте (не агентском) не проверялась, запускать в этом слое запрещено.

## 5. Вывод по слою: что взять готовым / что как референс / что писать самому

### Takeaway
Готовым брать только read-only инструменты для агента-исследователя: Wordstat (askads `mcp-yandex-wordstat` или аналог) и чтение Директа и Метрики (Yurich-ru с `YD_READONLY=true` или askads `mcp-yandex-metrica`). Прогноз Live 4, запуск смоук-тестов с бюджетной лестницей и учёт предоплат (офлайн-конверсии) писать самому, в бэкенде, по образцу yamcp. Ни один MCP с правами записи в боевой кабинет агенту не давать.

### Cited Findings
- Прогноз есть только в Live 4, а из MCP — только в yamcp ([Method equivalents](https://yandex.ru/dev/direct/doc/en/concepts/methods) — по сниппету; [yamcp forecast.py](https://github.com/Lermont/yamcp/blob/main/src/yadirect_mcp/forecast.py)).
- Человеко-подтверждаемую запись с бюджетным лимитом и без автостарта показов реализует только yamcp ([README](https://github.com/Lermont/yamcp)). Остальные ограничиваются флагами подтверждения (Yurich-ru — [README](https://github.com/Yurich-ru/yandex-ads-mcp); stufently — «there is no dry-run», [README](https://github.com/stufently/yandex-mcp)) или аннотациями, которые обрабатывает клиент (askads — [README](https://github.com/askads/mcp-yandex-direct)).
- Wordstat в 2026 — Cloud Search API v2, около 20 ₽ за 1000 запросов, Preview ([pricing](https://aistudio.yandex.ru/ru/docs/search-api/pricing), [concepts](https://yandex.cloud/en/docs/search-api/concepts/wordstat) — по сниппету).
- Офлайн-конверсии Метрики позволяют засчитать внесайтовые предоплаты как конверсии с задержкой до 24 часов ([upload](https://yandex.com/dev/metrika/doc/api2/management/yclid_conversion/upload.html) — по сниппету).

### Inferences
**Взять готовым (агентский read-only слой Claude Code, с фиксированной версией):**
1. Wordstat-разведка: `mcp-yandex-wordstat` (askads, MIT, npm 2.3.1) с `ASKADS_TELEMETRY=0`. Альтернативы — baltic-tea (Python) и `yandex-wordstat-mcp` от altrr2. Ключ сервисного аккаунта с ролью только на Search API, отдельный каталог Yandex Cloud.
2. Чтение Директа и Метрики для анализа результатов: Yurich-ru/yandex-ads-mcp с `YD_READONLY=true` и `YD_ALLOWED_LOGINS`. Либо удалённый read-only `mcp.askads.ru/mcp` вместе с `mcp-yandex-metrica` (специализированные инструменты не пишут). Для более полной Метрики — artgas1 в профиле `core`/`read` без `METRIKA_ALLOW_WRITES`.
3. Для пилота можно опционально взять yamcp в режиме `report` ради `direct_wordstat` и `direct_forecast`. Коммит зафиксировать, `campaign_setup` и `task_authorized` не включать.

**Как референс (читать код, а не зависеть):**
- yamcp: Live 4-прогноз (`forecast.py`), v4 Wordstat (`wordstat.py`), протокол подтверждения (план → SHA-256 → одноразовый токен на 30 минут → elicitation → readback), `client_budget`, оценка баллов (`api_units.py`), отказ от автостарта показов.
- Yurich-ru: флаги READONLY/CONFIRM/ALLOWED_LOGINS, офлайн-тест защиты, учёт `Units`, полный перечень эндпоинтов, включая `keywordsresearch` и офлайн-конверсии.
- askads: OAuth в чате с PKCE и refresh, файл учётных данных с правами 0600, повторы только для чтений, защита от SSRF при загрузке изображений.
- nozikov/yandex-mcp: выбор хранилища секретов (Keychain, `secret-tool`, файл 0600). artgas1: генерация инструментов из спецификации, профили, запись скрыта по умолчанию. 977ADAM: Go-клиент Wordstat v2. stufently и altrr2: упаковка в плагин и навыки Claude Code.

**Писать самому (Go или Rails бэкенд):**
- Тонкие API-клиенты: Директ v5/v501 + Reports (TSV, `Goals`/`AttributionModels`); Live 4 forecast (Create → poll List → Get → Delete в `finally`, без автоповтора `create`); Wordstat Cloud v2 (4 метода, учёт ошибок и 429); Метрика stat и management с загрузкой офлайн-конверсий и проверкой статуса.
- «Шлюз расходов» (spend gateway) — единственный держатель write-токена Директа. Агент присылает план, шлюз проверяет логин, лимит текущей ступени лестницы, статус кампании и оценку баллов. Человек утверждает план в Rails UI или Telegram, шлюз применяет его, делает readback и пишет аудит-лог. Повышение бюджета — отдельное утверждение на каждую ступень. Создание кампаний и запуск показов разведены, как в yamcp.
- Хранилище токенов (Rails credentials, Vault и т. п.), разные токены для чтения агентом и для записи шлюзом, мониторинг баллов `Units` и квот Метрики (5000 в сутки, 200 запросов за 5 минут на `/stat/v1/data`).
- Учёт предоплат: сохранять ClientId/yclid при заявке, по вебхуку оплаты загружать офлайн-конверсию в цель Метрики, затем читать её в отчётах Директа через `Goals`.

**Доступы, которые нужно получить до разработки:**
- Своё OAuth-приложение и заявка на полный доступ к API Директа: нужна хотя бы одна кампания или черновик в веб-интерфейсе, рассмотрение от часа до 3–7 рабочих дней.
- Платёжный аккаунт Yandex Cloud, каталог и сервисный аккаунт с API-ключом для Wordstat: новые OAuth-токены Cloud не принимает с 2026-06-01.
- OAuth Метрики со scope `metrika:read`, для загрузки офлайн-конверсий — запись (scope `metrika:write`, по README stufently; официально не проверено).

### Gaps
- Риск отключения Live 4: официальный changelog 2026 не проверен. Нужен мониторинг новостей API Директа и запасной сценарий (ручной прогноз в интерфейсе или `AuctionBids`).
- Не проверено, можно ли ограничить токен Директа правами только на чтение на уровне Яндекса (например, через представителя с ролью «только чтение»). От этого зависит, нужен ли отдельный read-токен агенту.
